# 08｜LLM Wiki 新版使用与配置说明

> 本说明对应 V2 目标界面，用于改造完成后随产品发布。当前仅有设计资料可核实，实际版本尚未按本说明运行验收；发布前应按实际按钮名称、安装包和客户端适配更新。本文不提供未经验证的下载地址、exe 路径或构建命令。

## 1. 这个工具能做什么

你可以把资料放进本地知识库，编辑和管理资料，再把工具生成的操作指令交给外部 AI，让 AI 整理出知识页面。资料、知识、规则和日志都保存在文件夹中。

工具不内置 AI 模型，也不需要配置模型 API Key。即使不连接 AI，仍可创建知识库、管理资料和查看已有知识。外部 AI 负责理解和整理内容；本应用负责文件管理、任务准备和连接权限。

## 2. 认识三个主要页面

| 页面 | 什么时候用 |
|---|---|
| 资料 | 添加文件、新建笔记、修改原始内容 |
| 知识 | 阅读整理结果、浏览分类、查看引用来源 |
| 整理 | 更新知识、准备问题或对比任务、检查知识质量 |

左上角切换当前知识库。底部的知识库设置只影响当前库，应用设置影响整个程序。连接与分享负责其他设备和外部 AI 的访问。

## 3. 第一次建立知识库

1. 打开应用；没有知识库时点击“创建知识库”。已有库时从左上库切换器点击“新建知识库”。
2. 输入名称，选择通用、研究、读书或业务模板。不确定时选通用。
3. 创建成功进入资料页，点击“添加文件”。
4. 选择 md、txt、docx 或 xlsx 文件。
5. 查看添加结果；失败的文件可单独重试。每个文件最大 20 MiB，多文件分别处理，不把整批限制为 20 MiB。

创建时不必先修改存储路径。默认位置为当前用户文档目录下的 LLM Wiki/wikis；应用设置会显示实际路径。安装程序目录和数据目录相互独立。

## 4. 第一次整理成知识：无需先配置的复制方式

1. 在资料页选择文件，点击“整理所选”；也可直接进入“整理 → 更新知识”。
2. 第一次可选全部资料，平时选择待整理变更或指定资料。
3. 默认“手动复制”，点击“复制整理指令”，当前库说明、目标规则入口和本次任务一次复制，无需先配置 AI 工具。
4. 在能访问该文件夹的外部 AI 中粘贴执行。
5. 回到整理页点击“查看本次变化”，检查文件变化、正文和来源。
6. 在同一面板勾选已核对完成的资料，点击“确认完成这 {n} 项”；一次提交，不再重复弹确认框。

复制成功只代表指令进入剪贴板。应用无法仅凭复制操作知道外部 AI 是否执行完成。没有生成知识时，先查看外部工具是否有路径访问权限、是否真的写回当前库的 wiki/ 目录。

## 5. 平时添加、修改与删除

添加文件后，从资料页点击“去整理”，使用待整理范围处理新增项即可。修改 md/txt 时先保存；保存完成后再整理相关项，不必每次处理全部资料。文本未修改时保存禁用，保存成功继续留在编辑模式，点“完成编辑”回到预览；保存中不要重复操作，失败时草稿保留。

Word 和 Excel 与其他支持类型一样按源格式保存，不生成 Markdown 副本。支持时可直接预览，不支持预览时点击“打开原文件”。使用系统关联程序修改并保存后，回到应用刷新检测变化；也可以修改本机文件后重新上传覆盖。

资料页的“移入回收站”保留原格式文件，可从更多菜单“回收站”恢复，成功提示也可撤销；不会立即删除已有知识。到整理页选择删除变更，让外部 AI 先给出引用清理计划，再按权限确认处理。核对共享实体和链接后才确认已处理。

## 6. 阅读、提问和对比

知识页左侧是分类，右侧是正文；查找框按文件名查找。点击可识别的来源可回到资料。

需要 AI 回答时，打开“整理 → 提问分析”，选择回答问题或对比主题，填写内容并生成操作指令。答案在外部 AI 中产生；是否存入知识库以任务指令和实际执行结果为准。

“检查维护”可生成知识质量检查任务，或处理已删除资料的引用。生成检查指令并不表示检查已经完成。

## 7. 修改知识库目标与规则

打开“知识库设置 → 目标与结构”。

| 配置 | 建议填写内容 | 示例 |
|---|---|---|
| 目标与边界 purpose.md | 使用者、要解决的问题、资料范围、不包含什么 | 面向售后团队整理产品操作和故障处理，不包含客户隐私记录 |
| 组织规则 schema.md | 分类、来源引用、页面关系、命名规则 | 产品放实体，方法放概念；结论标注来源，相关知识使用互链 |

不知道怎么写时保留默认模板。保存后，下一次复制完整任务会自动使用新规则与最新上下文。配置不会自行重写已有知识。规则更新提醒会保留，点击“稍后处理”仅收起提醒；按当前规则核对完整知识库后，再显式确认已完成规则更新。

## 8. 更换存储位置

1. 打开“应用设置 → 存储”。
2. 浏览文件夹或填写路径，等待校验。
3. 点击“应用路径”，处理未保存内容和运行中的服务。
4. 在新目录选择已有知识库，或创建新库。

应用路径只切换读取位置，不移动或合并原数据。需要搬迁时，先关闭访问该库的程序和服务，备份后手动复制整个知识库目录，再选择目标根目录并检查。不要只复制 wiki/ 而遗漏资料和规则。

使用共享文件夹时填写当前电脑能访问的 UNC，如 `\\主机名\共享名\wikis`。Windows 负责共享权限；本应用不会自动给其他电脑授予访问权。不要两台电脑同时维护同一文件，修改者负责重新整理。

## 9. 手机和其他设备只读查看

1. 打开“连接与分享 → 浏览分享”。
2. 确认分享的库名和范围，点击“启动浏览分享”。
3. 让设备连接可信局域网，打开实际地址或扫码。
4. 输入页面显示的访问码。
5. 使用完点击“停止浏览分享”。

访问者可以浏览和下载已授权内容，不能编辑、上传或删除。只在可信局域网使用。切到其他知识库不会自动更换已经分享的库；更换范围请先停止并重新开启。

无法访问时，先检查服务是否运行、设备是否同网、地址是否为局域网地址，再检查主机网络和防火墙规则。不要通过关闭全部防火墙解决问题。

## 10. 使用 MCP 接入外部 AI

这是可选的高级方式。不熟悉时先使用手动复制。

打开 AI 工具，选择实际支持的连接方式。HTTP 默认只允许本机访问、只读。复制应用生成的客户端配置和令牌到目标 AI 客户端；具体配置格式以该客户端和应用实际适配为准。

只读连接可以读取资料、搜索和获取任务指令，不能把整理结果写回。需要写知识时，由你显式开启写入并使用写令牌；权限仅限允许的 wiki/ 文件，不允许改原始资料、规则或删除文件。重启应用后恢复只读，需再次授权。

stdio 由外部客户端启动独立本机进程，本版按只读方式配置；退出桌面不保证结束该进程。配置中的授权库或路径改变后，要在外部客户端重启连接。

打开 MCP 不会自动发任务。可以在外部客户端发起，也可以配置支持 MCP 的本机启动器后由“开始整理”发起；结束后都需核对并确认待整理项。

## 11. 访问码、令牌和路径有什么区别

| 名称 | 用在哪里 | 使用说明 |
|---|---|---|
| 浏览访问码 | 浏览器只读页面 | 交给需要查看内容的人，更换后旧访问失效 |
| MCP 只读令牌 | 外部 AI HTTP 客户端 | 允许读取授权库，不允许写入 |
| MCP 写令牌 | 外部 AI HTTP 客户端 | 仅显式授权后使用，不贴进普通文档或日志 |
| 本机/共享路径 | 外部工具直接读文件 | 由操作系统控制权限，不受 MCP 只读开关限制 |

## 12. 常见问题

| 问题 | 处理方式 |
|---|---|
| 上传后知识没变 | 上传只是准备资料，需到整理页交给外部 AI 执行 |
| 为什么仍有待整理 | 可能未确认处理，或生成任务后资料又变了；核对后只确认对应项 |
| Word/Excel 无法预览 | 源文件仍按原格式保存，使用“打开原文件”；预览能力不影响文件保存 |
| AI 读不了 Word/Excel | 更换有对应读取能力的外部工具或已适配的 MCP 读取工具；该项保持待整理 |
| 不能上传 PDF | 当前支持列表尚未包含 PDF；保持源格式与支持所有格式是两回事 |
| 保存失败 | 草稿保留，检查目录权限/网络后重试；有外部改动时先处理冲突 |
| 切换路径后资料不见了 | 新路径不会搬迁旧文件，检查根目录是否选对 |
| AI 找不到文件 | 在能访问该路径的设备执行，或使用正确授权的 MCP 连接 |
| MCP 能读取但无法整理写回 | 当前可能只读；检查权限，或改用本机文件直读方式 |
| 修改目标后旧知识不变 | 规则影响后续整理，需要主动再次整理相应资料 |
| 删除资料后知识仍存在 | 这是保留的旧结果，需生成引用清理计划并核对执行 |
| 如何备份 | 关闭写入和外部编辑后备份完整知识库目录；令牌不通过普通文档备份 |

## 13. 数据目录速查

```text
wikis/知识库名称/
├─ purpose.md       目标与边界
├─ schema.md        组织规则
├─ .changes.json    待整理记录，由应用维护
├─ .llmwiki/        扫描、任务、人工核对与记录修复状态，由应用维护
├─ raw/
│  ├─ sources/      按源格式保存的资料，如 md/txt/docx/xlsx
│  └─ assets/       已有资源文件
└─ wiki/            整理出的知识及日志
```

不要手工清空 .changes.json 来表示 AI 已完成。知识内容通常是 Markdown，资料保持各自源格式；备份需要包含完整目录；源资料移入回收站可以恢复；删除整个知识库仍是永久删除，包含回收站，不等同从列表隐藏。

## 14. 中途退出、部分完成与结果检查

生成操作指令后，本次范围和版本会保存在库内。关闭并重开应用，可在整理页“未完成任务”继续查看和核对；“已复制”不会变成“已完成”。生成前未保存的输入、意外崩溃前未保存的文档草稿不保证恢复，正常关闭仍会提示保存。

AI 只完成一部分时，只确认完成的项目。读取失败或未完整读取的项目保留；如你用其他工具已经完整处理，可选择“我已在其他方式完成”并填写说明。原资料后来又改了，对应项继续待整理，其他未变的项目仍可确认。

“本次结果”展示任务准备以来的文件变化，不能证明它们全部来自 AI，也不提供历史正文回滚。你可以确认“已核对，无需修改”，但要填写理由；系统不会仅凭知识文件没变化就判断失败。

程序关闭期间修改过 Word/Excel，再启动或刷新也会检测变化。扫描失败时不会把资料误判为已删除。首次接入现有库且缺少检测基线，会提示历史处理状态待核对。

## 15. 保存与修复提示

“文件已保存，变更记录未完成”说明文件已经在磁盘上，只是待整理或日志登记需要修复。点击“重试登记”，不要重复上传覆盖。应用重启后会继续核实修复；网络断开导致结果不确定时先恢复连接再检查。

手动修订知识会记录人工版本保护，后续整理需核对人工内容。通过 MCP 覆盖受保护文件会被拦截，你可在桌面检查后解除当前版本保护；直接访问文件的外部程序仍拥有操作系统授予的权限。

## 16. 恢复误删资料

资料页更多菜单打开“回收站”，选中文件点击恢复。原路径有同名文件时另存新名称，不会直接覆盖。恢复后是否需要重新整理由删除任务与当前版本决定；已执行过引用清理时，恢复源文件仍需重新整理知识。

回收站不自动按时间清空。可查看占用、导出需要保留的文件，再手动永久删除或清空；这一步不能恢复。回收站不对网页和 MCP 开放，也不是独立备份。覆盖上传的旧版本会以“覆盖前版本”保留在回收站。

## 17. 配置本机 AI 工具并直接开始

打开“连接与分享 → AI 工具 → 本机执行工具”，选择实际支持的适配器和程序路径，检查版本、登录状态与读取能力。需要登录时到外部工具完成，本应用不保存模型账号密码或 API Key。

验证通过且任务能力匹配后，整理页主按钮变为“开始整理”；问题分析显示“开始分析”，质量检查显示“开始检查”。点击后应用启动外部工具，展示真实状态；外部工具结束后点击“查看本次变化”，逐项核对并确认。没有可用适配器时仍可复制完整指令。

执行中可取消，但已产生的文件修改不会自动撤销。关闭应用先取消并核实任务结束；意外重启看到“中断待核实”时先检查进程和结果，不重复启动。10 分钟未收到进展只会提醒，不代表失败，也不会默认杀进程。

MCP 与启动器可以搭配：启动器负责开始执行，MCP 负责受控读写；本机文件访问则受操作系统权限约束。工具程序退出成功也不代表全部资料已经正确整理。

## 18. 导出任务包给另一环境

整理页“更多 → 导出任务包”，默认只包含说明与文件清单，不包含资料。需要原资料时显式勾选，导出前核对范围；保持源格式，不带令牌、回收站或应用配置。

接收方按自己的路径执行，结果不会自动同步回本机。回填知识后仍需在原库核对；本版不自动导入外部任务包覆盖文件。导出、复制、进程结束都不会自动清除待整理项。
