# 05｜知识库设置与应用设置

## 1. 设置分层

| 配置 | 所属范围 | 入口 | 保存方式 |
|---|---|---|---|
| 目标与边界 purpose.md | 当前知识库 | 知识库设置 / 目标与结构 | 显式保存 |
| 组织规则 schema.md | 当前知识库 | 知识库设置 / 目标与结构 | 显式保存 |
| 库路径、打开文件夹、删库 | 当前知识库 | 知识库设置 / 基本信息 | 查看或危险操作 |
| 知识库根目录 wikisDir | 整个应用 | 应用设置 / 存储 | 校验后显式应用 |
| 外观、导航折叠 | 整个应用 | 应用设置 / 外观 | 即时生效并持久化 |
| 版本、更新检查 | 整个应用 | 应用设置 / 关于 | 沿用已有更新服务 |
| 分享端口、访问码、MCP 授权 | 服务会话 | 连接与分享 | 各服务自己的操作 |

取消原“配置”导航名称，避免用户混淆当前库配置与全局设置。

## 2. 知识库设置线框

```text
知识库设置                                      当前库：产品研究
[基本信息] [目标与结构]

基本信息：库名、完整路径、目录可访问状态 [打开文件夹] [复制路径]

目标与结构：
目标与边界  purpose.md                 未保存
说明：这个知识库为谁服务、回答哪些问题、哪些内容不收录。
[Markdown 编辑区]                                  [保存目标]

组织规则    schema.md                  已保存
说明：知识如何分类、如何标注来源、如何建立互链。
[Markdown 编辑区]                                  [保存规则]

危险操作（折叠）：[删除知识库…]
```

两个编辑区独立草稿和保存状态。离开时若都未保存，统一列出两个文件，一次选择“保存全部并继续 / 放弃更改 / 留在此处”；任意保存失败都不继续离开，并保留失败草稿，成功项不得回滚为未保存。

文件不存在时显示“目标文件缺失 / 规则文件缺失”，主操作“载入默认模板”，先填入草稿，再由用户保存。不自动落盘。模板替换已有草稿先确认，不能丢失编辑内容。

保持 Markdown 文件为真实来源，不另外存一套表单数据。初版只增加中文说明和示例，不做复杂结构化表单与 Markdown 双向同步。

保存成功显示“已保存；已有知识尚未按新规则核对”，持久保存规则版本提醒。旧规则的指令不能作为新指令复制；已执行旧任务仍可逐项核对，但不消除新规则提醒。“稍后处理”只折叠当前版本提醒，不代表完成；全库核对后的显式确认条件见第 11 章。每次复制新任务都会读取当前规则版本，不再要求用户另行复制接入说明。

## 3. 删除知识库

危险区说明“永久删除全部资料、知识文件、任务状态和库内回收站，无法通过本应用恢复”。点击后列出真实库名、完整路径、影响范围，要求输入库名。

删除前检查：目录可访问、没有未解决编辑、所有绑定服务已停止、当前无文件写入任务。确认按钮为“永久删除此知识库”。失败显示实际结果，不能成功 Toast 后发现残留。若发生部分删除，标记库损坏并建议从备份恢复，不自动创建骨架掩盖。

删除后选取其他现有库或进入无库引导。无重命名库需求时本轮不新增重命名功能，避免破坏 Agent 路径。

## 4. 应用设置：存储

根目录输入只在此处出现。标签“知识库根目录”，辅助说明“该目录下每个子文件夹是一份知识库”。显示当前生效路径、待应用路径与验证结果。

操作：“浏览文件夹 / 应用路径 / 恢复默认”。恢复默认只修改输入，用户点击应用后生效。默认路径为当前用户 Documents/LLM Wiki/wikis，具体解析由系统服务决定，不硬编码用户名。

| 校验状态 | 文案 | 可应用 |
|---|---|---|
| 空 | 请填写知识库根目录 | 否 |
| 格式非法 | 路径格式不正确 | 否 |
| 校验中 | 正在检查目录 | 否 |
| 存在可用 | 目录可用 | 是 |
| 不存在但可创建 | 应用后将创建目录 | 是，提交前再次验证 |
| 无权限/不可达 | 无权限访问 / 共享目录不可达 | 否 |

异步校验必须对应最新输入；旧输入的成功结果不得启用新输入的应用按钮。不能只检测存在，还需按应用实际需要验证可读/可写能力；试写临时文件应清理且不触碰知识库内容。

## 5. 应用路径的事务顺序

0. 有本机任务仍在运行时先返回该任务，结束或取消并核实后才能更换根目录，不在运行中切换执行环境。
1. 解析待应用路径，展示“切换不会搬迁、合并或删除原目录文件”。
2. 处理所有编辑草稿；用户取消则整个切换取消。
3. 提示并停止浏览分享与 HTTP MCP，阻止新请求；独立 stdio 提示需在外部客户端停用或重启。
4. 再次验证并创建必要根目录，读取目标库列表。不要把一般文件夹自动变成知识库。
5. 成功后持久化路径并替换全局上下文，清空旧选择/过期指令/页缓存。
6. 失败则保留旧路径配置与上下文；已停止的服务保持关闭，告诉用户可手动重新开启，不静默重启。
7. 若旧库在新目录不存在，要求选择现有库；不能自动复制原库。

## 6. UNC 与多设备说明

支持手输 UNC 路径；复用已有系统文件夹选择器和局域网浏览封装，不为低频场景重做一套资源管理器。已有 net view 枚举作为辅助入口保留，失败不影响手输和系统路径选择。

配置页显示：“共享目录的读写权限由 Windows 管理。请避免多台设备同时维护同一份资料；修改者负责重新整理知识。”共享存储与浏览分享是两回事，页面提供对应说明链接。

读取失败显示网络错误与重试，不自动切回默认路径，也不自动建同名新库。映射盘符在不同运行账户可能不同，帮助建议使用该设备实际可访问的 UNC；不在 UI 承诺所有 Agent 可访问同一盘符。

## 7. 外观、关于与配置持久化

主题保留“深色 / 浅色”，不添加未实现的“跟随系统”选项。切换立即生效，所有页、编辑器、弹窗和只读提示均覆盖。导航折叠持久化；页筛选和未生成输入会话内保留；生成后的整理任务跨重启保存，文档草稿通过正常离开保护，不承诺崩溃恢复。

版本来自实际程序集；更新检查仅在现有更新渠道可靠时展示。检查失败显示原因，不显示“已是最新”。无更新服务则只显示版本与已有下载入口，不伪造按钮。

沿用既有配置文件位置与字段，兼容 wikisDir；新增 UI 偏好加版本或独立命名空间，写配置时保留未知字段。PIN 不当作普通偏好保存；令牌沿用受保护存储，普通 README 和日志不落密钥。
