# 03 · 多设备只读访问

## 1. 需求边界（用户已定）

- **要**：其他设备（电脑 / 手机）能**访问查看**知识库。
- **不要**：在那些设备上做任何编辑、上传、删除——维护只发生在维护用电脑上。

实现分两层：**电脑端用存储路径配置指向局域网共享（主方案）**，手机 / 无客户端设备用只读网页（辅助方案）。

## 2. 主方案：配置存储路径指向局域网共享（电脑端）

**思路**：知识库目录本身就是普通文件夹。在仓库那台电脑（如 A）上把 `wikis` 目录设为 Windows 共享，其他电脑（如 B）装同一个客户端，把存储路径配置成 `\\A的IP\wikis`（可映射盘符 Z:\ 后填 `Z:\wikis`，或直接填 UNC）——B 的客户端、提示词生成、只读浏览即刻生效，全部读的是 A 上那份文件。

及以上对应的具体设计：

### 2.1 配置提案（跨设备入口全走存储路径）

- 存储路径规则不变（盘符 /UNC/ 相对路径；单个 `\` 开头绝对拒绝，Demo 已有防护）。
- **路径浏览选择器加"🌐 局域网"标签**：点开 = 列局域网电脑（复刻 Demo `net view` 解析）→ 点电脑列磁盘共享 → 点共享 → "用这个文件夹"，全程点选不手输。这条功能正式入接口清单（见 02 文档 §4 `netpc` / `netshares` 行），不再遗漏。
- 找不到电脑时的提示文案照搬 Demo：确认同一网络、开启网络发现与文件共享。

### 2.2 分工与安全约定（继承 Demo 模式二，写明）

- **编辑收敛为约定而非技术强制**：共享文件夹技术上无法阻止 B 改文件，面板明文提示——"不要两个人同时改同一个文件；改完源文档的一方负责重跑 Ingest"。
- **提示词里的绝对路径天然分区正确**：在 B 的客户端上生成边界说明 / 工作流提示词，写进去的就是 B 可读的路径（UNC 或 Z:\ 映射）；在 A 上生成的就是 A 的路径。Agent 在哪台机器执行，就用哪台机器生成的提示词。
- **AI 执行端也只配一次**：如果 Agent 跑在 B，B 的路径就是 Agent 的路径，不需要访问 A 的服务。

### 2.3 并发的浅保护（作为约定外的护栏）

只读浏览不需要保护。**允许写**的场景里，客户端无法区分自己是不是"维护机"，所以把约定写进两处：

- 存储路径指向 UNC 时，配置页明文提示"多设备共享目录：编辑请遵守分工约定（谁改的源谁重跑 Ingest）"。
- `.changes.json` 仍是文件级标记，天然多端可见；不做文件锁（范围外，Demo 也没有）。

## 3. 辅助方案：只读网页（手机 / 无客户端设备）

客户端内置**只读分享服务**（Kestrel，弱 HTTP 服务），给不能装客户端的设备用：

- 默认**关闭**；在面板"分享页"打开。
- 打开后监听指定端口（默认沿用 Demo 的 8765，可在分享页改），只在 0.0.0.0（本机 + 局域网）。
- 出口是一个独立的最小网页（不复用维护面板前端）：
  - 顶部固定横幅：**"只读视图 · 编辑请到主机"**；
  - 知识库下拉（只列库）+ 目录树浏览；
  - 点 md/txt 文件 → 渲染为网页预览（wiki 页面内 [[链接]] 显示为库内跳转，页面不存在则灰化）；
  - docx/xlsx → 展示其入库副本的转换结果预览；
  - 提供 md/txt/原件的**下载**链接（只读不等于禁用获取）。
- 关闭开关即停服；程序退出即停服。
- 分享页生成 `http://<局域网IP>:<端口>` 二维码，手机扫码进入。

## 4. 允许与禁止（只读网页的实现验收清单）

| 动作 | 只读网页上 |
| --- | --- |
| 列库 / 目录树 / 看与下载文件 | ✅ |
| 上传 / 编辑保存 / 删除 / 改配置 / 写 .changes.json | ❌ 一律不允许，接口根本不实现 |
| 提示词生成 | ❌（提示词含绝对路径与维护语义，是多设备场景的编辑入口变体，禁止） |

- 只读服务的实现必须与维护文件桥是**不同的代码面**：不是给后者加"没有写接口"的开关，而是根本不挂写路由——防误实现也防探测。
- 路径安全校验（`..`、越出库目录）与维护端同一套规则。

## 5. 安全说明（写明给用户）

- 面板与文档都明示：**只在可信局域网使用，不得暴露公网**（继承 Demo 的同一约定）。
- 只读网页首版不做鉴权、不做访问码（范围外，将来如有多人访问再议）。
- 主方案里共享文件夹本身的权限交给 Windows 共享 ACL 管理，客户端不做二次鉴权层。
