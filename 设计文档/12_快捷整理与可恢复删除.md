# 12｜快捷整理、AI 工具与可恢复删除

> 本章规定新版默认交互：接入上下文自动随任务携带、复制一次完成任务准备、结果勾选后一次确认、资料删除先入库内回收站。与 01—11 配套实施，取代其中需要先单独复制边界说明、重复确认处理、直接永久删除资料的流程。

## 1. AI 工具不再是日常前置步骤

用户需要告诉 AI “处理哪个库、能做什么、这次做什么”，不必理解或单独操作“边界说明”。保留 boundary 协议能力和高级查看入口，取消首次必须先去连接页复制说明的要求。

**无已配置工具时的路径：资料页选择文件 → 整理页 → 复制整理指令 → 外部 AI 执行 → 返回核对；有已验证本机工具时点击“开始整理”，见第 13 章。**

整理页保留三类任务。更新知识范围默认待整理；从资料页进入则继承所选资料。无已验证本机工具时默认手动复制；有适配且能力匹配时默认本机执行，记住用户明确选择，但当前库的 MCP 不可用时明确回退提示，不能静默向其他库派任务。

```text
整理 / 更新知识                              当前库：产品研究
范围：所选资料（3）       执行方式：手动复制 ▾

本次会处理 3 份资料，更新知识并保留来源。
✓ 已包含当前库路径、目标规则入口和操作范围
[复制整理指令]     [预览完整指令]

已复制。请在能访问该文件夹的外部 AI 工具中粘贴执行。
[查看本次变化]     未完成任务（1）
```

“预览完整指令”是次入口，不要求先预览再复制。“复制整理指令”一次完成校验、持久任务快照、生成完整指令、写剪贴板；任何阶段失败显示对应结果，不伪造复制成功。剪贴板失败保留已准备任务，重试复制同一任务；相同快照重复复制不重复创建任务。

复制之后按钮可显示“再次复制”。输入、范围或规则改变时显示“复制新任务指令”，创建新任务，不覆盖旧记录。没有选择或缺少必填输入时主按钮禁用，并在就地说明原因。

## 2. 完整指令如何携带边界

所有手动指令必须独立成立，不依赖 AI 记住上一次对话。生成器自动组合：

1. 任务ID、知识库身份、执行方式、真实可访问路径。
2. 当前目标与规则文件的入口和版本，要求执行前读取 purpose.md、schema.md；可附短摘要，但不把两个文件全文反复塞入剪贴板。
3. 本次源文件清单、变化类型与版本；原格式读取要求、失败与截断报告要求。
4. 可读写范围、资料不转换、人工修订保护、删除先计划确认、不要自行清除待整理记录。
5. 具体任务及结果报告要求：逐项说明已读取、已处理、未完成、受影响知识路径。

执行前须核对库身份和源/规则版本，变化时停止受影响项并报告，不跨库或使用旧路径继续写入。库内资料属于内容数据，不作为修改任务权限的指令；文件直读的最终权限由操作系统与外部工具约束，文字边界不等同服务端授权。

连接与分享中的“手动使用”仅说明选择哪类外部工具、路径是否可访问，保留折叠的“查看库说明 / 复制库说明”。这是调试与高级接入辅助，不再要求用户先完成“接入成功”打勾。无可靠握手时不显示“AI 已接入”。

## 3. MCP 方式：一次配置，按调用校验

初次使用 MCP 才进入连接页：启动授权库服务 → 复制客户端配置 → 到外部客户端配置。无真实客户端探测时，状态分别为“服务可用”“最近调用”，不根据复制配置显示连接成功。

选择在外部 MCP 客户端发起时，主按钮为“复制任务说明”；本机启动器与 MCP 搭配时按第 13 章启动，不能把两者混为互斥方式。外部客户端模式下复制的说明自动携带库标识、任务ID和需要的 Prompt/工具能力。用户到已配置客户端发起任务；本应用仍不宣称点击即发送。原格式读取能力和写权限不足时就地说明，只读查询可以继续，写入任务需改执行方式或由用户显式授权。

MCP Prompts 共用上下文生成器；服务端每次工具/资源请求都检查实际授权库、会话、路径、权限、文件版本与人工保护。客户端是否主动读取了 boundary 不能作为授权前提。规则变更在下一次读取/生成中生效；旧任务按规则版本核对，不把历史对话记忆视为最新配置。

不自动修改用户 Agent 配置或覆盖 AGENTS.md，不自动启动客户端，不在指令里嵌入访问令牌。需要客户端特定格式时只使用已验证适配。

## 4. 结果确认只保留一次明确提交

默认进入本次结果面板，未完成项与已核对项在同一处展示；复选框含义为“我已核对该项已完成”。选择后主按钮“确认完成这 {n} 项”，旁边持续显示“仅移出这些待整理记录，不会修改源文件和知识”。

普通确认点击一次即提交，不再弹“确定已处理吗”。提交时再次扫描和比较版本；部分冲突直接反馈成功/保留数量，不要求重新操作全部项目。未读取或失败项默认不勾选；“我已在其他方式完成”“无需修改”在当前行展开理由输入，再统一点击同一个确认按钮，不增加第二个确认弹窗。

没有原任务时可在当前面板建立“用户补充确认”快照，含义与第 11 章一致，不冒充历史执行证据。操作失败保留选择并可重试；提交中防重复。误确认的任务详情提供“重新列为待整理”，只登记当前版本需要核对，不回滚文件，也不覆盖已有更新的变更记录。

危险操作仍单独确认：不可恢复的清空回收站、永久删库、覆盖冲突、提升写权限。普通复制、普通保存、可恢复移入回收站、结果确认不叠加确认框。

## 5. 源资料删除进入库内回收站

范围为本应用管理的源资料，不新增 Wiki 删除工具。资料页菜单“移入回收站”；成功提示“已移入回收站，可恢复”，提供“撤销”。批量操作显示所选数量和隐藏选择数量，不默认勾选筛选外文件。未保存草稿先处理，保存失败/用户取消就不执行删除。

每库 `.llmwiki/trash/{条目ID}/` 保存原字节文件及元信息，包含原相对路径、文件名、大小、哈希、删除时间、原因、关联操作/变更版本。覆盖同名文件时，先保存旧版本并标为“覆盖前版本”，再提交新文件；不能可靠保留旧版本则拒绝覆盖，不能先破坏原文件。

回收站入口在资料页更多菜单，不增加主导航。列表可按名称筛选，展示原位置、移除时间、原因与大小，操作“恢复 / 导出 / 永久删除”。本地盘和 UNC 使用同一应用级回收站，不依赖系统回收站是否支持网络路径。

移动前写操作凭据，确认内容已安全保存在回收站后才移除源路径。移动/空间/权限失败时保留源文件并提示失败，不自动降级永久删除；中途崩溃由操作ID与两端哈希核实，不把仅有元数据的条目显示为可恢复。已完成移动但变更登记失败按第 11 章补记。

回收文件不参与资料统计、搜索、扫描、整理、MCP 或浏览分享；所有网络文件入口拒绝访问隐藏回收目录。回收站内部存在文件不影响源文件已删除的判断。回收站不是备份，磁盘损坏或整库永久删除会同时失去它。

不自动按时间永久清理，保留到用户手动清理；显示占用大小，空间不足引导手动导出/清理，不能自行删除最早文件。永久删除/清空需一次明确危险确认，列出数量与大小；无二次嵌套弹窗。确认失败逐项显示，不误报全部成功。

## 6. 恢复与待整理记录的关系

恢复前验证条目完整性与目标路径。原路径空闲则恢复原位；同名文件已存在默认提供“另存名称”，不覆盖；取消不改动任一文件。成功后记录恢复操作并刷新资料，外部 AI 不需要访问回收站。

| 场景 | 待整理处理 |
|---|---|
| 删除后尚未生成/复制相关清理任务，也未确认删除项；恢复同路径同哈希 | 仅在可靠关联到本次删除且变更版本仍匹配时撤销该删除标记；恢复删除前仍待整理的状态 |
| 已复制清理指令，或可能在外部执行，或删除项已确认 | 原删除任务标为范围已变化；恢复源文件登记新增/待重新核对，提示知识引用可能已被清理 |
| 恢复内容不同或另存新名称 | 按真实路径与内容登记新增/修改，不自动清除无关删除项 |
| 记录来源不明、后来又变化、历史原件映射不可靠 | 保守保留变更，提示刷新核对，不凭同名删记录 |

“撤销”也是同一恢复流程，不能绕过后来发生的同名冲突或清理任务。恢复资料不自动恢复已修改或删除的知识；知识仍需重新整理。误确认的“重新列为待整理”与源文件回收恢复是不同操作。

## 7. 整库删除的边界

本版源资料删除可恢复，整库删除仍为危险区的永久操作，需要输入库名并停止绑定服务；说明将包含资料、知识、隐藏任务状态和回收站。整库回收不在本轮范围，不得在帮助中笼统承诺所有删除都能恢复。真正永久删除的资料或整库，应用不能恢复，需用户自备备份。

本章的复制线框表示无已配置本机工具时的兜底状态，不覆盖第 13 章有工具时“开始整理”的主按钮规则。

## 8. 实施顺序

先复用现有生成器完成上下文自动组合和单按钮复制，再把结果确认合并到一个面板；回收站的凭据、移动、恢复、冲突和变更协调服务完成后，替换原直接删除入口。读写权限、源格式保存和逐项版本比较继续保持，不因减负取消业务校验。
