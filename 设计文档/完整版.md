# 00｜LLM Wiki V2 改造总纲与功能取舍

> 编制日期：2026-10-30。性质：针对已实现产品的最终设计规格（V2.0）；不是功能已验收报告。本设计包为唯一设计基准，已包含必要数据与服务契约，不依赖历史文档。本次未取得应用源码、运行截图和可执行程序，具体实现差异由改造阶段 0 核实。

## 1. 改造结论

产品定位保留为：**本地知识库维护工具，用外部 AI 把原始资料整理为可追溯的知识。**

主流程统一为：选择知识库 → 添加资料 → 整理知识 → 检查结果 → 确认本次变更已处理。日常阅读直接进入知识页。

界面围绕三件事组织：

1. **资料**：我放进来了什么，还缺什么？
2. **知识**：整理后得到了什么，内容能否追溯？
3. **整理**：哪些资料变了，下一步怎样交给 AI？

保留外部 AI、真实文件、源格式保存、局域网只读分享和 MCP 能力；减少平行入口、重复配置、技术名词和虚假的完成感。不新增聊天、模型 API 配置、云同步、知识图谱、数据库或无人值守自动执行；允许用户主动启动已适配的外部 Agent，见第 13 章。

## 2. 目前交互为何容易混淆

| 需要解决的交互问题 | 对用户的影响 | V2 处理 |
|---|---|---|
| 首页、源文档、工作流都能展示和处理变更 | 不知道哪里才是最终操作入口 | 待整理清单只在“整理”页完整维护；其他页只显示数量并跳转 |
| 源文档和目录浏览都有编辑工作区 | 资料与 AI 产物边界不清，编辑规则冲突 | “资料”编辑输入；“知识”阅读产物。共享文档控件但按区域授权 |
| 七张提示词卡长期并排 | 用户要理解 Ingest、Lint、Clean 才能开始 | 改为“更新知识、提问分析、检查维护”三类任务，按需显示表单 |
| 边界说明是一张日常任务卡 | 接入设置与日常工作混在一起 | 每次任务自动携带必要上下文；独立说明收为高级入口 |
| 批量、增量、清理各为独立卡 | 同一批新增、修改、删除被拆成多次操作 | 合并到“更新知识”，用范围和删除项处理规则区分 |
| 配置同时放路径、purpose/schema；设置另起一页 | 当前库与整个应用的作用范围不直观 | 库内设置管目的和结构；应用设置管根目录与外观 |
| 分享页面混合浏览者与 Agent | PIN、令牌、只读、写入概念互相干扰 | 同一入口下分“浏览分享”“AI 工具”两个独立页签 |
| 复制提示词后缺少清晰闭环 | 容易把“已复制”理解成“已整理” | 明确显示“等待外部执行”；用户核对结果后才确认处理 |
| 首页统计、欢迎图、最近访问和路径占大量面积 | 看得到数据，找不到下一步 | 默认打开当前库的知识；用状态摘要和下一步提示替代仪表盘 |
| 全局搜索与局部搜索能力界限模糊 | 用户误以为能语义检索或全文提问 | 顶部只做当前库文件名查找；内容搜索仅在真实支持时单独标注 |

上述属于设计判断，需用真实操作走查验证，不宣称已通过用户研究。

## 4. 本版统一决策

| 范围 | 唯一基准 |
|---|---|
| 桌面知识编辑 | 默认阅读，手动修订从高级入口显式进入 |
| AI 工具 | 本机启动器/复制/导出是执行入口；文件访问/MCP 是访问方式，不内置模型 |
| stdio | 首轮只读，独立进程生命周期与授权库明确 |
| Office | 当前 md/txt/docx/xlsx 白名单；上传文件保持原格式和字节，不生成 Markdown 副本；增加格式须独立定义能力 |
| 桌面渲染 | 全 WPF，不引入 WebView2 |
| 分享范围 | 服务会话绑定用户确认的单库，切库不静默换范围 |
| 配置 | 保留 wikisDir 与已有字段，UI 偏好独立命名，令牌受保护存储 |
| 验收 | 所有清单从未勾选开始，以实际构建与操作结果为准 |
| 数据和服务规则 | 本包 10_数据与服务契约.md，无需查阅其他版本 |

## 5. 改造边界与优先级

- **第一优先级**：已验证本机工具主动执行与复制兜底、单按钮复制完整任务、单次结果确认、资料回收站、导航、中文文案、待整理唯一入口、统一文档工作区、处理确认不误清、新版帮助。先改善最常用闭环。
- **第二优先级**：连接状态、分享范围固定、配置分层、外部改动冲突保护。
- **第三优先级**：高级手动修订、较复杂搜索、复杂执行历史等增强。没有可靠数据时不做占位界面。

新上传资料统一按原格式保存在 raw/sources/，停止创建 Office Markdown 副本；已有原件和历史副本不自动搬移或删除，按第 07、10 章兼容处理，不因为合并页面而删除已实现服务。新增权限限制属于业务行为调整，应独立提交、提供迁移说明和回归结果。

## 6. 产品成功标准

第一次使用的人不阅读技术协议，也能找到添加资料和整理入口；熟练用户能在当前资料选择后直接进入整理，不必重复选文件。复制、外部执行、确认处理三个阶段清晰分开。用户始终知道当前知识库、编辑是否保存、哪一个库正在对外开放。

验收方法见 09：按完整任务走查，不以按钮数量减少作为唯一成效标准。

## 7. 闭环实施要求

第 11 章的轻量文件扫描与任务恢复、逐项确认和失败补记是本版必须完成的基础能力，不归入可推迟的复杂执行历史。上传范围为 md/txt/docx/xlsx，单文件 20 MiB；原格式保存不等于自动支持任意格式。

## 2. 知识库切换器

下拉面板包含搜索库名、现有库列表、当前库标记、“新建知识库”“管理当前知识库”。列表显示名称和路径摘要；不在此处扫描全盘统计。

- 单击库名切换，不要求双击。
- 切换先处理当前编辑，再取消旧页面加载，最后刷新依赖上下文的数据。
- 慢请求带知识库上下文版本，旧库请求晚返回不得覆盖新库页面。
- 当前库被外部删除：保留错误提示，要求选择其他库；不自动新建同名空库。
- 切换后的默认页为该库上次访问的“知识/资料/整理”；首次进入为知识。
- 对外服务绑定的库不随切换改变，顶部提示“浏览分享仍在分享：产品研究”，可跳转管理。

## 3. 创建知识库

一个轻量对话框内填写“知识库名称”，选择模板“通用/研究/读书/业务”，可展开“目标说明”。默认通用，不强迫先写配置。

名称即时校验，复用原服务的合法字符规则；重名显示“这个知识库已存在”，提供“打开已有知识库”，不覆盖。创建中防重复提交；成功选中新库进入资料空状态，主按钮“添加资料”。

无库启动时内容区显示三步：“创建知识库 → 添加资料 → 整理成知识”，只突出“创建知识库”。用户不必先配置路径。路径不可访问时显示修复入口，不能误显示为没有知识库。

## 4. 统一布局与视觉

保留 .NET 10、WPF、WPF-UI 4.3.0、MVVM 的既有基线，不在设计期重选技术栈。优先项目已封装业务控件，其次 WPF-UI，再用 WPF 原生控件。现有服务和控件名称以源码盘点结果为准。

| 项目 | 规范 |
|---|---|
| 窗口 | 建议 1440×900；1180×760 为推荐最小工作尺寸；1100×650 核心操作仍可通过滚动访问 |
| 导航 | 208—224px，可折叠为 64px；只持久化布局偏好 |
| 顶栏/状态栏 | 约 52px / 28px；长路径在详情而非状态栏完整铺开 |
| 页面留白 | 左右 24px，区块间距 16px；正文 14px，标题 26px |
| 主操作 | 每个任务区一个主要蓝色按钮；不可恢复删除采用危险样式，可恢复移除显示“移入回收站” |
| 颜色 | 延续原主题 Token；深浅主题齐全；Windows 蓝强调，禁止紫色渐变与发光 |
| 内容布局 | 文档列表/目录树 + 阅读编辑区；表单按需展开，避免所有功能卡同时堆叠 |

主题资源集中管理，状态同时有文字和图标，不能只用颜色。图标按钮有 Tooltip、AutomationProperties.Name 和可见焦点。

## 5. 全局查找与局部筛选

顶栏 placeholder 固定为“查找当前库文件…”，按文件名搜索资料和知识，结果分组显示名称与相对路径。Ctrl+K 聚焦，方向键选择，Enter 打开选中项，Esc 收起。跨页打开也执行未保存保护。

局部搜索分别标为“筛选资料文件名”“筛选知识目录”，只过滤当前页。MCP 的内容搜索不等同桌面的全局搜索，不能因服务有该工具就声称桌面已有全文检索。若后续接入真实正文搜索，提供明确的“文件名/正文”范围及加载、截断状态。

## 6. 保存与离开保护

触发：切文件、切页、切库、改根目录、关闭窗口、关闭正在编辑的面板。

统一按钮：“保存并继续 / 放弃更改 / 留在此处”。保存失败留在原页面，显示原因与重试；放弃只丢弃当前草稿，不撤销已经落盘的修改。任务表单未生成输入在会话内保留，正常离开有保护；生成后的任务快照跨重启保存。文档意外崩溃草稿本版不保证恢复，不与任务恢复混为一谈。

保存期间锁定目标文件标识，不能随选择变化把内容写入另一文件。写回前发现磁盘文件发生变化，显示“文件已被其他程序修改”，提供“查看磁盘版本 / 另存副本 / 返回编辑”；不提供无说明的覆盖。

## 7. 状态、消息与快捷键

| 类型 | 表达 |
|---|---|
| 加载 | 区域内进度，保留旧内容但标记正在刷新 |
| 真正空白 | 一句话解释 + 对应主操作 |
| 无搜索结果 | “没有匹配文件” + 清空筛选 |
| 加载失败 | 错误摘要 + 重试；不显示暂无数据 |
| 成功 | Snackbar“已保存”“已复制整理指令”等，约 3 秒 |
| 长期状态 | 页面内保留“等待外部执行”“分享中”等，不只使用 Toast |
| 详细错误 | 可展开技术详情，默认中文；不包含令牌、PIN 和文档正文 |

Ctrl+S 保存当前编辑文档；Ctrl+F 聚焦页内筛选；F5 刷新当前页并保护草稿；Esc 关闭轻面板，编辑中先执行保护；Ctrl+N 仅资料页且焦点不在文本控件时新建资料。

保存按钮、保存后是否退出编辑及人工修订保护统一见 [闭环补全规范第 7 节](11_闭环补全与状态恢复规范.md#7-文本编辑与手动知识修订)。

普通保存、复制、可恢复移入回收站与结果勾选后的确认不重复弹确认框；危险操作才单独确认。首次整理无需先单独粘贴库说明；已配置适配工具时主按钮“开始整理”，否则“复制整理指令”。普通确认减负见第 12 章，执行入口见第 13 章。

## 8. 通用组件复用清单

库切换器、文档工作区、文件元信息栏、未保存对话框、操作反馈、错误区、待整理清单、指令预览面板应复用已有封装。数据可共享服务，但不同页不共用会互相覆盖的编辑缓冲区；相同文件的冲突由统一文件版本校验处理。

# 02｜资料与知识工作区

## 1. 两个区域的关系

“资料”是输入，“知识”是外部 AI 整理后的输出。两页保留，因为对象和操作权限不同；合并底层文档组件，取消同一文件在多处重复维护的入口。

| 对象 | 展示位置 | 默认操作 | 写入影响 |
|---|---|---|---|
| raw/sources/*.md、*.txt | 资料 | 预览、编辑、删除 | 记录源变更和日志 |
| docx/xlsx 原格式资料 | 资料 | 查看文件信息、支持时预览、打开/导出原文件、重新上传、删除 | 操作 raw/sources/ 下的源文件，记录源变更 |
| wiki/ 下的知识页 | 知识 | 阅读、链接跳转、复制路径 | 默认不写入 |
| wiki/log.md | 整理中的“查看变更日志” | 只读 | 仅既有日志服务追加 |
| purpose.md、schema.md | 知识库设置 | 查看、编辑 | 沿用配置变更记录规则 |
| .changes.json 等内部文件 | 普通列表隐藏 | 由业务服务维护 | 禁止作为普通文档编辑 |

## 3. 添加资料

“添加文件”使用系统多选文件选择器；若现有拖拽可用则保留。当前支持 md/txt/docx/xlsx，所有支持类型都按原格式保存，不强制 Markdown。PDF、doc/xls、图片等是否支持是独立能力，本次不因取消转换就宣称全部格式已支持；不支持时提示“此类型暂不支持添加”。

处理列表逐项展示“等待 / 保存中 / 已添加 / 已跳过 / 失败”。按原字节保存文件，不做上传转码或 Markdown 转换。先完整写入临时文件并校验，再提交目标；失败不留下半文件，覆盖失败保留之前有效版本。无真实百分比时只显示阶段。

重名先列冲突文件，让用户选“覆盖同名 / 跳过同名 / 返回”；可只对本批应用同一选择。覆盖提示“将替换现有资料，替换后需要重新整理知识”。非冲突文件与冲突文件的执行范围在提交前明确。

单文件上限 20 MiB（20,971,520 字节），多选按文件逐项提交。底层请求体上限需为协议封装预留空间，批次总量不能误当单文件上限；接入前按第 11 章适配传输。

完成后保留结果摘要，例如“已添加 3 份，失败 1 份”；失败条目提供重试。主后续操作“整理新增资料”，次操作“继续添加”。不自动执行外部 AI。

## 4. 非文本源文件展示与操作

- Word、Excel 文件直接保存为 raw/sources/需求说明.docx、raw/sources/销售明细.xlsx，一份上传对应一个原格式文件。
- 列表显示真实文件名与类型；预览可用时显示原文件预览，没有可用预览器时显示文件信息及“打开原文件 / 导出文件”，不阻止添加或整理。
- 预览或 AI 读取需要的临时内容提取仅在读取时进行，不保存为资料 Markdown，不替代原文件；不因预览失败把添加标成失败。
- 桌面文本编辑器只编辑受支持的文本类型。Word、Excel 用系统关联程序打开，不用文本框读写二进制文件。打开前提示“修改并保存原文件后，请返回应用刷新”。
- 外部编辑后，通过文件监测触发扫描，启动、进入资料页、刷新与确认前也扫描；按第 11 章持久指纹基线检测应用关闭期间的变化，排除 Office 锁文件。扫描不完整不判删除。
- “移入回收站”将所选源文件从活动目录移至库内隐藏回收站，不执行历史副本级联删除；可恢复，已有知识仍需引用清理。
- 重传先暂存并验证，把旧文件保留为回收站“覆盖前版本”，再替换同名源文件；不能安全保留旧版本则拒绝覆盖。添加、导出保持原字节；用户主动编辑保存才改变内容。
- 历史 raw/original 与历史 Markdown 衍生文件只作兼容展示，不自动移动、转换或删除；身份与变更切换见第 07、10 章。

## 5. 新建与编辑

“新建资料”菜单只有 Markdown、纯文本；默认为 Markdown。在右侧工作区输入文件名和正文，“创建资料”为主操作。缺少后缀按选择类型补齐，非法名和重名就地提示。未成功创建前不产生空文件。

文本选中后默认预览，点击“编辑”进入原位编辑；工具栏显示“未保存 / 保存中 / 已保存 / 保存失败”。支持现有的预览切换能力；分屏不是首轮必做。Ctrl+S 保存，取消走统一保护。无修改保存禁用；成功后继续编辑，点“完成编辑”回预览；保存中防重复，失败保留草稿，细则见第 11 章。

移入回收站前先处理编辑草稿；保存失败或取消则不移除。可恢复移除不再额外弹删除确认，成功后提供“撤销”；批量范围和隐藏选择数量提前显示，失败逐项说明。永久删除、整库删除仍需危险确认。资料页更多菜单提供“回收站”，恢复冲突与变更规则见第 12 章。

## 6. 资料选择与整理跳转

复选框选择与行单击预览分开。筛选后保留已选项，并显示“已选 5 项，其中 2 项被筛选隐藏”，避免暗中丢失或误删。切库清空选择。

“整理所选”携带当前库和稳定的相对路径进入整理页，范围自动为“所选资料”，不要求再填逗号文件名。按钮在无选择时禁用。跳转期间文件被删除时先提示缺失项，可移除缺失项后继续。

## 7. 知识页线框与默认入口

```text

产品研究 · 3 项资料变更尚未整理                         [去整理]
┌────────────────────────┬────────────────────────────────────────────┐
│ 筛选知识目录…          │ 产品概览                       [复制路径] […]│
│ ▼ 知识首页             │ wiki/overview.md                            │
│ ▼ 概念                 ├────────────────────────────────────────────┤
│   业务模型             │ Markdown 正文、表格与代码块                  │
│ ▼ 实体                 │ [[业务模型]] 可点击                          │
│ ▼ 资料摘要             │                                            │
│ ▷ 分析与对比           │ 来源：需求说明.docx [查看资料]                │
└────────────────────────┴────────────────────────────────────────────┘
```

首次打开默认选 wiki/index.md，缺失则尝试 overview.md；只有初始模板骨架且没有其他知识页时也视为尚未整理，按第 11 章模板哈希判定；没有知识时根据是否已有资料显示“添加资料”或“开始整理”。不要求新增数据库或自建知识首页文件。

目录使用中文分类别名，但不重命名磁盘目录：entities→实体、concepts→概念、sources→资料摘要、queries→问题分析、synthesis→综合分析、comparisons→对比。详情与复制路径始终使用真实相对路径。

Wiki 链接按现有解析能力解析相对目标；同名歧义展示候选路径；不存在显示“目标页面不存在”。来源标记能准确映射时提供“查看资料”，映射不可靠则只展示原引用，不猜测跳转。删除资料后的引用显示“来源已移除”，提供整理入口。

## 8. 高级手动修订

默认工具栏无“编辑”。更多菜单“手动修订知识…”说明“此内容通常由 AI 维护，手动修改不会更新源资料，后续整理应先核对人工内容”。显式进入后复用编辑器、版本校验、未保存保护；保存后记录手工版本保护。MCP 不可静默覆盖，文件直读通过指令提醒，具体见第 11 章。

只允许原服务允许的 wiki Markdown/TXT 文件；日志和系统文件保持只读。修订写回原相对路径，登记操作日志但不伪造成源资料待整理项。不新增知识页删除入口；清理仍通过维护流程计划后在本机确认。

高级手动修订正式纳入本版，仅作用于允许的知识文本；需同时实现版本保护和 MCP 冲突拒绝，不能只开放编辑按钮而跳过权限规则。

## 1. 页面目标

这里统一回答“有什么要整理、交给 AI 什么任务、执行后怎样确认”。不再展示七张并列卡，不加入聊天窗口。任务选择只有三项：**更新知识 / 提问分析 / 检查维护**。

```text
整理                                           当前知识库：产品研究
[更新知识] [提问分析] [检查维护]

│ 1 准备指令  →  2 在外部 AI 中执行  →  3 检查结果                    │
```

## 2. 更新知识：三个范围、一套流程

| 范围 | 适用情况 | 默认选择 |
|---|---|---|
| 待整理变更 | 日常新增、修改、删除 | 默认范围；首次进入默认不勾选，提供全选 |
| 所选资料 | 从资料页带入，或手动选择 | 继承调用方明确选择 |
| 全部资料 | 第一次整理，或主动全面重新整理 | 先显示总数与可能耗时；用户确认范围后生成 |

“全部资料”不命名为“重建”，避免用户误解为先删除 Wiki。其语义是按批量模板重新审视全部输入，不能先清空知识目录。

待整理清单显示资料新增、修改、删除；目标与规则变化作为独立持久提醒。保留 `.changes.json` 格式与合并规则，提醒在 .llmwiki/reviews.json 中按版本维护，完成条件见第 11 章。

对于删除项，文案写“整理引用”，不写“重新读取资料”。生成器组合原增量处理说明与清理计划，必须保留“共享实体不整页删除、先列拟修改项”的约束。没有删除工具的 MCP 任务要明确：本次可修订引用，但真正删除文件需本机确认，不能承诺自动完成全部清理。

## 3. 任务准备、复制与主动执行

以下步骤描述无已配置本机工具时的复制分支；有适配工具时由第 13 章开始/取消/核对流程执行，复用相同快照与确认规则。

1. 选择任务和范围，页面检查当前库可访问、目标资料存在、删除项确实已删除。
2. 点击“复制整理指令”，一次完成校验、持久化库/范围/规则/文件快照、组合上下文与任务正文，再写剪贴板；可选“预览完整指令”，不强制先预览。
3. 展示任务摘要：处理范围、外部工具与访问方式。本机启动器由用户点击开始后启动外部进程；复制方式仍由用户去外部工具粘贴。应用不内置模型。
4. 写剪贴板成功才显示“已复制，等待外部执行”；复制失败保留已准备任务，重试同一快照，不重复创建任务。
5. 用户到外部 AI 工具粘贴执行；面板不根据剪贴板事件推断是否启动、成功或失败。
6. 返回后“查看本次变化”打开本次文件变化与逐项核对面板，再由条目进入知识页，“刷新待整理清单”读取当前真实状态。
7. 用户核对后点击“确认完成这 {n} 项”，仅确认本次仍一致的变更。

修改输入后生成新任务，不覆盖原快照；切库保留原库任务。范围内资料变化仅使相应项失效，无关新增项不阻断所选任务；全部资料范围增加、规则或模板变化时，重新复制必须准备新任务。完整失效规则见第 11 章。

指令正文继续复用已有 PromptEngine/模板，不在页面写第二套文案。UI 中文名称与协议标识分离，旧 CLI/MCP 标识保持兼容。

## 4. 确认处理的必要保护

“确认处理”表示用户确认本次变更已由外部 AI 处理，不是系统证明知识质量合格。按钮旁显示这一说明。

- 在结果面板持续显示将移出的项目和数量，勾选即表示用户已核对；点击“确认完成这 {n} 项”一次提交，不再另弹普通确认框。
- 已复制不是启用确认按钮的充分依据；用户可以未复制而在外部自行处理，因此允许“我已在外部完成”并明确确认。
- 只有选中的待整理记录能被清除，不清空整库变更。
- 新增/修改项比较记录快照及当前文件内容版本；删除项比较变更记录版本，并确认文件没有重新出现。
- 生成后再次变动的项继续保留，反馈“已确认 2 项；1 项有新变化，仍待整理”。
- 确认与新增变更并发时必须在业务服务中以同一写入临界区比较并修改，不能在 UI 先读后全量覆盖 JSON。
- 若旧记录无 hash，可计算当前指纹并结合记录字段形成会话快照；不能因缺 hash 就直接清除。无法稳定匹配的项要求刷新后重新选择。
- 所选资料/全部资料模式只有能映射到本次快照的待整理记录才可确认，不能按文件名消除后来发生的新记录。
- 所有新资料按原文件相对路径匹配；SHA256 针对原文件字节计算，不用派生文本替代。历史记录按第 07、10 章显式适配。

确认失败保留所有未成功项。现有清除 API 如不支持上述语义，应先增加服务级“比较后确认”能力，再启用新按钮；禁止仅用前端延迟掩盖竞态。

## 5. 任务状态与持久化

| 状态 | 用户能看到什么 | 可做什么 |
|---|---|---|
| 未准备 | 任务表单与范围 | 选择、生成 |
| 已生成 | 本次范围、指令、生成时间 | 预览、复制 |
| 已复制/已交给外部 | 等待外部执行，未确认完成 | 查看结果、刷新、确认 |
| 某项已变化（附加标记） | 标注受影响项，其他项可继续核对 | 为变化项准备新任务 |
| 部分确认 | 已确认数量、保留项目原因 | 继续处理剩余项 |
| 本次已确认 | 明确本次范围，不表示整库无其他变更 | 返回知识或开始下一次 |

生成后的任务以隐藏 JSON 记录跨重启保留，不建数据库、不混入 `.changes.json`。恢复任务范围、文件版本和逐项确认进度，不把复制恢复成执行成功。未完成任务不自动清理，完成/放弃记录保留最近 50 条且最多 30 天；字段与恢复细则见第 11 章。

## 6. 提问分析

类型切换：“回答问题 / 对比主题”。输入区仅显示对应字段，例子使用当前知识主题的通用占位，不插入虚构答案。

- 回答问题：标签“你想了解什么？”，必填；调用 Query 模板。
- 对比主题：标签“你想比较什么？”，必填；调用 Compare 模板。
- 下方共用执行入口；本机工具可用时“开始分析”，否则复制完整任务。
- 显示“回答会在外部 AI 工具中生成”，不显示空聊天气泡或“发送”按钮。
- 分析结果是否写入 queries/comparisons 以模板规则为准，界面不能声称每次提问都会存档。

## 7. 检查维护

两个任务：

1. **检查知识质量**：沿用 Lint，检查来源、矛盾、陈旧、孤立页、缺口；可由用户主动交给本机工具执行，或复制检查任务；程序结束仍需核对报告。
2. **处理已删除资料的引用**：沿用 Clean，可从删除变更中选择；显示“先生成清理计划，再在外部确认执行”。

维护面板不提供“一键清空知识”“自动修复全部”等新能力。无删除项时仍可阅读说明，但不生成空清理任务。

## 8. MCP 协作与手动复制的关系

执行入口与访问方式分开：已验证本机工具可用时默认“开始整理”，否则“复制整理指令”；高级入口可导出任务包。访问方式为文件访问或 MCP；选择外部 MCP 客户端时只复制任务说明，不假装已派发。详细启动、取消和重试按第 13 章。

本工具提供 MCP 服务，通常由外部客户端主动调用；**服务开启不等于任务已发送，连接成功不等于整理完成**。外部客户端需读取资料并写知识时必须有写权限；只读连接只能查询和生成计划，应提示切到文件直读方式或由用户开启写入。

MCP 写入不自动确认待整理项。旧 Prompt 若包含绝对路径，则“手动文件访问”保留该语义；MCP 版本通过同一生成器的传输上下文适配成逻辑资源和工具调用，不能把本机路径当远端可访问路径，也不能宣称两个版本逐字一致。

## 9. 七类能力去向对照

| 旧能力 | 中文新入口 | 协议/模板兼容标识 |
|---|---|---|
| Boundary | 自动随任务携带；高级查看/复制库说明 | boundary |
| Batch Ingest | 更新知识 / 所选资料或全部资料 | batch_ingest |
| Incremental Ingest | 更新知识 / 待整理变更 | incremental_ingest |
| Query | 提问分析 / 回答问题 | query |

| Lint | 检查维护 / 检查知识质量 | lint |

## 10. 原格式资料的读取能力

任务直接列出源文件名与真实路径，包括 docx/xlsx；不再要求存在同名 .md。执行前说明外部 AI 必须能读取相应原格式，不能因文件不是 Markdown 就忽略它。

文件直读模式由外部 Agent 的文件读取/解析工具处理；MCP 模式通过已实现的原格式内容读取能力提供临时文本或表格响应，不生成落盘 Markdown。工具不支持、读取失败、内容被截断或加密时明确告知，受影响项继续待整理，不当作已执行成功。可更换具备读取能力的工具，不强迫用户转换源格式。

## 11. 结果核对与部分完成

本次结果面板列出从任务准备以来 wiki/ 新增、修改、删除的文件及来源关联；变化可能来自其他程序，不等于 AI 成功。资料逐项选择确认，读取失败/未完整读取默认保留，已在其他工具完成可带理由人工确认；无变化但已核对无需修改也可说明后确认。

外部执行期间新增无关资料不影响本次已完成项。确认前重新扫描并比较源版本，记录冲突或有新变化的项继续保留。任务开始基线、跨重启恢复、确认凭据与规则提醒完成条件统一按 [闭环补全规范](11_闭环补全与状态恢复规范.md) 实施。

## 12. 日常操作减负

统一使用第 12 章的自包含任务；有可用适配工具时按第 13 章主动执行，无工具时单按钮复制；结果页勾选后一次确认。资料删除先移入回收站，恢复会使相关清理任务按版本失效，不自动恢复已清理的知识。

# 04｜连接与分享及权限

## 1. 入口与概念

页面分为“浏览分享”“AI 工具”两个页签，各自拥有真实状态、开关、权限和帮助。共用宿主是实现细节，界面开关独立；关闭浏览分享不能意外断开用户以为独立运行的 MCP。若现有服务耦合，先拆生命周期再开放独立开关。

| 场景 | 方式 | 凭据 | 写入 |
|---|---|---|---|
| 手机或其他设备看资料和知识 | 浏览分享 | 4 位 PIN | 始终禁止 |
| 本机 Agent 直接访问文件 | 复制含库上下文的完整任务 | 文件系统权限 | 由外部 Agent 和用户本机权限约束 |
| 外部 AI 客户端通过协议访问 | MCP | HTTP 令牌；stdio 遵循本机权限 | 默认只读，HTTP 可显式授权写入 |
| 多台电脑访问同一文件夹 | Windows 共享路径 | Windows 共享权限 | 不由网页或 MCP 开关约束 |

页面不得暗示关闭 MCP 写入就能限制拥有文件系统权限的本机 Agent，也不得暗示 UNC 目录天然只读。

## 2. 分享范围：固定单库会话

开启前显示“分享知识库：产品研究”。服务会话绑定该库，而非动态读取 SelectedKb。用户切换到其他库时，服务继续原范围，并在全局显示分享中的库名。

更换分享库需要“停止并更换范围”，关闭旧连接、失效旧凭据、生成新凭据后重启；不在旧令牌下静默暴露新库。删除正在分享的库时先停止相关服务，停止失败则拒绝删除。根目录切换也先停止所有绑定服务，保留配置但不自动重启。

MCP 的 list_knowledge_bases 仅返回当前授权范围；携带其他 kb 参数应拒绝。浏览分享不提供全根目录库列表。此为有意收窄的 V2 权限变化，需验证旧客户端兼容行为。

## 3. 浏览分享线框

```text
连接与分享                  [浏览分享] [AI 工具]
浏览分享：已关闭                                  [启动浏览分享]
让可信局域网中的其他设备查看“产品研究”。
分享范围：产品研究 / 资料、知识和可下载原件

启动后：
访问地址  http://<真实局域网地址>:<实际端口>   [复制] [二维码]
访问码    <本次生成的 PIN>                    [复制] [更换访问码]
允许：浏览、预览、下载     不允许：上传、编辑、删除、改配置
[停止浏览分享]
```

启动时显示“正在启动”，失败回到关闭并展示原因；运行中显示实际端口与可用地址。无 LAN 地址提供本机测试地址并说明“当前未检测到局域网地址”；多个网卡逐条展示，避免混为单个文本。

二维码默认编码不含 PIN 的地址，扫码后输入 PIN；如旧实现包含 PIN，需明显标注“二维码包含访问码”，不把带凭据 URL 写日志。更换 PIN 应使旧凭据与已认证会话失效；如果现有 cookie 机制不能失效，应修正服务端而非只替换显示文字。

只读网页沿用“只读浏览 · 编辑请回到桌面应用”横幅，移动端树与正文可切换，允许下载已授权库的原件。下载也校验 PIN 和路径，不因静态文件中间件绕过认证。

## 4. AI 工具：先选方式，再显示配置

### 4.1 手动复制

默认说明“到整理页复制完整任务，在能访问该目录的外部 AI 中执行”。不再要求首次先复制接入说明，也不显示无可靠依据的接入完成状态；高级折叠入口保留“查看库说明 / 复制库说明”。

每次任务自动携带库身份、路径、目标规则入口、版本、任务范围和边界；不依赖历史对话记忆。MCP 的首次客户端配置仍在此页完成，服务端每次调用独立校验权限，不要求 AI 先调用 boundary。完整交互见第 12 章。

### 4.2 MCP 本机 HTTP

展开后展示：服务状态、绑定库、本机端点、权限“只读”、令牌掩码、复制令牌、重新生成、客户端配置。

默认关闭、回环监听、只读。写入用独立写令牌；开启前明确“允许此连接修改本库 wiki/ 下的知识文件，不能修改原始资料、库规则或删除文件”。本版每次启动应用后恢复为只读，写权限不自动恢复；已有持久写权限要在升级说明中提示此变化。

停止或降权时，在最终落盘前再次检查会话权限；已经成功提交的写入不能撤销，UI 不承诺回滚。不能仅靠前端隐藏写入工具。

“允许局域网访问”为高级配置，默认关闭，显式确认后才改变监听；明文 HTTP 仅限可信网络。不在首轮承诺 HTTPS 证书管理。客户端配置按真实支持的客户端适配生成，不在文档虚构通用 JSON 或安装路径。

### 4.3 stdio 本机进程

放在高级连接方式中，V2 默认只读。显示实际可执行文件路径、配置预览与说明“由外部客户端启动，退出桌面应用不一定停止该进程”。不显示由桌面服务推测的运行状态。

若无法通过统一授权机制约束 stdio 范围，首轮不要宣称其跟随桌面当前库；需将授权库作为启动配置，配置改变后重启客户端进程。原实现若支持 --allow-write，必须核实现存配置并给出只读迁移提示，不能只隐藏开关。

## 5. 写入、清理与并发

HTTP 写入仅允许 wiki/ 下既有白名单文本；禁止 raw/、purpose.md、schema.md、.changes.json、wiki/log.md，禁止所有删除工具。原子写入、路径边界、拒绝链接绕过和令牌验证必须在服务层执行。

对已存在文件的写入强制 expected_version，缺失时返回 VERSION_REQUIRED；新建用显式“不存在”前置条件，避免抢占同名文件。该调整与旧可选参数存在兼容差异，要升级协议说明并回归客户端。

桌面保存同样比较磁盘版本；有可靠跨进程编辑登记时可附加“正在编辑”保护，没有时只承诺版本冲突检测，不声称能感知其他进程所有未保存草稿。stdio 只读降低首轮并发复杂度。

## 6. 连接诊断与权限反馈

只展示可验证状态：服务正在监听、令牌已配置、最近调用时间/工具/结果。没有可靠客户端心跳时不显示“已连接 3 台”。令牌、PIN、正文、绝对路径不进入普通调用日志。

常见错误对应中文：未授权→检查令牌；权限不足→连接只读；范围不符→连接绑定其他库；版本冲突→重新读取后重试；服务停止→返回应用开启。技术错误码可在详情中查看。

## 7. 验收

- [ ] 两类服务独立启停，状态来自服务，退出行为符合说明。
- [ ] 切库不静默换范围；更换范围使旧凭据失效。
- [ ] 旧 PIN/cookie、旧令牌、无凭据下载均被正确拒绝。
- [ ] 写权限升级、降级、重启恢复只读实际生效。
- [ ] 跨库、路径穿越、符号链接、删除、写入禁区均被服务拒绝。
- [ ] 写入版本冲突不覆盖已有内容，不自动清除待整理项。
- [ ] stdio 生命周期和授权范围与 UI 文案一致。

## 8. 原格式资料访问

浏览分享允许下载授权范围内的原格式文件，支持预览时直接预览，不支持时显示文件信息和下载入口，不提供强制转 Markdown 的操作。

MCP read_file 是文本读取工具，不表示能读取 Word/Excel。原格式读取使用第 10 章 read_source_content 格式适配，响应可包含临时文本或表格，不产生知识库 Markdown 副本。客户端或工具缺少适配时明确返回格式/读取错误；连接可用与文件可读取分别显示，不把这些失败项标记处理完成。

## 9. 本机执行配置

AI 工具页签内统一管理本机工具适配、MCP 连接及手动说明。适配器配置、身份检测、主动启动和取消按第 13 章；不把 MCP 当作与启动器互斥的执行方式，也不在应用设置重复配置。

文件不存在时显示“目标文件缺失 / 规则文件缺失”，主操作“载入默认模板”，先填入草稿，再由用户保存。不自动落盘。模板替换已有草稿先确认，不能丢失编辑内容。

保持 Markdown 文件为真实来源，不另外存一套表单数据。初版只增加中文说明和示例，不做复杂结构化表单与 Markdown 双向同步。

保存成功显示“已保存；已有知识尚未按新规则核对”，持久保存规则版本提醒。旧规则的指令不能作为新指令复制；已执行旧任务仍可逐项核对，但不消除新规则提醒。“稍后处理”只折叠当前版本提醒，不代表完成；全库核对后的显式确认条件见第 11 章。每次复制新任务都会读取当前规则版本，不再要求用户另行复制接入说明。

## 3. 删除知识库

危险区说明“永久删除全部资料、知识文件、任务状态和库内回收站，无法通过本应用恢复”。点击后列出真实库名、完整路径、影响范围，要求输入库名。

删除前检查：目录可访问、没有未解决编辑、所有绑定服务已停止、当前无文件写入任务。确认按钮为“永久删除此知识库”。失败显示实际结果，不能成功 Toast 后发现残留。若发生部分删除，标记库损坏并建议从备份恢复，不自动创建骨架掩盖。

删除后选取其他现有库或进入无库引导。无重命名库需求时本轮不新增重命名功能，避免破坏 Agent 路径。

## 4. 应用设置：存储

根目录输入只在此处出现。标签“知识库根目录”，辅助说明“该目录下每个子文件夹是一份知识库”。显示当前生效路径、待应用路径与验证结果。

操作：“浏览文件夹 / 应用路径 / 恢复默认”。恢复默认只修改输入，用户点击应用后生效。默认路径为当前用户 Documents/LLM Wiki/wikis，具体解析由系统服务决定，不硬编码用户名。

| 校验状态 | 文案 | 可应用 |
|---|---|---|
| 空 | 请填写知识库根目录 | 否 |
| 格式非法 | 路径格式不正确 | 否 |
| 校验中 | 正在检查目录 | 否 |
| 存在可用 | 目录可用 | 是 |
| 不存在但可创建 | 应用后将创建目录 | 是，提交前再次验证 |
| 无权限/不可达 | 无权限访问 / 共享目录不可达 | 否 |

异步校验必须对应最新输入；旧输入的成功结果不得启用新输入的应用按钮。不能只检测存在，还需按应用实际需要验证可读/可写能力；试写临时文件应清理且不触碰知识库内容。

## 5. 应用路径的事务顺序

0. 有本机任务仍在运行时先返回该任务，结束或取消并核实后才能更换根目录，不在运行中切换执行环境。
1. 解析待应用路径，展示“切换不会搬迁、合并或删除原目录文件”。
2. 处理所有编辑草稿；用户取消则整个切换取消。
3. 提示并停止浏览分享与 HTTP MCP，阻止新请求；独立 stdio 提示需在外部客户端停用或重启。
4. 再次验证并创建必要根目录，读取目标库列表。不要把一般文件夹自动变成知识库。
5. 成功后持久化路径并替换全局上下文，清空旧选择/过期指令/页缓存。
6. 失败则保留旧路径配置与上下文；已停止的服务保持关闭，告诉用户可手动重新开启，不静默重启。
7. 若旧库在新目录不存在，要求选择现有库；不能自动复制原库。

## 6. UNC 与多设备说明

支持手输 UNC 路径；复用已有系统文件夹选择器和局域网浏览封装，不为低频场景重做一套资源管理器。已有 net view 枚举作为辅助入口保留，失败不影响手输和系统路径选择。

配置页显示：“共享目录的读写权限由 Windows 管理。请避免多台设备同时维护同一份资料；修改者负责重新整理知识。”共享存储与浏览分享是两回事，页面提供对应说明链接。

读取失败显示网络错误与重试，不自动切回默认路径，也不自动建同名新库。映射盘符在不同运行账户可能不同，帮助建议使用该设备实际可访问的 UNC；不在 UI 承诺所有 Agent 可访问同一盘符。

## 7. 外观、关于与配置持久化

主题保留“深色 / 浅色”，不添加未实现的“跟随系统”选项。切换立即生效，所有页、编辑器、弹窗和只读提示均覆盖。导航折叠持久化；页筛选和未生成输入会话内保留；生成后的整理任务跨重启保存，文档草稿通过正常离开保护，不承诺崩溃恢复。

版本来自实际程序集；更新检查仅在现有更新渠道可靠时展示。检查失败显示原因，不显示“已是最新”。无更新服务则只显示版本与已有下载入口，不伪造按钮。

沿用既有配置文件位置与字段，兼容 wikisDir；新增 UI 偏好加版本或独立命名空间，写配置时保留未知字段。PIN 不当作普通偏好保存；令牌沿用受保护存储，普通 README 和日志不落密钥。

# 06｜完整流程与中文文案规范

## 1. 首次使用流程

```text
启动
 ├─ 根目录无法访问 → 修复存储路径 → 重试
 ├─ 没有知识库 → 创建知识库 → 资料页
 └─ 已有知识库 → 恢复当前库 → 上次主页面

资料页 → 添加文件 → 查看结果 → 整理新增资料
       → 复制完整任务指令 → 到外部 AI 执行 → 查看知识 → 确认处理
```

首用引导仅在无库或没有资料/知识时出现。已有库的老用户不强制完成向导、不重新创建配置、不自动执行整理。

首次和日常都在整理页操作，库说明与任务自动组合。已配置并验证本机工具时点击“开始整理”，否则“复制整理指令”到外部 AI 执行。只有选择 MCP 且尚未配置客户端时才去连接页；没有 MCP 也能走完整流程。

## 2. 日常新增和修改

1. 从资料页添加文件或编辑文本并保存。
2. 页头提示“有 2 项资料变更尚未整理”，提供“去整理”。
3. 整理页默认待整理范围，用户选择对应项。
4. 点击“复制整理指令”，上下文与本次任务一次复制，在外部执行。
5. 返回查看知识内容和来源，确认本次处理。
6. 剩余项继续保留；没有待整理项时显示“暂无待整理变更”，不用“全部知识已同步”，因为系统无法证明外部结果正确。

不要求每次修改都跑全部资料；不把未整理当成保存失败。资料保存成功与知识尚未更新可以同时成立。

## 3. 删除资料与清理知识

```text
移入回收站 → 原格式文件可恢复 → 记录删除变更
  → 整理中心选择删除项 → 生成引用清理计划
  → 外部核对受影响知识 → 在允许范围执行修订/本机确认删除
  → 检查知识链接和共享实体 → 确认该删除变更已处理
```

资料删除后知识仍存在是可解释状态，不自动清掉引用或整页知识。只读 MCP 无法写；写 MCP 也不支持文件删除。执行说明必须针对连接能力生成，不让用户等待永远无法完成的操作。

## 4. 阅读与分析

打开知识页 → 浏览目录/文件名查找 → 阅读正文 → 点击来源回到资料。想提问时进入整理/提问分析，填写问题并选择外部执行方式。阅读工具与问答指令相互衔接，但不将知识页伪装为内置聊天。

## 5. 共享与切库

启动浏览分享前明确库名 → 获取地址与 PIN → 其他设备输入 PIN 浏览 → 桌面切到另一个库 → 状态栏仍明确原库在分享 → 用户在连接页停止或更换范围。

切换根目录前先解决草稿和服务；取消任一步时不继续。退出桌面时停止桌面宿主服务；独立 stdio 的停止方式另作说明。

## 6. 异常恢复流程

| 异常 | 保留内容 | 恢复入口 |
|---|---|---|
| 文件上传部分失败 | 已成功项、失败清单 | 重试失败文件 |
| 文件保存失败 | 原有效文件；未完成临时文件不算入库 | 查看原因、重新上传 |
| 原格式内容读取失败 | 原文件与待整理状态 | 更换读取工具或稍后重试，不自动转 Markdown |
| 编辑保存失败 | 当前草稿、原文、目标路径 | 重试保存/另存副本 |
| 外部 Agent 改了当前文件 | 用户草稿、磁盘新版本 | 查看冲突/另存副本 |
| 共享目录断开 | 当前上下文和草稿 | 重连后重试；不用空列表冒充无数据 |
| 外部 AI 未执行或中断 | 待整理变更 | 重新复制指令；应用不猜测完成率 |
| 生成后又有变更 | 新变更记录 | 重新生成或仅确认未变化项 |
| 分享启动失败 | 用户配置，不保留假运行状态 | 修改端口/查看网络后重试 |
| 设置持久化失败 | 原生效配置、当前输入 | 重试，不显示已应用 |
| 文件已保存但记录失败 | 源文件、持久修复凭据 | 重试登记，不重复上传 |
| 应用重启后继续整理 | 原任务范围、版本和确认进度 | 打开未完成任务；本机 attempt 中断先核实进程，不推断执行成功 |

# 07｜实现映射与兼容迁移

## 1. 实施原则

这是已实现产品的渐进改造。先盘点真实源码，再按功能迁移视图和交互；不按文档建议目录批量搬代码，不从零重写文件桥、提示词引擎或分享服务；上传链路取消 Markdown 转换，既有转换器仅在需要时改为无落盘的读取适配。

本文件中的类名是现有程序盘点时的映射线索，不代表已验证存在。实施者必须将实际类、接口、资源字典和调用链填入盘点报告。

## 2. 页面映射

| 原页面/组件 | 新归属 | 实施动作 |
|---|---|---|
| DashboardPage | 库切换器、无库引导、页面摘要 | 拆出库操作；取消仪表盘导航，旧路由重定向到当前库 |
| SourcePage | 资料 | 复用上传与编辑，直接删除改为回收站服务；移走完整变更确认列表 |
| TreeBrowserPage | 知识 | 限制内容树范围；默认只读，复用预览 |
| WorkflowPage | 整理 | 七卡生成器保留，替换为任务表单与统一结果面板 |
| SharePage | 连接与分享 | 浏览分享和 AI 工具分页签，拆状态与生命周期 |
| ConfigPage | 知识库设置 + 应用设置 | purpose/schema 留库内；根目录移应用级 |
| SettingsPage | 应用设置 | 合并主题与版本，删除重复路径入口 |
| GuidePage | 使用帮助 | 改写为完整任务教程与配置解释 |
| DocumentWorkspace | 资料/知识/规则编辑共用 | 按文档角色注入权限，不以扩展名独自决定可编辑 |
| ChangeService/对应服务 | 整理中心 | 增加快照比较确认，原文件格式兼容 |
| 新增执行适配层 | AI 工具配置、本机任务运行 | 复用任务上下文；按工具能力启动、取消、接收事件，不拼 shell 命令 |
| PromptEngine/对应服务 | 整理、AI 工具、MCP Prompts | 单一模板来源，按传输上下文适配 |

旧快捷入口携带 kb 与相对路径重定向到新入口，不能静默丢上下文。原 Ctrl+K/Ctrl+S 等快捷键保持语义兼容，旧页面名不再出现在用户帮助。

## 3. 状态与服务边界

| 状态 | 所有者 | 约束 |
|---|---|---|
| 当前知识库、根目录 | 统一上下文服务 | 切换时发布版本化通知 |
| 文件读写、元数据、版本 | 文件服务 | UI 不直接拼路径写盘 |
| 原格式文件身份与读取能力 | 资料/文件服务和格式读取适配 | 以源文件路径与原字节指纹为准；预览/提取不改变存储格式 |
| 待整理记录 | 变更服务 | UI 只选择，服务原子比较后确认 |
| 文档草稿、搜索、选中项 | 各页/工作区 VM | 不塞进全局大 state，避免跨页污染 |
| 分享绑定库、权限、运行状态 | 各服务会话 | 与当前页面选库独立 |
| 指令预览与输入 | 整理任务 VM + 隐藏任务 JSON | 按范围内资料/规则版本逐项判断；跨重启恢复，切库不覆盖 |

异步加载应支持取消或丢弃旧上下文结果；写操作必须持有明确目标标识。复用统一未保存协调器，先处理草稿，再执行调用方原动作。

## 4. 必须保留的数据契约

保留 wikis/<库名>/、purpose.md、schema.md、raw/sources/、raw/assets/、wiki/ 和 .changes.json。所有新上传文件直接存 raw/sources/原文件名，保持原扩展名与字节，不生成 .docx.md/.xlsx.md，不为新上传建立 raw/original。来源引用始终写实际源文件名。中文导航别名不写成磁盘目录。

已有 raw/original 与衍生 Markdown 文件不自动移动、删除或重新生成。阶段 0 盘点其映射、人工修改及待整理记录；历史源文件继续从真实位置读取。只有能可靠识别原件和派生物时才分组展示，不凭文件后缀猜测并删文件。

如果历史待整理项指向派生 Markdown，保持该记录身份和相应版本快照，明确显示为历史记录；切换到原文件任务需显式记录映射和用户确认，不能直接把路径改写后清除。新上传 Office 为原文件身份，即使同名历史资料存在也先提示冲突与处理范围，不隐式建立第二份主源或覆盖用户编辑过的历史 Markdown。

不新建数据库，不改 .changes.json 结构与去重规则，不把任务记录塞入变更清单；隐藏 .llmwiki/ JSON 状态记录扫描、任务、修复操作和人工核对，见第 11 章。此轮禁止自动批量迁移资料；若后续需要统一历史路径，应单独提供可预览、可回滚的迁移方案。

配置读取保留 wikisDir 与未知字段。新 UI 偏好可加命名空间或配置版本，但必须兼容旧启动；配置修改失败不切换运行时路径。

## 5. 有意改变的行为与迁移要求

| 改变 | 风险 | 迁移要求 |
|---|---|---|
| 分享绑定单库 | 旧链接可能失去其他库访问 | 首次升级停止服务并提示重新开启，不沿用旧范围凭据 |
| 写授权重启恢复只读 | 旧客户端写入失败 | 提示重新授权，返回明确只读错误，不自动提升权限 |
| stdio 仅只读 | 原写配置可能依赖旧启动参数 | 盘点现有配置，展示受影响项与替代 HTTP 写入方式 |
| Wiki 默认阅读 | 用户习惯直接编辑 | 若保留高级修订，在更多菜单和帮助中明确路径 |
| 上传保持源格式、不转 Markdown | 现有上传链路和任务可能依赖衍生文件 | 停止新转换；历史原件、派生物与变更保留并显式映射；任务直接读取原格式 |
| 写入要求版本前置条件 | 旧 MCP 客户端未传字段 | 发布错误码与参数说明；先验证现有客户端再启用强制策略 |
| 变更仅比较后确认 | 旧“全部清空”操作收窄 | 移除含糊按钮，保留逐项/全选明确确认 |

以上应分业务提交实施，不能和纯视觉改动混为一次“页面美化”。用户已实现的能力以保留服务为原则；任何无法确认安全兼容的行为先保留旧服务、暂不开放新入口，记录为未完成，不伪装验收通过。

## 6. 模板适配与 MCP 约束

七类协议名称与原参数兼容；中文任务名只是展示。文件直读模板保留绝对路径，MCP 模板使用授权库标识和工具名；共用核心任务定义和引用规则。

HTTP 与 stdio 共用路径校验和读权限策略。写入仅 HTTP 显式授权；检查相对路径、根目录包含关系、链接/junction、大小上限与系统文件禁区。不能靠文件扩展名白名单绕过 .changes.json 隐藏策略。

参数和日志限制沿用现有服务可验证值；不在改造文档中指定未经核实的 SDK 最新版本或客户端配置字段。开发时根据锁定依赖和目标客户端官方文档核对，记录实际版本与生成配置样例。

## 7. 回滚与交付

开始前备份用户目录与应用配置，记录旧版本构建和关键流程。纯 UI 改造不迁移业务数据，因此回滚旧程序时文本资料仍保持目录兼容；原格式 Office 新上传路径可能超出旧程序读取能力，须先核实支持矩阵，不能宣称无条件可回滚；新增配置字段不应破坏旧版本读取。

服务范围、授权模式和参数要求的变化需要单独迁移说明；回滚时不自动恢复高权限或重启分享。每阶段提供改动文件、行为变化、构建结果、关键页面截图、已知问题和回滚办法。

状态 JSON 引入与原格式上传同属有意行为变化：普通旧客户端需忽略隐藏目录，旧程序不会理解任务恢复、人工保护或未完成修复记录。回滚前完成修复、停止写入并核查原格式读取能力。

回收站是有意新增的可恢复删除机制：本地与 UNC 同用库内隐藏文件存储，回滚到不认识该目录的程序不会自动恢复资料；回滚前核实并导出需要保留的条目。MCP 和浏览分享不新增删除/回收访问权限。

## 8. 独立规范入口

数据结构、原格式存储、文件权限、日志与变更、任务模板语义及 MCP 能力统一见 [数据与服务契约](10_数据与服务契约.md)。本文中的现有页面与旧客户端仅指待改造程序及存量数据，不表示需要查阅其他设计版本。

# 08｜LLM Wiki 新版使用与配置说明

> 本说明对应 V2 目标界面，用于改造完成后随产品发布。当前仅有设计资料可核实，实际版本尚未按本说明运行验收；发布前应按实际按钮名称、安装包和客户端适配更新。本文不提供未经验证的下载地址、exe 路径或构建命令。

## 1. 这个工具能做什么

你可以把资料放进本地知识库，编辑和管理资料，再把工具生成的操作指令交给外部 AI，让 AI 整理出知识页面。资料、知识、规则和日志都保存在文件夹中。

工具不内置 AI 模型，也不需要配置模型 API Key。即使不连接 AI，仍可创建知识库、管理资料和查看已有知识。外部 AI 负责理解和整理内容；本应用负责文件管理、任务准备和连接权限。

## 2. 认识三个主要页面

| 页面 | 什么时候用 |
|---|---|
| 资料 | 添加文件、新建笔记、修改原始内容 |
| 知识 | 阅读整理结果、浏览分类、查看引用来源 |
| 整理 | 更新知识、准备问题或对比任务、检查知识质量 |

左上角切换当前知识库。底部的知识库设置只影响当前库，应用设置影响整个程序。连接与分享负责其他设备和外部 AI 的访问。

## 3. 第一次建立知识库

1. 打开应用；没有知识库时点击“创建知识库”。已有库时从左上库切换器点击“新建知识库”。
2. 输入名称，选择通用、研究、读书或业务模板。不确定时选通用。
3. 创建成功进入资料页，点击“添加文件”。
4. 选择 md、txt、docx 或 xlsx 文件。
5. 查看添加结果；失败的文件可单独重试。每个文件最大 20 MiB，多文件分别处理，不把整批限制为 20 MiB。

创建时不必先修改存储路径。默认位置为当前用户文档目录下的 LLM Wiki/wikis；应用设置会显示实际路径。安装程序目录和数据目录相互独立。

## 4. 第一次整理成知识：无需先配置的复制方式

1. 在资料页选择文件，点击“整理所选”；也可直接进入“整理 → 更新知识”。
2. 第一次可选全部资料，平时选择待整理变更或指定资料。
3. 默认“手动复制”，点击“复制整理指令”，当前库说明、目标规则入口和本次任务一次复制，无需先配置 AI 工具。
4. 在能访问该文件夹的外部 AI 中粘贴执行。
5. 回到整理页点击“查看本次变化”，检查文件变化、正文和来源。
6. 在同一面板勾选已核对完成的资料，点击“确认完成这 {n} 项”；一次提交，不再重复弹确认框。

复制成功只代表指令进入剪贴板。应用无法仅凭复制操作知道外部 AI 是否执行完成。没有生成知识时，先查看外部工具是否有路径访问权限、是否真的写回当前库的 wiki/ 目录。

## 5. 平时添加、修改与删除

添加文件后，从资料页点击“去整理”，使用待整理范围处理新增项即可。修改 md/txt 时先保存；保存完成后再整理相关项，不必每次处理全部资料。文本未修改时保存禁用，保存成功继续留在编辑模式，点“完成编辑”回到预览；保存中不要重复操作，失败时草稿保留。

Word 和 Excel 与其他支持类型一样按源格式保存，不生成 Markdown 副本。支持时可直接预览，不支持预览时点击“打开原文件”。使用系统关联程序修改并保存后，回到应用刷新检测变化；也可以修改本机文件后重新上传覆盖。

资料页的“移入回收站”保留原格式文件，可从更多菜单“回收站”恢复，成功提示也可撤销；不会立即删除已有知识。到整理页选择删除变更，让外部 AI 先给出引用清理计划，再按权限确认处理。核对共享实体和链接后才确认已处理。

## 6. 阅读、提问和对比

知识页左侧是分类，右侧是正文；查找框按文件名查找。点击可识别的来源可回到资料。

需要 AI 回答时，打开“整理 → 提问分析”，选择回答问题或对比主题，填写内容并生成操作指令。答案在外部 AI 中产生；是否存入知识库以任务指令和实际执行结果为准。

“检查维护”可生成知识质量检查任务，或处理已删除资料的引用。生成检查指令并不表示检查已经完成。

## 7. 修改知识库目标与规则

打开“知识库设置 → 目标与结构”。

| 配置 | 建议填写内容 | 示例 |
|---|---|---|
| 目标与边界 purpose.md | 使用者、要解决的问题、资料范围、不包含什么 | 面向售后团队整理产品操作和故障处理，不包含客户隐私记录 |
| 组织规则 schema.md | 分类、来源引用、页面关系、命名规则 | 产品放实体，方法放概念；结论标注来源，相关知识使用互链 |

不知道怎么写时保留默认模板。保存后，下一次复制完整任务会自动使用新规则与最新上下文。配置不会自行重写已有知识。规则更新提醒会保留，点击“稍后处理”仅收起提醒；按当前规则核对完整知识库后，再显式确认已完成规则更新。

## 8. 更换存储位置

1. 打开“应用设置 → 存储”。
2. 浏览文件夹或填写路径，等待校验。
3. 点击“应用路径”，处理未保存内容和运行中的服务。
4. 在新目录选择已有知识库，或创建新库。

应用路径只切换读取位置，不移动或合并原数据。需要搬迁时，先关闭访问该库的程序和服务，备份后手动复制整个知识库目录，再选择目标根目录并检查。不要只复制 wiki/ 而遗漏资料和规则。

使用共享文件夹时填写当前电脑能访问的 UNC，如 `\\主机名\共享名\wikis`。Windows 负责共享权限；本应用不会自动给其他电脑授予访问权。不要两台电脑同时维护同一文件，修改者负责重新整理。

## 9. 手机和其他设备只读查看

1. 打开“连接与分享 → 浏览分享”。
2. 确认分享的库名和范围，点击“启动浏览分享”。
3. 让设备连接可信局域网，打开实际地址或扫码。
4. 输入页面显示的访问码。
5. 使用完点击“停止浏览分享”。

访问者可以浏览和下载已授权内容，不能编辑、上传或删除。只在可信局域网使用。切到其他知识库不会自动更换已经分享的库；更换范围请先停止并重新开启。

无法访问时，先检查服务是否运行、设备是否同网、地址是否为局域网地址，再检查主机网络和防火墙规则。不要通过关闭全部防火墙解决问题。

## 10. 使用 MCP 接入外部 AI

这是可选的高级方式。不熟悉时先使用手动复制。

打开 AI 工具，选择实际支持的连接方式。HTTP 默认只允许本机访问、只读。复制应用生成的客户端配置和令牌到目标 AI 客户端；具体配置格式以该客户端和应用实际适配为准。

只读连接可以读取资料、搜索和获取任务指令，不能把整理结果写回。需要写知识时，由你显式开启写入并使用写令牌；权限仅限允许的 wiki/ 文件，不允许改原始资料、规则或删除文件。重启应用后恢复只读，需再次授权。

stdio 由外部客户端启动独立本机进程，本版按只读方式配置；退出桌面不保证结束该进程。配置中的授权库或路径改变后，要在外部客户端重启连接。

打开 MCP 不会自动发任务。可以在外部客户端发起，也可以配置支持 MCP 的本机启动器后由“开始整理”发起；结束后都需核对并确认待整理项。

## 11. 访问码、令牌和路径有什么区别

| 名称 | 用在哪里 | 使用说明 |
|---|---|---|
| 浏览访问码 | 浏览器只读页面 | 交给需要查看内容的人，更换后旧访问失效 |
| MCP 只读令牌 | 外部 AI HTTP 客户端 | 允许读取授权库，不允许写入 |
| MCP 写令牌 | 外部 AI HTTP 客户端 | 仅显式授权后使用，不贴进普通文档或日志 |
| 本机/共享路径 | 外部工具直接读文件 | 由操作系统控制权限，不受 MCP 只读开关限制 |

## 12. 常见问题

| 问题 | 处理方式 |
|---|---|
| 上传后知识没变 | 上传只是准备资料，需到整理页交给外部 AI 执行 |
| 为什么仍有待整理 | 可能未确认处理，或生成任务后资料又变了；核对后只确认对应项 |
| Word/Excel 无法预览 | 源文件仍按原格式保存，使用“打开原文件”；预览能力不影响文件保存 |
| AI 读不了 Word/Excel | 更换有对应读取能力的外部工具或已适配的 MCP 读取工具；该项保持待整理 |
| 不能上传 PDF | 当前支持列表尚未包含 PDF；保持源格式与支持所有格式是两回事 |
| 保存失败 | 草稿保留，检查目录权限/网络后重试；有外部改动时先处理冲突 |
| 切换路径后资料不见了 | 新路径不会搬迁旧文件，检查根目录是否选对 |
| AI 找不到文件 | 在能访问该路径的设备执行，或使用正确授权的 MCP 连接 |
| MCP 能读取但无法整理写回 | 当前可能只读；检查权限，或改用本机文件直读方式 |
| 修改目标后旧知识不变 | 规则影响后续整理，需要主动再次整理相应资料 |
| 删除资料后知识仍存在 | 这是保留的旧结果，需生成引用清理计划并核对执行 |
| 如何备份 | 关闭写入和外部编辑后备份完整知识库目录；令牌不通过普通文档备份 |

## 13. 数据目录速查

```text
wikis/知识库名称/
├─ purpose.md       目标与边界
├─ schema.md        组织规则
├─ .changes.json    待整理记录，由应用维护
├─ .llmwiki/        扫描、任务、人工核对与记录修复状态，由应用维护
├─ raw/
│  ├─ sources/      按源格式保存的资料，如 md/txt/docx/xlsx
│  └─ assets/       已有资源文件
└─ wiki/            整理出的知识及日志
```

不要手工清空 .changes.json 来表示 AI 已完成。知识内容通常是 Markdown，资料保持各自源格式；备份需要包含完整目录；源资料移入回收站可以恢复；删除整个知识库仍是永久删除，包含回收站，不等同从列表隐藏。

## 14. 中途退出、部分完成与结果检查

生成操作指令后，本次范围和版本会保存在库内。关闭并重开应用，可在整理页“未完成任务”继续查看和核对；“已复制”不会变成“已完成”。生成前未保存的输入、意外崩溃前未保存的文档草稿不保证恢复，正常关闭仍会提示保存。

AI 只完成一部分时，只确认完成的项目。读取失败或未完整读取的项目保留；如你用其他工具已经完整处理，可选择“我已在其他方式完成”并填写说明。原资料后来又改了，对应项继续待整理，其他未变的项目仍可确认。

“本次结果”展示任务准备以来的文件变化，不能证明它们全部来自 AI，也不提供历史正文回滚。你可以确认“已核对，无需修改”，但要填写理由；系统不会仅凭知识文件没变化就判断失败。

程序关闭期间修改过 Word/Excel，再启动或刷新也会检测变化。扫描失败时不会把资料误判为已删除。首次接入现有库且缺少检测基线，会提示历史处理状态待核对。

## 15. 保存与修复提示

“文件已保存，变更记录未完成”说明文件已经在磁盘上，只是待整理或日志登记需要修复。点击“重试登记”，不要重复上传覆盖。应用重启后会继续核实修复；网络断开导致结果不确定时先恢复连接再检查。

手动修订知识会记录人工版本保护，后续整理需核对人工内容。通过 MCP 覆盖受保护文件会被拦截，你可在桌面检查后解除当前版本保护；直接访问文件的外部程序仍拥有操作系统授予的权限。

## 16. 恢复误删资料

资料页更多菜单打开“回收站”，选中文件点击恢复。原路径有同名文件时另存新名称，不会直接覆盖。恢复后是否需要重新整理由删除任务与当前版本决定；已执行过引用清理时，恢复源文件仍需重新整理知识。

回收站不自动按时间清空。可查看占用、导出需要保留的文件，再手动永久删除或清空；这一步不能恢复。回收站不对网页和 MCP 开放，也不是独立备份。覆盖上传的旧版本会以“覆盖前版本”保留在回收站。

## 17. 配置本机 AI 工具并直接开始

打开“连接与分享 → AI 工具 → 本机执行工具”，选择实际支持的适配器和程序路径，检查版本、登录状态与读取能力。需要登录时到外部工具完成，本应用不保存模型账号密码或 API Key。

验证通过且任务能力匹配后，整理页主按钮变为“开始整理”；问题分析显示“开始分析”，质量检查显示“开始检查”。点击后应用启动外部工具，展示真实状态；外部工具结束后点击“查看本次变化”，逐项核对并确认。没有可用适配器时仍可复制完整指令。

执行中可取消，但已产生的文件修改不会自动撤销。关闭应用先取消并核实任务结束；意外重启看到“中断待核实”时先检查进程和结果，不重复启动。10 分钟未收到进展只会提醒，不代表失败，也不会默认杀进程。

MCP 与启动器可以搭配：启动器负责开始执行，MCP 负责受控读写；本机文件访问则受操作系统权限约束。工具程序退出成功也不代表全部资料已经正确整理。

## 18. 导出任务包给另一环境

整理页“更多 → 导出任务包”，默认只包含说明与文件清单，不包含资料。需要原资料时显式勾选，导出前核对范围；保持源格式，不带令牌、回收站或应用配置。

接收方按自己的路径执行，结果不会自动同步回本机。回填知识后仍需在原库核对；本版不自动导入外部任务包覆盖文件。导出、复制、进程结束都不会自动清除待整理项。

# 09｜分阶段实施与验收清单

## 1. 阶段 0：核实基线

不改业务代码，先完成实际界面截图、路由/VM/服务映射、可复用组件、配置字段和依赖版本清单。运行当前构建与核心流程，记录已存在的问题。

重点核实 MCP HTTP/stdio 权限、服务生命周期、分享范围、原格式存储和读取能力、单文件 20 MiB 与传输封装开销适配、变更合并结构、版本校验与原子清除能力。输出“与 V2 设计差异表”，每项标为已支持、仅 UI 迁移、需服务改造。

## 2. 阶段 1：导航与文档工作区

建立新导航、库切换器、中文文案、统一未保存保护；迁移资料和知识，复用既有编辑器与服务。此阶段不改分享权限和文件结构。

交付无库、资料正常/空/失败、Office 预览、文本编辑/保存失败、知识目录、深浅主题截图。检查 1440×900、1180×760、1100×650 和系统缩放下的核心操作。

## 3. 阶段 2：整理中心

先实现第 11 章的扫描基线、持久任务和可恢复操作，再实现三类任务、统一指令预览、结果核对与逐项确认。原变更接口不满足竞态保护前，不开放新确认按钮。验证七类生成器输出仍符合既有业务语义。

## 4. 阶段 3：设置与连接

拆库设置和应用设置，补路径切换事务。完成第 13 章至少一个真实 Agent 适配与开始、取消、重启核实、复制兜底、导出流程，不能只做启动按钮。浏览分享与 MCP 分页签，生命周期、单库授权、写权限和凭据失效独立交付。客户端配置必须在实际目标客户端验证。

## 5. 阶段 4：帮助、迁移与发布

将 08 转为应用内帮助，更新实际截图、版本、安装与启动方式。旧路由重定向、新导航和权限变化写入发布说明。验证旧库、旧配置和升级后第一次启动，列出未完成项。

# 10｜数据与服务契约

> 本章是新版独立实施所需的数据、文件与服务规则。新版设计包为唯一设计基准，无须另行查阅历史设计。本文描述目标契约；已有程序的实际 JSON 结构、接口签名与依赖版本须在阶段 0 从源码核实，不能由实施者猜测后覆盖用户数据。

## 1. 产品与技术边界

Windows 桌面应用，C#、.NET 10、WPF、WPF-UI 4.3.0、MVVM。桌面全 WPF，不引入 WebView2，不依赖 Node 服务；浏览分享使用独立网页，不等同桌面渲染层。具体依赖锁定为项目可验证版本，不因本次设计升级框架。

不内置模型、聊天、模型 API Key、无人值守 Agent、云同步、数据库、知识图谱或多端协同编辑；第 13 章的用户主动外部进程调用纳入本版。外部 AI 通过文件访问或 MCP 运行，应用不能单凭复制或文件时间戳判断任务完成。

## 2. 知识库目录契约

```text
<知识库根目录>/<库名>/
├─ purpose.md
├─ schema.md
├─ .changes.json
├─ .llmwiki/             隐藏 JSON 状态：扫描、任务与修复记录
├─ raw/
│  ├─ sources/           保持源格式的资料：md/txt/docx/xlsx
│  └─ assets/            资源文件
└─ wiki/
   ├─ index.md
   ├─ overview.md
   ├─ log.md
   ├─ entities/
   ├─ concepts/
   ├─ sources/
   ├─ queries/
   ├─ synthesis/
   └─ comparisons/
```

根目录可配置，默认用系统解析的当前用户 Documents/LLM Wiki/wikis。支持本机盘符与 UNC；安装目录不作为数据目录。相对路径解析必须使用稳定的配置基准，不依赖进程偶然的工作目录；UI 展示解析后的绝对路径。

库标识为合法目录名，新建校验中文、英文、数字、下划线、中划线及 Windows 保留名等限制。校验服务统一处理，不靠前端正则保障路径安全。已有库识别规则由阶段 0 核实并兼容，不能把任意子目录自动初始化为库。

新上传不创建 raw/original；已有 raw/original 只作兼容读取，不自动迁移或删除。不批量重写用户规则或默认文件。新建四种场景模板只影响默认目标和规则，不改变目录。默认目标包含目标、关键问题、范围与边界；默认规则包含分类、来源与互链约定。

## 3. 源格式保存与内容读取

**上传即保存原文件：保留扩展名、文件内容和原始字节，不转 Markdown、不重编码、不生成资料副本。** 文件系统创建时间等元信息不承诺与上传前完全一致，内容一致性用原字节 SHA256 校验。

| 类型 | 入库目标 | 阅读和修改 |
|---|---|---|
| md、txt | raw/sources/原文件名 | 文本预览；用户显式编辑保存才修改内容 |
| docx | raw/sources/原文件名.docx | 支持时预览，否则打开关联程序；外部工具按原格式读取 |
| xlsx | raw/sources/原文件名.xlsx | 支持时预览，否则打开关联程序；外部工具按原格式读取 |
| PDF、doc、xls、其他类型 | 当前未纳入支持列表 | 如需支持，独立规定校验、打开、读取与安全边界，不以转 Markdown 作为前提 |

例如报告.docx直接保存为 raw/sources/报告.docx，不创建报告.docx.md。引用写 `[来源: 报告.docx]`，变更身份与文件指纹都针对该源文件。

存储、预览、AI 读取、编辑是四项独立能力。没有预览器不能阻止原格式存储，也不能声称 AI 必然能读取所有上传类型。Word/Excel 不进入纯文本编辑框；通过系统关联程序编辑并在刷新/文件监测时检测原字节变化。

临时内容提取可以用于预览或 MCP 响应，但只在读取时执行，不写成知识库 Markdown 文件、不成为新的事实来源，不偷偷替代原件。提取结果标明原文件、页/表/段定位、覆盖范围、截断与错误。无法读取、加密、缺少工具或不支持某种格式时明确失败，待整理项保留。Excel 公式无缓存值时不能编造计算结果，复杂图形或结构未读取时不能声称已完整处理。

文本上传不转码；预览可按现有能力识别 UTF-8/BOM 与中文编码。用户主动编辑保存时使用明确的编码策略，必要时说明编码变化；无法正确解码时不允许用乱码覆盖文件。

单文件上限固定为 20 MiB（20,971,520 字节），多选按文件提交，传输封装开销另计；底层按第 11 章适配，停止含糊的整批/单文件双口径。保存先完整暂存、验证再提交，同名覆盖失败保留原有效文件，不生成半文件。添加、下载、导出的文件内容需与保存的源字节一致，普通删除仅将明确选中的源文件移入 .llmwiki/trash/，成功后仍可恢复；不直接永久删除，见第 12 章。

历史 raw/original 和历史 .docx.md/.xlsx.md 不自动删除或移动。不能把独立人工 Markdown 凭后缀当成可丢弃的衍生物；可靠映射与待整理记录兼容规则见 07。

## 4. 文件读写权限

| 角色 | 可读 | 可写 |
|---|---|---|
| 资料工作区 | 原格式资料、可用预览与文件元数据 | 支持的 md/txt 原位编辑；二进制源文件用外部程序修改 |
| 知识工作区 | wiki 内容 | 默认只读；高级修订只允许授权文本 |
| 规则编辑器 | purpose.md、schema.md | 仅当前明确目标文件 |
| 日志服务 | wiki/log.md | 追加，禁止任意覆盖 |
| 浏览分享 | 当前授权库公开的资料、知识、原件 | 无 |
| MCP 只读 | 授权库白名单内容和受控变更查询 | 无 |
| MCP 写入 | 同上 | 仅允许的 wiki/ 文本，禁止日志和删除 |

所有操作接收稳定库身份与相对路径，不只传文件名。拒绝绝对路径、盘符、UNC、控制字符、.. 路径段及越界结果；验证规范化根目录边界，拒绝跟随符号链接/junction。库根目录本身允许配置 UNC，但库内文件参数不能用 UNC 绕过校验。

目录默认隐藏点号系统文件和 node_modules。隐藏不是授权机制，API 仍须拒绝直接读取内部状态文件；变更查询仅通过专门服务返回必要字段。

## 5. 变更与日志

.changes.json 是已有待整理数据，不重新定义一套 JSON 格式。阶段 0 记录真实字段、动作合并规则、排序和清除语义，为本版整理中心提供兼容适配。无 hash 的已有记录也必须可读，不通过重写文件强制升级。

逻辑上需要库身份、相对路径、动作、时间和可比较版本；新增/修改的内容计算 SHA256，包括 Office 在内均使用原文件字节。删除使用稳定变更版本并检查文件是否重现。不得假设时间戳单独足以唯一标识变更。

同内容重存不要在 UI 伪造已完成；是否去重按现有服务规则兼容。新增/修改/删除组合的最终语义必须由业务服务统一决定，不能在列表中自行合并后回写。

源资料写入、添加、删除与规则保存追加日志；一次上传只记录该原格式文件的添加或替换，不记录不存在的转换动作。日志行保留可读的时间、动作与相对路径；记录发生在对应动作提交成功之后，不写虚假的成功事实。Wiki 人工修订和 MCP 写入写操作日志，但不冒充源资料变更。

文件提交成功但变更/日志登记失败时，使用 .llmwiki/operations/ 凭据幂等补记，提示“文件已保存，变更记录未完成”，不要求用户重复上传。完整恢复顺序见第 11 章。

确认处理在服务级临界区比较任务快照和当前记录，仅移除匹配项。与后续新增、修改并发时，新记录不能被整文件覆盖掉。外部工具可能改 .changes.json，因此本机线程锁不足以防跨进程覆盖；需结合文件级协调和读取后版本比较，失败时刷新重试。共享文件夹不承诺完整协同编辑或分布式锁。

## 6. 外部任务的共同约束

七类能力共用任务定义：boundary、batch_ingest、incremental_ingest、query、lint、compare、clean。UI 中文入口见 03，保留协议标识，避免客户端配置无故失效。

任务共同携带：库身份、访问方式、允许范围、输入资料、来源标记、知识输出目录与必要限制。文件直读方式给真实可访问绝对路径；MCP 方式给逻辑库标识和工具，不要求远端访问本机盘符。

资料路径归一化防 raw/sources/ 重复前缀；任务直接指向原格式文件，引用源文件原名。知识采用 frontmatter `sources: []` 与 `[[页面名]]` 互链约定；具体引用内容以真实资料为准，不虚构来源。

更新任务区分新增、修改和删除，删除文件不再尝试读取。清理先列出受影响摘要、索引、链接与共享实体，获得外部执行所需确认后处理；共享实体只移除该来源相关内容，不能整页删除。MCP 无删除工具时明确要求到本机完成真正文件删除。

本版规定任务语义，不声称具备可逐字复用的历史模板全文。实际模板从现有程序提取，按本章与 03 校验后使用同一生成器，禁止每个页面另写一套。

## 7. MCP 能力契约

服务默认关闭，HTTP 默认本机回环、只读，绑定明确单库；stdio 首轮只读且由客户端独立管理。浏览分享与 MCP 即使复用宿主也独立授权、独立生命周期。

| 工具 | 参数要点 | 结果与限制 |
|---|---|---|
| list_knowledge_bases | 无 | 仅授权库，不泄露本机路径 |
| list_tree | kb、relative_dir 可选 | 受控目录条目与相对路径 |
| read_file | kb、relative_path、version/cursor（续读） | 内容、原字节版本、totalBytes、nextCursor、complete；内部文件另行拒绝 |
| read_source_content | kb、relative_path、version/cursor、可选工作表/行区间 | 源版本、临时内容、定位、覆盖范围、nextCursor、complete，不落盘 |
| search_content | kb、query、limit | 仅 wiki/ 和 raw/sources 文本；默认 20，最大 50，每片段不超过 200 字符 |
| get_pending_changes | kb | 路径、动作、时间，不提供清除操作 |
| write_wiki_file | kb、relative_path、content、expected_version 或 expectedAbsent | 仅显式 HTTP 写授权可用，版本条件校验后提交 |

read_file 继续只返回文本，不把 docx/xlsx 二进制强制解码成字符串。read_source_content 为需适配的原格式读取工具，实施后按真实格式能力列表展示；没有适配前标明不可用，不以现有 read_file 冒充支持。search_content 当前仅搜索文本文件，不能暗示已覆盖 Office 正文。浏览下载原格式文件时校验相同库范围与凭据。

Resources 用 `wiki://{kb}/purpose.md`、`wiki://{kb}/schema.md`、`wiki://{kb}/index`、`wiki://{kb}/{relative_path}` 等逻辑 URI，和工具共用授权。Prompts 提供上述七类能力；question/topic 等必填字段校验错误明确返回。

读取采用第 11 章版本化分段协议，每次最多返回 64 KiB UTF-8 内容，带后续游标和完整标记；不是自动按截断内容完成任务。MCP 文本写入上限本版定为 4 MiB UTF-8，超限拒绝，不拆成可能损坏文档的多次覆盖；编辑器和预览能力据实际配置另行说明。路径参数设长度限制，默认 260 字符；如产品支持长路径应整体调整校验与说明，而非部分端点暗中放开。

HTTP 所有请求校验 Bearer 令牌，写权限独立令牌，随机令牌不少于 32 字节，受保护存储，不写普通日志。Origin 仅允许缺省的原生客户端请求或明确白名单来源。令牌轮换和范围切换使会话失效，不仅更换显示文本。

写入原子替换，提交前重查授权与版本；已有文件版本取读取返回的 version，新文件要求 expectedAbsent=true，二者互斥。人工修订保护命中返回 MANUAL_REVIEW_REQUIRED，不能绕过后直接覆盖。错误至少区分 KB_NOT_FOUND、PATH_NOT_ALLOWED、READ_ONLY_MODE、VERSION_REQUIRED、VERSION_CONFLICT、FILE_TOO_LARGE、FORMAT_NOT_SUPPORTED、SOURCE_READ_FAILED、SERVICE_UNAVAILABLE。错误不得泄露密钥、正文或其他库内容。

stdio stdout 只输出协议消息，日志走 stderr/文件。HTTP 和 stdio 复用业务校验，不各自拼路径。客户端配置按实际可执行文件、端点和目标客户端生成并实测，不提供未经核实的通用 JSON。

## 8. 配置与外部访问

应用配置保留 wikisDir 语义，主题与导航偏好独立管理，写配置保留未知字段。规则保存在库内 Markdown，不复制到另一套表单数据源。权限与令牌不当作普通布局偏好；本版 HTTP 写授权在应用重启后恢复只读。

浏览分享默认关闭，实际端口由系统分配或用户指定，运行时返回实际地址。4 位 PIN 是可信局域网轻量门槛；所有页面、API、下载均受控，无上传、编辑、删除、配置写入、工作流执行路由。退出桌面停止其宿主服务，独立 stdio 不能错误宣称已退出。

共享目录权限由 Windows 管理，不新增账号体系或云同步。根目录不可达时不自动切回本地，不建同名空库。删库永久删除，输入库名确认，目录不可访问或服务不能停止时拒绝。

## 9. 规范优先级

本版分章文档是唯一规范；完整版由分章生成，不单独手改。00 定义产品决策，01—06 定义交互，07 定义改造映射，08 为用户说明，09 为验收，本章定义数据与服务契约，11 定义跨重启状态与失败恢复，12 定义自包含任务、单次确认与回收恢复，13 定义本机执行和导出，14 定义控件与实现映射，15 汇总最终决策和文档检查结果。相互冲突时先修正文档，不要求实施者回查已删除的历史资料。概念图仅供布局参考，示例日期、文本、按钮状态不覆盖文字规范。

# 11｜闭环补全与状态恢复规范

> 本章补全外部文件变化、跨重启任务、结果检查、逐项确认、规则更新和失败恢复。本章与 01—10 的相应入口配套实施，不增加主导航、数据库或内置 AI。2026-10-30。

## 1. 本版已定范围

资料保存、预览、AI 读取与编辑分别声明能力。当前资料类型 md/txt/docx/xlsx，上传保持原格式和字节；PDF 等尚不支持，不要求用户改成 Markdown。单文件最大 **20 MiB（20,971,520 字节）**，多选按文件逐项提交，不把整批大小当作单文件限制；协议封装开销另计。底层若只有旧请求体限制，按文件拆分/调整传输适配后再上线这一口径。

列表可显示“可预览 / 外部程序打开 / 读取工具待配置”等说明，上传成功不能推导为可在任意 AI 中完整读取。

## 2. 本地状态文件与生命周期

在每库隐藏目录 `.llmwiki/` 下保存可读 JSON，不引入数据库，不修改 `.changes.json` 的已有格式。路径校验统一禁止普通文档 API、浏览分享、MCP 直接访问这些内部文件。

| 文件 | 用途 |
|---|---|
| manifest.json | 最近一次完整扫描的源文件路径、大小、时间、SHA256；扫描代次与规则版本 |
| tasks/{任务ID}.json | 本次任务范围、源文件/变更快照、规则版本、知识文件基线、逐项确认状态 |
| operations/{操作ID}.json | 待提交/已提交的文件动作与变更、日志补记进度；作为可恢复操作凭据 |
| trash/{条目ID}/ | 源资料回收文件、覆盖前版本和恢复元信息；不自动永久清理 |
| reviews.json | 规则更新提醒的确认/暂时忽略版本，手动修订知识的路径与版本 |

各文件含 schemaVersion，先临时写入再原子替换。未知字段保留；不认识的未来版本只读报错，不以空对象覆盖。损坏状态隔离为损坏文件并提示重建可推导部分；任务已确认与未确认状态不能凭猜测恢复。

任务只保存路径、哈希、时间、范围、任务参数和状态，不复制源文件或知识正文，不保存令牌、PIN、外部 AI 对话。指令用冻结输入与模板版本生成；模板版本不可用时显示“无法恢复原指令”，允许查看摘要并生成新任务，不伪造旧指令。

已确认/已放弃任务保留最近 50 条且最多 30 天，超出后清理；未结束任务不自动清理。放弃任务仅关闭记录，不清除待整理项。删除库时隐藏状态一并删除，备份完整库时一并包含；应用退出不删除。任务详情放在整理页“未完成任务 / 最近任务”折叠区，不新增任务中心导航。

## 3. 文件变化发现

启动、进入资料页、手动刷新、确认任务前执行扫描；文件监测只触发去抖扫描，不能作为唯一依据。生成任务前也检查相关源文件与规则，避免复制已过期范围。

扫描 raw/sources/ 及可靠识别的历史源位置。排除 `~$` Office 锁文件、应用临时文件、隐藏状态目录和不支持类型；过滤规则固定并可查。遍历失败、共享断开、读取被锁、权限失败时标记“扫描不完整”，不能把未读到的文件判为删除，不能替换上次完整清单。

变化最终以原字节哈希判断：时间或大小改变是快速筛选线索；启动、用户刷新和确认前须校验相关文件内容，不能漏掉同大小/同时间的更改。读取前后比较元信息，变化中重试；仍不稳定显示“文件正在保存”，暂不提交该项快照。

对完整可读范围比较：新路径是新增、已有路径哈希变化是修改、完整扫描确定消失才是删除。路径改名默认作为“旧路径删除 + 新路径新增”，不猜测重命名；大小写和 Windows 名称规范由文件服务统一处理。

检测结果通过同一变更服务写入，保留原去重规则；扫描完成不等于已整理。先可靠登记变化，再推进 manifest 基线。首次接入没有 manifest 的存量库时保留已有变更，建立扫描基线，并显示“历史处理状态未核对”，提供“核对现有资料”；不自动宣称全部已整理，也不一口气覆盖原待整理记录。

操作日志不因多次扫描重复追加。由应用完成的操作通过操作ID去重；外部发现的变化以路径、前后哈希、动作和扫描代次去重。已确认版本不因相同扫描重复回到待整理。

## 4. 跨重启任务与失效规则

复制指令或开始本机执行前持久化任务快照；写入失败不提供假成功的生成状态。任务冻结库绑定、范围、所选变更身份、源哈希、purpose/schema 哈希、模板版本及知识文件路径/哈希基线。快照不是文件内容副本，外部执行时仍要核对当前版本。

状态为“已准备 / 已复制待外部执行 / 待核对 / 部分确认 / 已确认 / 已放弃”。资料发生变化是逐项附加标记，不把整任务直接覆盖成未知状态。重启进入整理页显示“有未完成任务，继续核对”，恢复选择与已确认进度；绝不恢复成外部执行成功。本机进程的准备/运行/取消/结束状态另由第 13 章 attempt 管理，不能混为任务已确认。

| 变化 | 原任务处理 |
|---|---|
| 新增不在本次范围的资料 | 原所选任务仍有效，页头提醒另有变更；全部资料任务提示范围增加，重新复制需生成新任务 |
| 本次某资料内容变化或删除 | 该项失效，不再按原版本确认；其他未变化项仍可核对 |
| 已删除资料重新出现 | 删除项失效，不能继续按旧清理计划确认 |
| purpose/schema 或模板规则变化 | 原指令不再允许当作当前指令复制；已完成的旧任务可核对，但新规则提醒仍保留 |
| 切换库 | 只切换视图，保留任务绑定；返回原库继续，不对新库复用旧指令 |
| 根目录变化 | 不按同名库自动匹配任务；新位置通过已有状态和用户核对确认身份 |

不允许旧任务反复生成后覆盖原快照。重新生成创建新任务，保留被替代任务的摘要与确认进度。任务指令要求读取前检查源版本，变化时停止该项并报告；本机文件直读无法强制限制外部程序，UI 如实说明。

## 5. 本次变化与结果核对

“查看本次变化”先打开整理页内的“本次结果核对”面板，另有“打开知识页”。对比任务开始时的 wiki/ 文件清单与当前清单，显示新增、修改、删除及无变化；wiki/log.md 单独列为操作日志，不算知识产出。

每项展示相对路径、变化类型、当前文件打开入口和来源关联。已删除文件因未备份正文，仅能显示删除事实，不能提供虚假的旧内容预览；本版提供文件级变化，不承诺逐行 Diff 或历史回滚。

面板固定说明“以下为任务准备以来检测到的变化，可能包含其他程序的修改，不代表均由本次 AI 产生”。多任务时间重叠提示“变化范围可能重叠”。无法解析来源时不猜测哪项资料已完成。

资料级核对表列：源文件、原动作、执行报告（未提供/已读取/读取失败/读取不完整）、知识变化关联、用户确认状态。外部 AI 的报告是辅助信息，不是应用自动验证；无报告也可由用户人工核对，不能伪造“AI 已处理”。

## 6. 逐项确认与规则更新

确认表默认不勾选。未生成任务但在外部已完成的情况，先建立标注“用户补充确认”的当前版本快照，并要求用户核对这些正是已处理版本；不伪装成恢复了历史执行快照。用户选中确已完成的资料或删除项，点击“确认完成这 {n} 项”后仅清除快照仍匹配的记录；普通确认不再追加确认弹窗。未读取、失败、未完成分段读取的项目默认不能确认；用户若在另一工具已完整处理，可选择“我已在其他方式完成”，在行内填写说明，再使用同一面板的提交按钮一次确认，系统重新比较当前源版本，不额外弹窗。

每项结果独立为“已确认 / 有新变化保留 / 未完成保留 / 记录冲突待刷新”。无变更文件也可能无需改知识，允许“已核对，无需修改”并记录用户理由；不能强制每项都产生 Wiki 修改。单项确认不能清除新增的无关项。

确认保存使用可恢复操作凭据：先保存确认意图，再比较版本并更新变更文件，最后标记任务该项已确认。中断恢复时核实变更与凭据状态，幂等完成或保守保留，不仅凭任务里的勾选删记录。

purpose/schema 变化独立显示“规则已更新，已有知识尚未按新规则核对”。“稍后处理”只折叠当前版本提醒，保存 ignoredVersion，不等于完成。全部资料任务按当前规则逐项确认完毕后，用户仍需显式“确认已按新规则核对现有知识”；才推进已确认规则版本。也可人工完成全库核对后独立确认。部分任务不自动消除此提醒。

## 7. 文本编辑与手动知识修订

| 状态 | 保存按钮与行为 |
|---|---|
| 预览 | 显示“编辑”，没有可提交草稿 |
| 编辑但内容未变化 | 保存禁用，显示“未修改”；Ctrl+S 不写盘、不制造变更 |
| 已修改 | 保存启用；取消、切换、关闭执行统一保护 |
| 保存中 | 禁止重复保存、目标切换和覆盖动作；等待保存结果后再执行离开意图 |
| 成功 | 更新原始缓冲与版本，继续留在编辑模式，显示“已保存”；可点“完成编辑”返回预览 |
| 失败 | 留在编辑，保留草稿和原始版本，重试或另存；不提示再次上传同一文件 |
| 外部版本冲突 | 不覆盖，提供磁盘版本、另存、返回编辑；另存生成独立资料且需合法命名 |

本版正常退出靠离开保护；意外崩溃的未保存编辑草稿不保证恢复，帮助必须说明。持久任务记录只恢复任务，不等同恢复文档草稿。Word/Excel 的外部编辑保存由对应程序负责，桌面无法替它确认未保存内容。

手动修订知识成功后在 reviews.json 记录路径和新哈希。后续整理任务标出“含手动修订内容”，默认要求 AI 保留人工内容；确需覆盖时先列出拟修改项让用户在外部确认。MCP 写入命中受保护手工版本时返回 MANUAL_REVIEW_REQUIRED，不直接覆盖；用户可在桌面明确解除该文件当前版本的保护。外部文件直读只能通过任务约定提醒，不承诺技术上拦截 Agent。

## 8. 知识空状态

新建 index/overview 的模板不视为已生成知识。创建时记录模板内容哈希，或与可验证模板版本比较；仍全部为初始骨架且没有其他知识页时显示“还没有整理出的知识”。用户编辑过首页或新增知识页则展示实际内容，但不据此声称 AI 已执行成功。

存量库无法识别模板时保守展示内容，不因猜测清空文件。来源解析失败不影响阅读。index/overview 缺失仍按 02 的降级入口处理。

## 9. 文件成功、记录失败与崩溃恢复

源文件、变更 JSON 与日志无法当作一个跨文件原子事务。应用操作先写 operations 凭据（目标、动作、前后哈希、临时文件标识），再提交源文件，随后补变更与日志，最后标记操作完成。日志内部或关联元数据用操作ID去重，不破坏可读日志格式。

源文件已提交但记录失败时显示“文件已保存，变更记录未完成”，提供“重试登记 / 查看文件”，不显示整体失败并要求用户重传。登记失败项进入持久修复队列；继续生成该项整理任务前先修复或明确阻止，不允许安静漏项。

启动按凭据与磁盘哈希恢复：未提交的临时文件可清理；已提交动作补记；目标后来又变化则保留最新变化并提示冲突，不能用旧凭据回滚新文件。删除凭据保存目标曾存在与动作版本，不因“文件现在不存在”就重复制造删除记录。

共享目录断开时凭据可能暂时无法写入，应在源提交前拒绝新动作；提交后断线的未知结果先显示“结果待核实”，重连检查后恢复。文件扫描可以补源变化，但不能凭当前文件恢复完整历史日志，缺失时明确说明。多程序写同库仍应遵守单维护者约定，不能宣称拥有跨设备完整事务。

## 10. MCP 分段读取与版本闭合

read_file 返回 content、version（原字节 SHA256）、totalBytes、nextCursor 与 complete。read_source_content 返回原文件 sourceVersion、内容片段、页/段/工作表定位、覆盖范围、nextCursor、complete、warnings；首请求固定版本，后续请求带 version/cursor，源文件变化返回 VERSION_CONFLICT，不能混读两个版本。

工具支持按 cursor 继续读取；Excel 可提供工作表列表与按表/行区间读取。读取上限为每响应最多 64 KiB UTF-8 内容，单次受限不等于处理完成；结构定位元数据和必要封装另计，遇到单字段超限也必须分段或明确报错。读取超时、权限、加密和格式错误分别返回，不能以空内容表示成功。

write_wiki_file 的 expected_version 取读取返回的 version；新建文件传显式 expectedAbsent=true，与 expected_version 互斥。完整更新不得只凭截断预览生成内容。MCP 的成功读取/写入不自动确认任务；可在带任务上下文时记录观察到的覆盖信息，缺少上下文或客户端走文件直读时由用户核对。

## 11. 实施依赖顺序

先完成状态存储与恢复、扫描登记、任务快照和逐项确认，再开放结果核对与版本化 MCP 分段读取；最后更新帮助与视觉。状态文件损坏、重启、断网、部分完成、规则变化、人工修订覆盖和记录失败均须有验收用例。

# 12｜快捷整理、AI 工具与可恢复删除

> 本章规定新版默认交互：接入上下文自动随任务携带、复制一次完成任务准备、结果勾选后一次确认、资料删除先入库内回收站。与 01—11 配套实施，取代其中需要先单独复制边界说明、重复确认处理、直接永久删除资料的流程。

## 1. AI 工具不再是日常前置步骤

用户需要告诉 AI “处理哪个库、能做什么、这次做什么”，不必理解或单独操作“边界说明”。保留 boundary 协议能力和高级查看入口，取消首次必须先去连接页复制说明的要求。

**无已配置工具时的路径：资料页选择文件 → 整理页 → 复制整理指令 → 外部 AI 执行 → 返回核对；有已验证本机工具时点击“开始整理”，见第 13 章。**

整理页保留三类任务。更新知识范围默认待整理；从资料页进入则继承所选资料。无已验证本机工具时默认手动复制；有适配且能力匹配时默认本机执行，记住用户明确选择，但当前库的 MCP 不可用时明确回退提示，不能静默向其他库派任务。

```text
整理 / 更新知识                              当前库：产品研究
范围：所选资料（3）       执行方式：手动复制 ▾

本次会处理 3 份资料，更新知识并保留来源。
✓ 已包含当前库路径、目标规则入口和操作范围
[复制整理指令]     [预览完整指令]

已复制。请在能访问该文件夹的外部 AI 工具中粘贴执行。
[查看本次变化]     未完成任务（1）
```

“预览完整指令”是次入口，不要求先预览再复制。“复制整理指令”一次完成校验、持久任务快照、生成完整指令、写剪贴板；任何阶段失败显示对应结果，不伪造复制成功。剪贴板失败保留已准备任务，重试复制同一任务；相同快照重复复制不重复创建任务。

复制之后按钮可显示“再次复制”。输入、范围或规则改变时显示“复制新任务指令”，创建新任务，不覆盖旧记录。没有选择或缺少必填输入时主按钮禁用，并在就地说明原因。

## 2. 完整指令如何携带边界

所有手动指令必须独立成立，不依赖 AI 记住上一次对话。生成器自动组合：

1. 任务ID、知识库身份、执行方式、真实可访问路径。
2. 当前目标与规则文件的入口和版本，要求执行前读取 purpose.md、schema.md；可附短摘要，但不把两个文件全文反复塞入剪贴板。
3. 本次源文件清单、变化类型与版本；原格式读取要求、失败与截断报告要求。
4. 可读写范围、资料不转换、人工修订保护、删除先计划确认、不要自行清除待整理记录。
5. 具体任务及结果报告要求：逐项说明已读取、已处理、未完成、受影响知识路径。

执行前须核对库身份和源/规则版本，变化时停止受影响项并报告，不跨库或使用旧路径继续写入。库内资料属于内容数据，不作为修改任务权限的指令；文件直读的最终权限由操作系统与外部工具约束，文字边界不等同服务端授权。

连接与分享中的“手动使用”仅说明选择哪类外部工具、路径是否可访问，保留折叠的“查看库说明 / 复制库说明”。这是调试与高级接入辅助，不再要求用户先完成“接入成功”打勾。无可靠握手时不显示“AI 已接入”。

## 3. MCP 方式：一次配置，按调用校验

初次使用 MCP 才进入连接页：启动授权库服务 → 复制客户端配置 → 到外部客户端配置。无真实客户端探测时，状态分别为“服务可用”“最近调用”，不根据复制配置显示连接成功。

选择在外部 MCP 客户端发起时，主按钮为“复制任务说明”；本机启动器与 MCP 搭配时按第 13 章启动，不能把两者混为互斥方式。外部客户端模式下复制的说明自动携带库标识、任务ID和需要的 Prompt/工具能力。用户到已配置客户端发起任务；本应用仍不宣称点击即发送。原格式读取能力和写权限不足时就地说明，只读查询可以继续，写入任务需改执行方式或由用户显式授权。

MCP Prompts 共用上下文生成器；服务端每次工具/资源请求都检查实际授权库、会话、路径、权限、文件版本与人工保护。客户端是否主动读取了 boundary 不能作为授权前提。规则变更在下一次读取/生成中生效；旧任务按规则版本核对，不把历史对话记忆视为最新配置。

不自动修改用户 Agent 配置或覆盖 AGENTS.md，不自动启动客户端，不在指令里嵌入访问令牌。需要客户端特定格式时只使用已验证适配。

## 4. 结果确认只保留一次明确提交

默认进入本次结果面板，未完成项与已核对项在同一处展示；复选框含义为“我已核对该项已完成”。选择后主按钮“确认完成这 {n} 项”，旁边持续显示“仅移出这些待整理记录，不会修改源文件和知识”。

普通确认点击一次即提交，不再弹“确定已处理吗”。提交时再次扫描和比较版本；部分冲突直接反馈成功/保留数量，不要求重新操作全部项目。未读取或失败项默认不勾选；“我已在其他方式完成”“无需修改”在当前行展开理由输入，再统一点击同一个确认按钮，不增加第二个确认弹窗。

没有原任务时可在当前面板建立“用户补充确认”快照，含义与第 11 章一致，不冒充历史执行证据。操作失败保留选择并可重试；提交中防重复。误确认的任务详情提供“重新列为待整理”，只登记当前版本需要核对，不回滚文件，也不覆盖已有更新的变更记录。

危险操作仍单独确认：不可恢复的清空回收站、永久删库、覆盖冲突、提升写权限。普通复制、普通保存、可恢复移入回收站、结果确认不叠加确认框。

## 5. 源资料删除进入库内回收站

范围为本应用管理的源资料，不新增 Wiki 删除工具。资料页菜单“移入回收站”；成功提示“已移入回收站，可恢复”，提供“撤销”。批量操作显示所选数量和隐藏选择数量，不默认勾选筛选外文件。未保存草稿先处理，保存失败/用户取消就不执行删除。

每库 `.llmwiki/trash/{条目ID}/` 保存原字节文件及元信息，包含原相对路径、文件名、大小、哈希、删除时间、原因、关联操作/变更版本。覆盖同名文件时，先保存旧版本并标为“覆盖前版本”，再提交新文件；不能可靠保留旧版本则拒绝覆盖，不能先破坏原文件。

回收站入口在资料页更多菜单，不增加主导航。列表可按名称筛选，展示原位置、移除时间、原因与大小，操作“恢复 / 导出 / 永久删除”。本地盘和 UNC 使用同一应用级回收站，不依赖系统回收站是否支持网络路径。

移动前写操作凭据，确认内容已安全保存在回收站后才移除源路径。移动/空间/权限失败时保留源文件并提示失败，不自动降级永久删除；中途崩溃由操作ID与两端哈希核实，不把仅有元数据的条目显示为可恢复。已完成移动但变更登记失败按第 11 章补记。

回收文件不参与资料统计、搜索、扫描、整理、MCP 或浏览分享；所有网络文件入口拒绝访问隐藏回收目录。回收站内部存在文件不影响源文件已删除的判断。回收站不是备份，磁盘损坏或整库永久删除会同时失去它。

不自动按时间永久清理，保留到用户手动清理；显示占用大小，空间不足引导手动导出/清理，不能自行删除最早文件。永久删除/清空需一次明确危险确认，列出数量与大小；无二次嵌套弹窗。确认失败逐项显示，不误报全部成功。

## 6. 恢复与待整理记录的关系

恢复前验证条目完整性与目标路径。原路径空闲则恢复原位；同名文件已存在默认提供“另存名称”，不覆盖；取消不改动任一文件。成功后记录恢复操作并刷新资料，外部 AI 不需要访问回收站。

| 场景 | 待整理处理 |
|---|---|
| 删除后尚未生成/复制相关清理任务，也未确认删除项；恢复同路径同哈希 | 仅在可靠关联到本次删除且变更版本仍匹配时撤销该删除标记；恢复删除前仍待整理的状态 |
| 已复制清理指令，或可能在外部执行，或删除项已确认 | 原删除任务标为范围已变化；恢复源文件登记新增/待重新核对，提示知识引用可能已被清理 |
| 恢复内容不同或另存新名称 | 按真实路径与内容登记新增/修改，不自动清除无关删除项 |
| 记录来源不明、后来又变化、历史原件映射不可靠 | 保守保留变更，提示刷新核对，不凭同名删记录 |

“撤销”也是同一恢复流程，不能绕过后来发生的同名冲突或清理任务。恢复资料不自动恢复已修改或删除的知识；知识仍需重新整理。误确认的“重新列为待整理”与源文件回收恢复是不同操作。

## 7. 整库删除的边界

本版源资料删除可恢复，整库删除仍为危险区的永久操作，需要输入库名并停止绑定服务；说明将包含资料、知识、隐藏任务状态和回收站。整库回收不在本轮范围，不得在帮助中笼统承诺所有删除都能恢复。真正永久删除的资料或整库，应用不能恢复，需用户自备备份。

本章的复制线框表示无已配置本机工具时的兜底状态，不覆盖第 13 章有工具时“开始整理”的主按钮规则。

## 8. 实施顺序

先复用现有生成器完成上下文自动组合和单按钮复制，再把结果确认合并到一个面板；回收站的凭据、移动、恢复、冲突和变更协调服务完成后，替换原直接删除入口。读写权限、源格式保存和逐项版本比较继续保持，不因减负取消业务校验。

# 13｜本机 Agent 执行与任务导出

> 最终设计范围：应用可以由用户主动启动已配置的外部 Agent，并管理本次执行；不内置模型、模型 API Key 或聊天，不新增无人值守定时整理。具体 Agent 兼容性须通过适配验收，不能因本机安装了可执行文件就宣称支持。

## 1. 区分执行入口与资料访问

| 层次 | 解决的问题 | 选项 |
|---|---|---|
| 执行入口 | 谁让外部 AI 开始任务 | 本机启动器、复制指令、导出任务包 |
| 资料访问 | AI 如何读取和写回本库 | 文件直接访问、MCP 受控访问 |

MCP 不再作为与启动器互斥的第四种执行引擎。一个本机启动器可以配合文件访问，也可配合 MCP；外部客户端同样可以读取复制的任务说明后使用 MCP。浏览分享只是只读浏览，不作为 Agent 执行入口。

## 2. 页面与默认入口

“连接与分享”保留两个页签：**浏览分享 / AI 工具**。AI 工具内分“本机执行工具”“MCP 连接”“手动使用说明”，不新增主导航。此处是统一配置入口，应用设置不再重复提供 AI 工具配置。

整理页默认按钮由实际能力决定：

| 条件 | 主按钮 | 次入口 |
|---|---|---|
| 已配置且已验证、当前任务能力匹配的本机工具 | 开始整理（分析任务为“开始分析”，检查任务为“开始检查”） | 复制整理指令、预览指令、高级导出 |
| 未配置工具或工具当前不可用 | 复制整理指令 | 配置本机工具、预览指令、高级导出 |
| 用户明确选择在外部 MCP 客户端发起 | 复制任务说明 | 查看 MCP 连接配置；不显示本应用“已发送” |

主按钮按任务名称显示，但统一执行机制。不可用原因就地解释，例如未登录、格式读取能力不匹配、只读连接无法写知识。不能悄悄改用另一工具、提升权限或切换库。用户始终可选复制方式完成任务。

```text
整理 / 更新知识                         产品研究
范围：所选资料（3）   使用：已配置的本机工具 ▾
访问：MCP · 本库知识写入已授权
本次上下文、目标规则和任务范围已包含
[开始整理]   [复制整理指令]   [预览]   [更多 ▾]

启动后：运行中 · 正在等待工具响应        [取消任务]
输出（可折叠，标注来自外部工具）

结束后：外部程序已结束，请核对结果       [查看本次变化]
```

不在每次运行前再弹普通“确定执行吗”。页面持续展示工具、库、范围与权限，点击主按钮表示启动该任务。首次启用有写能力的配置，或访问/权限发生提升时，明确确认一次相应授权；不绕过外部工具自己的审批。

## 3. 首次配置本机工具

1. 选择已实现适配的工具类型及实际可执行文件。不能把任意自定义 shell 文本当默认支持入口。
2. 验证路径、工具版本和非交互调用能力；检测不得读写用户知识库。
3. 展示身份状态：已登录、需在外部登录、无法检测。登录在工具自己的安全界面完成，本应用不索要外部账号密码或存储模型 API Key。
4. 检查适配能力：能否传入任务、指定工作目录、原格式读取、结构化事件、取消、MCP、写入审批。无法可靠探测的标为“未验证”，不伪造支持。
5. 验证通过后保存执行配置：工具类型、路径、已验证版本、结构化参数、访问方式、超时策略与能力。只保存适配配置，不保存令牌到普通 JSON。

工具版本变化、可执行文件更换或能力检查过期，运行前重验关键能力。首版至少完成一个实际适配的端到端验收才启用“开始整理”；未适配工具仍可使用复制指令。文档不预置未经验证的厂商命令、安装路径或登录命令。

## 4. 启动过程与上下文

启动前检查库可访问、源和规则快照、任务输入、读取能力、写权限、人工修订保护；复用第 11、12 章的持久任务与上下文生成器。用户点击主按钮后先持久化任务和本次 attempt，再启动进程，避免进程已运行却没有可恢复记录。

固定任务工作目录与库绑定，使用适配器的可执行文件和参数数组，不拼接 shell 命令。不把资料名称、问题、主题或模型输出作为命令执行；任务通过适配器支持的 stdin 或受控任务文件传递，避免命令行长度和转义问题。临时任务文件属于隐藏状态，不成为源资料。

每次指令包含本次库/任务身份、路径或逻辑资源、规则入口与版本、源清单、允许动作、原格式读取与结果报告要求。复制、启动器、MCP Prompt 共用任务定义，区别只在传输适配。

文件访问模式：Agent 使用其操作系统权限，应用不能技术保证它只写 wiki/。首次启用说明此区别，不自动传入跳过审批或扩大权限的启动参数。MCP 模式：通过用户授权的会话读取原格式与写知识，令牌不写进指令、输出或普通任务记录；服务端逐次校验实际范围。

## 5. 执行状态与展示

| 执行状态 | 判断依据 | 用户操作 |
|---|---|---|
| 准备中 | 本应用校验、保存任务与 attempt | 防重复启动 |
| 启动失败 | 进程未成功启动 | 查看原因、修复配置、重试 |
| 运行中 | 已启动且仍运行，或适配器确认活动 | 查看输出、取消 |
| 等待外部审批 | 工具明确提供该事件 | 去工具审批；否则只显示等待响应 |
| 正在取消 | 已向本次进程发出取消 | 等待，防重复取消 |
| 已取消 | 进程已确认停止 | 核对可能产生的部分修改 |
| 异常结束 | 非零退出或可靠错误事件 | 查看错误、核对部分结果、重试剩余 |
| 程序已结束，待核对 | 零退出/可靠结束事件 | 查看变化、逐项确认 |
| 中断待核实 | 应用退出/崩溃后无法可靠确认进程状态 | 核实进程与磁盘，不自动重启 |

零退出不等于知识正确或全部资料处理完成；不自动清除待整理项。阶段、已读文件数和进度仅从真实事件显示，没有真实百分比就不用进度百分比。stdout/stderr 原样内容作为不可信文本呈现，禁用脚本/终端控制序列；默认界面不输出密钥或全文日志。运行输出默认会话保留，用户主动导出时提示内容可能包含资料信息。

执行状态与第 11 章任务核对状态分开存储：进程结束后任务仍可部分确认。任务摘要记录 attemptID、已启动时间、终止原因、退出信息与确认进度，不把模型输出当自动完成凭据。

## 6. 取消、超时、重启与并发

首版本应用同时只管理一个正在执行的本机任务，不增加后台排队。第二个启动被就地阻止，提供返回当前任务；多个复制/外部客户端任务可以存在，但结果面板仍提示变化可能重叠，版本与人工保护保持生效。

取消先请求当前适配器终止，5 秒未结束再提供“强制结束本次进程”。只操作本次启动并可靠归属的进程及子进程，不结束用户其他窗口或共享守护进程。适配器无法可靠取消时不得标记“已取消”；明确提示去外部工具停止并核实。

10 分钟无可观察事件时提醒“暂未收到进展”，不是超时失败；允许继续等待或取消。默认不因静默自动杀进程。工具自身超时策略须展示并保存，不把网络断开等同已停止执行。

运行中可以切页或切库阅读，任务仍固定原库，状态栏提供返回。禁止删除该库、更换全局根目录及修改本次所选源文件；外部程序仍可能修改，结束和确认前必须比较版本。用户关闭应用时提供“留在应用 / 取消任务后退出”，不默认脱离应用后台运行。仍有文档草稿先统一处理，不叠放对话框。

异常重启后仅凭 PID 不认领进程，需验证可执行文件、启动时间和 attempt 归属。确认无法执行后再允许新任务；不自动恢复运行，不复用失效凭据。重试创建关联的新 attempt/任务，重新扫描、选择剩余项与当前版本，不对整批盲目重跑；取消和失败不自动回滚已经落盘的知识。

## 7. 导出任务包

位于整理页“更多 → 导出任务包”，不与日常主操作同级。默认只导出任务说明和 manifest：标明不包含资料。可显式选择“包含本次源资料与规则文件”，按原字节打包，不转 Markdown；导出前列出范围、大小和可能敏感内容。

包内包含任务说明、版本清单、所选源文件（如用户勾选）及 purpose/schema 副本。排除 .changes.json、.llmwiki 状态/回收站、令牌、PIN、应用配置与未选资料。导出包路径用库内相对路径，接收方指定自己的执行根目录，不沿用发送机器绝对路径。

导出不修改本地知识，不清除待整理，不证明任务已执行。接收方的改动不会自动同步回来；首版不实现自动导入并覆盖知识，用户需在原库核对并通过明确写入流程回填，之后逐项确认。导出任务标记为外部执行，记录原始快照；源资料随后变化时不能按旧版本盲目确认。

## 8. 最终范围与落地要求

基础能力保留复制指令；增加用户主动的本机 Agent 调用、取消、异常结果管理；MCP 继续可选，保持网络默认关闭与只读。没有已验证适配器时，“开始整理”不可用并解释原因，不能用打开一个空终端冒充任务派发成功。

未纳入：内置模型/聊天、自动登录外部账号、无人值守定时执行、跨机器自动同步、运行中自动回滚、任意命令脚本配置和复杂多任务调度。实现验收必须使用真实兼容工具，不以静态 UI 或模拟输出替代。

## 4. 文档工作区与状态绑定

DocumentWorkspace 输入明确的库身份、相对路径、文档角色和允许动作；不只靠扩展名决定可写。编辑缓冲、原内容和文件版本独立管理，不在页面 View 里直接写文件。

工具栏提供文件名、路径、状态、编辑/保存/完成编辑；CanSave 由 Dirty、权限、版本和 Busy 综合决定。预览/编辑切换复用同区域，禁止为主要编辑任务弹小窗口。Office 原格式文件的编辑动作是打开关联程序，不假装应用内保存。

内容区独立滚动；左右栏宽度允许拖动。大列表使用现有虚拟化方案，避免外层 ScrollViewer 破坏虚拟化。高亮和文件加载异步执行；查询结果与当前上下文版本不匹配则丢弃。

## 5. 本机 Agent 输出与交互限制

AgentRunPanel 用只读文本/虚拟化行列表展示适配器事件，不嵌入终端模拟器，不执行 ANSI/脚本，不新增聊天输入框。UI 默认保留最近 5,000 行且最多 1 MiB 展示文本，任一上限达到就丢弃最早显示内容并标注“较早输出已省略”；任务状态和确认记录不能随显示截断而丢失。

没有真实事件时显示“运行中，等待外部工具响应”，不虚构正在读哪个文件。需要外部审批时只有适配器明确报告才显示对应入口。工具选择与程序路径属于结构化配置，不提供任意脚本编辑框。

运行中、等待取消、待核对、异常结束都在页面持久呈现，Snackbar 只报告短结果。取消、登录、提升授权、退出运行中应用的交互按第 13 章，不用 MessageBox 堆叠。

## 6. 系统能力不伪装成 WPF-UI 控件

- 文件多选、导出、目录选择、程序路径选择使用系统选择器或已有项目封装，复用明确路径校验。
- 原格式文件打开通过系统关联程序；缺少关联时提示选择程序或导出，不能影响文件已保存状态。
- Markdown、Word、Excel 解析不由 WPF-UI 负责，按数据/读取服务实现；不增加转换落盘。
- QR 码、剪贴板、进程管理、凭据保护、文件监测、哈希和回收站都是服务职责，控件只绑定状态与命令。
- 不引入 Office 嵌入控件/COM 自动化作为默认预览前提；缺少现有预览时使用原格式信息卡。
