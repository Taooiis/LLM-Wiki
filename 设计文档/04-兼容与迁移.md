# 04 · 兼容与迁移

## 1. 数据兼容（核心承诺）

**同一个 `wikis` 目录，Demo 与新版交替使用都成立。**

- 目录骨架、文件名、默认文案与 Demo 逐字一致（唯一新增 `raw/original/` 不影响老库读取）。
- .changes.json 结构不变，两个客户端可以继续维护同一份变更清单。
- `config.json` 只有一项 `wikisDir`：新版也用这个键语义（可放在应用自己的配置文件里，存储格式继承 `{ "wikisDir": "..." }`），首次启动可自动从 Demo 的 config 导入一次。
- 旧库不含 office 副本的场景：纯文本流，两种客户端行为完全一致，不需要迁移工具。

## 2. Agent 侧零改动（AGENTS.md 与 prompts）

demo 里的约定文本（`AGENTS.md`、`prompts/*.md`）逐字沿用，本次**只允许最小的文案增量**，全部围绕 office 副本：

1. `AGENTS.md` 目录树注释更新一处：`raw/sources/` 描述从"只收 .md/.txt"改为"入库副本：.md/.txt（Word/Excel 上传时自动转换，原件在 raw/original/）"。
2. `prompts/context.md`（边界说明说明文）同类句子同步一改。
3. **引用规则不改**：`[来源: 文件名]` 中的"文件名"仍写原文件名（如 `调研报告.docx`），生成提示词与边界说明的模板需要向 Agent 交代清楚"sources 里的 .docx.md 对应原文件 .docx"，避免 Agent 引用副本文件名正确性（此项在 Ingest 模板加一句说明）。
4. 除以上三点外不改任何提示词文本，保证存量用户训练出来的习惯与外部 Agent 的既有理解不被破坏。

## 2c. 本节目标的落点

- Obsidian 打开 `wikis/<库名>/` 须得到完整可读的 wiki（[[wikilink]] 可跳转），这是数据层的隐性验收标准之一；`raw/original/` 不影响（Obsidian 只见文件，不认原件也无害）。

## 3. 首次启动体验（升级路径）

1. 新版首启动时探查 Demo 目录（默认 `Documents\LLM Wiki Demo`）：
   - 找到 `config.json` → 迁移 `wikisDir` 为默认值。
   - 找不到 → 默认仍指向 `Documents\LLM Wiki\wikis`（新建即认为全新使用，允许空白库）。
2. 首次建 office 文件库时自动补 `raw/original/`，其余骨架不动。
3. 不提供"把 Demo 里旧 office 外部文件批量转换"功能（外链由用户自行上传），避免隐式写用户数据。
4. **默认存储路径（本设计决定）**：与安装目录解耦，默认落在当前用户 `Documents\LLM Wiki\wikis`；`wikisDir` 键语义与 Demo `config.json` 一致，故同名机制可互导（见第 1 条）。
