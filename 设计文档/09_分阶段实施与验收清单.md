# 09｜分阶段实施与验收清单

## 1. 阶段 0：核实基线

不改业务代码，先完成实际界面截图、路由/VM/服务映射、可复用组件、配置字段和依赖版本清单。运行当前构建与核心流程，记录已存在的问题。

重点核实 MCP HTTP/stdio 权限、服务生命周期、分享范围、原格式存储和读取能力、单文件 20 MiB 与传输封装开销适配、变更合并结构、版本校验与原子清除能力。输出“与 V2 设计差异表”，每项标为已支持、仅 UI 迁移、需服务改造。

## 2. 阶段 1：导航与文档工作区

建立新导航、库切换器、中文文案、统一未保存保护；迁移资料和知识，复用既有编辑器与服务。此阶段不改分享权限和文件结构。

交付无库、资料正常/空/失败、Office 预览、文本编辑/保存失败、知识目录、深浅主题截图。检查 1440×900、1180×760、1100×650 和系统缩放下的核心操作。

## 3. 阶段 2：整理中心

先实现第 11 章的扫描基线、持久任务和可恢复操作，再实现三类任务、统一指令预览、结果核对与逐项确认。原变更接口不满足竞态保护前，不开放新确认按钮。验证七类生成器输出仍符合既有业务语义。

## 4. 阶段 3：设置与连接

拆库设置和应用设置，补路径切换事务。完成第 13 章至少一个真实 Agent 适配与开始、取消、重启核实、复制兜底、导出流程，不能只做启动按钮。浏览分享与 MCP 分页签，生命周期、单库授权、写权限和凭据失效独立交付。客户端配置必须在实际目标客户端验证。

## 5. 阶段 4：帮助、迁移与发布

将 08 转为应用内帮助，更新实际截图、版本、安装与启动方式。旧路由重定向、新导航和权限变化写入发布说明。验证旧库、旧配置和升级后第一次启动，列出未完成项。

## 7. 验证边界

自动化重点：路径与权限、原字节存储与覆盖失败恢复、扫描基线、持久任务、可恢复补记、比较后确认、并发新增记录、版本冲突、配置切换失败恢复。复用既有测试，不为静态文案编写重复实现的测试。

人工检查：文件选择、Office 预览、剪贴板、快捷键、未保存保护、主题布局、手机浏览、目标 MCP 客户端连接。本机工具适配、WPF-UI 控件映射与真实客户端连接也必须端到端验证。每阶段执行仓库要求的 dotnet build 和相关测试，不能在只有设计资料的目录报告构建成功。

## 8. 任务走查

请未看过旧页面的人执行：创建并整理三份资料；修改一份后只处理该项；删除一份并找到清理入口；给手机只读查看；切根目录但不搬数据。记录求助点、错误路径和误操作。

成功标准：不必理解 Ingest/Lint/Clean 就能找到中文任务，没有误清新变更、误写文件或意外换分享范围。不用虚构的效率百分比评价。
