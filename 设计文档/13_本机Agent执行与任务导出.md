# 13｜本机 Agent 执行与任务导出

> 最终设计范围：应用可以由用户主动启动已配置的外部 Agent，并管理本次执行；不内置模型、模型 API Key 或聊天，不新增无人值守定时整理。具体 Agent 兼容性须通过适配验收，不能因本机安装了可执行文件就宣称支持。

## 1. 区分执行入口与资料访问

| 层次 | 解决的问题 | 选项 |
|---|---|---|
| 执行入口 | 谁让外部 AI 开始任务 | 本机启动器、复制指令、导出任务包 |
| 资料访问 | AI 如何读取和写回本库 | 文件直接访问、MCP 受控访问 |

MCP 不再作为与启动器互斥的第四种执行引擎。一个本机启动器可以配合文件访问，也可配合 MCP；外部客户端同样可以读取复制的任务说明后使用 MCP。浏览分享只是只读浏览，不作为 Agent 执行入口。

## 2. 页面与默认入口

“连接与分享”保留两个页签：**浏览分享 / AI 工具**。AI 工具内分“本机执行工具”“MCP 连接”“手动使用说明”，不新增主导航。此处是统一配置入口，应用设置不再重复提供 AI 工具配置。

整理页默认按钮由实际能力决定：

| 条件 | 主按钮 | 次入口 |
|---|---|---|
| 已配置且已验证、当前任务能力匹配的本机工具 | 开始整理（分析任务为“开始分析”，检查任务为“开始检查”） | 复制整理指令、预览指令、高级导出 |
| 未配置工具或工具当前不可用 | 复制整理指令 | 配置本机工具、预览指令、高级导出 |
| 用户明确选择在外部 MCP 客户端发起 | 复制任务说明 | 查看 MCP 连接配置；不显示本应用“已发送” |

主按钮按任务名称显示，但统一执行机制。不可用原因就地解释，例如未登录、格式读取能力不匹配、只读连接无法写知识。不能悄悄改用另一工具、提升权限或切换库。用户始终可选复制方式完成任务。

```text
整理 / 更新知识                         产品研究
范围：所选资料（3）   使用：已配置的本机工具 ▾
访问：MCP · 本库知识写入已授权
本次上下文、目标规则和任务范围已包含
[开始整理]   [复制整理指令]   [预览]   [更多 ▾]

启动后：运行中 · 正在等待工具响应        [取消任务]
输出（可折叠，标注来自外部工具）

结束后：外部程序已结束，请核对结果       [查看本次变化]
```

不在每次运行前再弹普通“确定执行吗”。页面持续展示工具、库、范围与权限，点击主按钮表示启动该任务。首次启用有写能力的配置，或访问/权限发生提升时，明确确认一次相应授权；不绕过外部工具自己的审批。

## 3. 首次配置本机工具

1. 选择已实现适配的工具类型及实际可执行文件。不能把任意自定义 shell 文本当默认支持入口。
2. 验证路径、工具版本和非交互调用能力；检测不得读写用户知识库。
3. 展示身份状态：已登录、需在外部登录、无法检测。登录在工具自己的安全界面完成，本应用不索要外部账号密码或存储模型 API Key。
4. 检查适配能力：能否传入任务、指定工作目录、原格式读取、结构化事件、取消、MCP、写入审批。无法可靠探测的标为“未验证”，不伪造支持。
5. 验证通过后保存执行配置：工具类型、路径、已验证版本、结构化参数、访问方式、超时策略与能力。只保存适配配置，不保存令牌到普通 JSON。

工具版本变化、可执行文件更换或能力检查过期，运行前重验关键能力。首版至少完成一个实际适配的端到端验收才启用“开始整理”；未适配工具仍可使用复制指令。文档不预置未经验证的厂商命令、安装路径或登录命令。

## 4. 启动过程与上下文

启动前检查库可访问、源和规则快照、任务输入、读取能力、写权限、人工修订保护；复用第 11、12 章的持久任务与上下文生成器。用户点击主按钮后先持久化任务和本次 attempt，再启动进程，避免进程已运行却没有可恢复记录。

固定任务工作目录与库绑定，使用适配器的可执行文件和参数数组，不拼接 shell 命令。不把资料名称、问题、主题或模型输出作为命令执行；任务通过适配器支持的 stdin 或受控任务文件传递，避免命令行长度和转义问题。临时任务文件属于隐藏状态，不成为源资料。

每次指令包含本次库/任务身份、路径或逻辑资源、规则入口与版本、源清单、允许动作、原格式读取与结果报告要求。复制、启动器、MCP Prompt 共用任务定义，区别只在传输适配。

文件访问模式：Agent 使用其操作系统权限，应用不能技术保证它只写 wiki/。首次启用说明此区别，不自动传入跳过审批或扩大权限的启动参数。MCP 模式：通过用户授权的会话读取原格式与写知识，令牌不写进指令、输出或普通任务记录；服务端逐次校验实际范围。

## 5. 执行状态与展示

| 执行状态 | 判断依据 | 用户操作 |
|---|---|---|
| 准备中 | 本应用校验、保存任务与 attempt | 防重复启动 |
| 启动失败 | 进程未成功启动 | 查看原因、修复配置、重试 |
| 运行中 | 已启动且仍运行，或适配器确认活动 | 查看输出、取消 |
| 等待外部审批 | 工具明确提供该事件 | 去工具审批；否则只显示等待响应 |
| 正在取消 | 已向本次进程发出取消 | 等待，防重复取消 |
| 已取消 | 进程已确认停止 | 核对可能产生的部分修改 |
| 异常结束 | 非零退出或可靠错误事件 | 查看错误、核对部分结果、重试剩余 |
| 程序已结束，待核对 | 零退出/可靠结束事件 | 查看变化、逐项确认 |
| 中断待核实 | 应用退出/崩溃后无法可靠确认进程状态 | 核实进程与磁盘，不自动重启 |

零退出不等于知识正确或全部资料处理完成；不自动清除待整理项。阶段、已读文件数和进度仅从真实事件显示，没有真实百分比就不用进度百分比。stdout/stderr 原样内容作为不可信文本呈现，禁用脚本/终端控制序列；默认界面不输出密钥或全文日志。运行输出默认会话保留，用户主动导出时提示内容可能包含资料信息。

执行状态与第 11 章任务核对状态分开存储：进程结束后任务仍可部分确认。任务摘要记录 attemptID、已启动时间、终止原因、退出信息与确认进度，不把模型输出当自动完成凭据。

## 6. 取消、超时、重启与并发

首版本应用同时只管理一个正在执行的本机任务，不增加后台排队。第二个启动被就地阻止，提供返回当前任务；多个复制/外部客户端任务可以存在，但结果面板仍提示变化可能重叠，版本与人工保护保持生效。

取消先请求当前适配器终止，5 秒未结束再提供“强制结束本次进程”。只操作本次启动并可靠归属的进程及子进程，不结束用户其他窗口或共享守护进程。适配器无法可靠取消时不得标记“已取消”；明确提示去外部工具停止并核实。

10 分钟无可观察事件时提醒“暂未收到进展”，不是超时失败；允许继续等待或取消。默认不因静默自动杀进程。工具自身超时策略须展示并保存，不把网络断开等同已停止执行。

运行中可以切页或切库阅读，任务仍固定原库，状态栏提供返回。禁止删除该库、更换全局根目录及修改本次所选源文件；外部程序仍可能修改，结束和确认前必须比较版本。用户关闭应用时提供“留在应用 / 取消任务后退出”，不默认脱离应用后台运行。仍有文档草稿先统一处理，不叠放对话框。

异常重启后仅凭 PID 不认领进程，需验证可执行文件、启动时间和 attempt 归属。确认无法执行后再允许新任务；不自动恢复运行，不复用失效凭据。重试创建关联的新 attempt/任务，重新扫描、选择剩余项与当前版本，不对整批盲目重跑；取消和失败不自动回滚已经落盘的知识。

## 7. 导出任务包

位于整理页“更多 → 导出任务包”，不与日常主操作同级。默认只导出任务说明和 manifest：标明不包含资料。可显式选择“包含本次源资料与规则文件”，按原字节打包，不转 Markdown；导出前列出范围、大小和可能敏感内容。

包内包含任务说明、版本清单、所选源文件（如用户勾选）及 purpose/schema 副本。排除 .changes.json、.llmwiki 状态/回收站、令牌、PIN、应用配置与未选资料。导出包路径用库内相对路径，接收方指定自己的执行根目录，不沿用发送机器绝对路径。

导出不修改本地知识，不清除待整理，不证明任务已执行。接收方的改动不会自动同步回来；首版不实现自动导入并覆盖知识，用户需在原库核对并通过明确写入流程回填，之后逐项确认。导出任务标记为外部执行，记录原始快照；源资料随后变化时不能按旧版本盲目确认。

## 8. 最终范围与落地要求

基础能力保留复制指令；增加用户主动的本机 Agent 调用、取消、异常结果管理；MCP 继续可选，保持网络默认关闭与只读。没有已验证适配器时，“开始整理”不可用并解释原因，不能用打开一个空终端冒充任务派发成功。

未纳入：内置模型/聊天、自动登录外部账号、无人值守定时执行、跨机器自动同步、运行中自动回滚、任意命令脚本配置和复杂多任务调度。实现验收必须使用真实兼容工具，不以静态 UI 或模拟输出替代。
