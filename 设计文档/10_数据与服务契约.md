# 10｜数据与服务契约

> 本章是新版独立实施所需的数据、文件与服务规则。新版设计包为唯一设计基准，无须另行查阅历史设计。本文描述目标契约；已有程序的实际 JSON 结构、接口签名与依赖版本须在阶段 0 从源码核实，不能由实施者猜测后覆盖用户数据。

## 1. 产品与技术边界

Windows 桌面应用，C#、.NET 10、WPF、WPF-UI 4.3.0、MVVM。桌面全 WPF，不引入 WebView2，不依赖 Node 服务；浏览分享使用独立网页，不等同桌面渲染层。具体依赖锁定为项目可验证版本，不因本次设计升级框架。

不内置模型、聊天、模型 API Key、无人值守 Agent、云同步、数据库、知识图谱或多端协同编辑；第 13 章的用户主动外部进程调用纳入本版。外部 AI 通过文件访问或 MCP 运行，应用不能单凭复制或文件时间戳判断任务完成。

## 2. 知识库目录契约

```text
<知识库根目录>/<库名>/
├─ purpose.md
├─ schema.md
├─ .changes.json
├─ .llmwiki/             隐藏 JSON 状态：扫描、任务与修复记录
├─ raw/
│  ├─ sources/           保持源格式的资料：md/txt/docx/xlsx
│  └─ assets/            资源文件
└─ wiki/
   ├─ index.md
   ├─ overview.md
   ├─ log.md
   ├─ entities/
   ├─ concepts/
   ├─ sources/
   ├─ queries/
   ├─ synthesis/
   └─ comparisons/
```

根目录可配置，默认用系统解析的当前用户 Documents/LLM Wiki/wikis。支持本机盘符与 UNC；安装目录不作为数据目录。相对路径解析必须使用稳定的配置基准，不依赖进程偶然的工作目录；UI 展示解析后的绝对路径。

库标识为合法目录名，新建校验中文、英文、数字、下划线、中划线及 Windows 保留名等限制。校验服务统一处理，不靠前端正则保障路径安全。已有库识别规则由阶段 0 核实并兼容，不能把任意子目录自动初始化为库。

新上传不创建 raw/original；已有 raw/original 只作兼容读取，不自动迁移或删除。不批量重写用户规则或默认文件。新建四种场景模板只影响默认目标和规则，不改变目录。默认目标包含目标、关键问题、范围与边界；默认规则包含分类、来源与互链约定。

## 3. 源格式保存与内容读取

**上传即保存原文件：保留扩展名、文件内容和原始字节，不转 Markdown、不重编码、不生成资料副本。** 文件系统创建时间等元信息不承诺与上传前完全一致，内容一致性用原字节 SHA256 校验。

| 类型 | 入库目标 | 阅读和修改 |
|---|---|---|
| md、txt | raw/sources/原文件名 | 文本预览；用户显式编辑保存才修改内容 |
| docx | raw/sources/原文件名.docx | 支持时预览，否则打开关联程序；外部工具按原格式读取 |
| xlsx | raw/sources/原文件名.xlsx | 支持时预览，否则打开关联程序；外部工具按原格式读取 |
| PDF、doc、xls、其他类型 | 当前未纳入支持列表 | 如需支持，独立规定校验、打开、读取与安全边界，不以转 Markdown 作为前提 |

例如报告.docx直接保存为 raw/sources/报告.docx，不创建报告.docx.md。引用写 `[来源: 报告.docx]`，变更身份与文件指纹都针对该源文件。

存储、预览、AI 读取、编辑是四项独立能力。没有预览器不能阻止原格式存储，也不能声称 AI 必然能读取所有上传类型。Word/Excel 不进入纯文本编辑框；通过系统关联程序编辑并在刷新/文件监测时检测原字节变化。

临时内容提取可以用于预览或 MCP 响应，但只在读取时执行，不写成知识库 Markdown 文件、不成为新的事实来源，不偷偷替代原件。提取结果标明原文件、页/表/段定位、覆盖范围、截断与错误。无法读取、加密、缺少工具或不支持某种格式时明确失败，待整理项保留。Excel 公式无缓存值时不能编造计算结果，复杂图形或结构未读取时不能声称已完整处理。

文本上传不转码；预览可按现有能力识别 UTF-8/BOM 与中文编码。用户主动编辑保存时使用明确的编码策略，必要时说明编码变化；无法正确解码时不允许用乱码覆盖文件。

单文件上限固定为 20 MiB（20,971,520 字节），多选按文件提交，传输封装开销另计；底层按第 11 章适配，停止含糊的整批/单文件双口径。保存先完整暂存、验证再提交，同名覆盖失败保留原有效文件，不生成半文件。添加、下载、导出的文件内容需与保存的源字节一致，普通删除仅将明确选中的源文件移入 .llmwiki/trash/，成功后仍可恢复；不直接永久删除，见第 12 章。

历史 raw/original 和历史 .docx.md/.xlsx.md 不自动删除或移动。不能把独立人工 Markdown 凭后缀当成可丢弃的衍生物；可靠映射与待整理记录兼容规则见 07。

## 4. 文件读写权限

| 角色 | 可读 | 可写 |
|---|---|---|
| 资料工作区 | 原格式资料、可用预览与文件元数据 | 支持的 md/txt 原位编辑；二进制源文件用外部程序修改 |
| 知识工作区 | wiki 内容 | 默认只读；高级修订只允许授权文本 |
| 规则编辑器 | purpose.md、schema.md | 仅当前明确目标文件 |
| 日志服务 | wiki/log.md | 追加，禁止任意覆盖 |
| 浏览分享 | 当前授权库公开的资料、知识、原件 | 无 |
| MCP 只读 | 授权库白名单内容和受控变更查询 | 无 |
| MCP 写入 | 同上 | 仅允许的 wiki/ 文本，禁止日志和删除 |

所有操作接收稳定库身份与相对路径，不只传文件名。拒绝绝对路径、盘符、UNC、控制字符、.. 路径段及越界结果；验证规范化根目录边界，拒绝跟随符号链接/junction。库根目录本身允许配置 UNC，但库内文件参数不能用 UNC 绕过校验。

目录默认隐藏点号系统文件和 node_modules。隐藏不是授权机制，API 仍须拒绝直接读取内部状态文件；变更查询仅通过专门服务返回必要字段。

## 5. 变更与日志

.changes.json 是已有待整理数据，不重新定义一套 JSON 格式。阶段 0 记录真实字段、动作合并规则、排序和清除语义，为本版整理中心提供兼容适配。无 hash 的已有记录也必须可读，不通过重写文件强制升级。

逻辑上需要库身份、相对路径、动作、时间和可比较版本；新增/修改的内容计算 SHA256，包括 Office 在内均使用原文件字节。删除使用稳定变更版本并检查文件是否重现。不得假设时间戳单独足以唯一标识变更。

同内容重存不要在 UI 伪造已完成；是否去重按现有服务规则兼容。新增/修改/删除组合的最终语义必须由业务服务统一决定，不能在列表中自行合并后回写。

源资料写入、添加、删除与规则保存追加日志；一次上传只记录该原格式文件的添加或替换，不记录不存在的转换动作。日志行保留可读的时间、动作与相对路径；记录发生在对应动作提交成功之后，不写虚假的成功事实。Wiki 人工修订和 MCP 写入写操作日志，但不冒充源资料变更。

文件提交成功但变更/日志登记失败时，使用 .llmwiki/operations/ 凭据幂等补记，提示“文件已保存，变更记录未完成”，不要求用户重复上传。完整恢复顺序见第 11 章。

确认处理在服务级临界区比较任务快照和当前记录，仅移除匹配项。与后续新增、修改并发时，新记录不能被整文件覆盖掉。外部工具可能改 .changes.json，因此本机线程锁不足以防跨进程覆盖；需结合文件级协调和读取后版本比较，失败时刷新重试。共享文件夹不承诺完整协同编辑或分布式锁。

## 6. 外部任务的共同约束

七类能力共用任务定义：boundary、batch_ingest、incremental_ingest、query、lint、compare、clean。UI 中文入口见 03，保留协议标识，避免客户端配置无故失效。

任务共同携带：库身份、访问方式、允许范围、输入资料、来源标记、知识输出目录与必要限制。文件直读方式给真实可访问绝对路径；MCP 方式给逻辑库标识和工具，不要求远端访问本机盘符。

资料路径归一化防 raw/sources/ 重复前缀；任务直接指向原格式文件，引用源文件原名。知识采用 frontmatter `sources: []` 与 `[[页面名]]` 互链约定；具体引用内容以真实资料为准，不虚构来源。

更新任务区分新增、修改和删除，删除文件不再尝试读取。清理先列出受影响摘要、索引、链接与共享实体，获得外部执行所需确认后处理；共享实体只移除该来源相关内容，不能整页删除。MCP 无删除工具时明确要求到本机完成真正文件删除。

本版规定任务语义，不声称具备可逐字复用的历史模板全文。实际模板从现有程序提取，按本章与 03 校验后使用同一生成器，禁止每个页面另写一套。

## 7. MCP 能力契约

服务默认关闭，HTTP 默认本机回环、只读，绑定明确单库；stdio 首轮只读且由客户端独立管理。浏览分享与 MCP 即使复用宿主也独立授权、独立生命周期。

| 工具 | 参数要点 | 结果与限制 |
|---|---|---|
| list_knowledge_bases | 无 | 仅授权库，不泄露本机路径 |
| list_tree | kb、relative_dir 可选 | 受控目录条目与相对路径 |
| read_file | kb、relative_path、version/cursor（续读） | 内容、原字节版本、totalBytes、nextCursor、complete；内部文件另行拒绝 |
| read_source_content | kb、relative_path、version/cursor、可选工作表/行区间 | 源版本、临时内容、定位、覆盖范围、nextCursor、complete，不落盘 |
| search_content | kb、query、limit | 仅 wiki/ 和 raw/sources 文本；默认 20，最大 50，每片段不超过 200 字符 |
| get_pending_changes | kb | 路径、动作、时间，不提供清除操作 |
| write_wiki_file | kb、relative_path、content、expected_version 或 expectedAbsent | 仅显式 HTTP 写授权可用，版本条件校验后提交 |

read_file 继续只返回文本，不把 docx/xlsx 二进制强制解码成字符串。read_source_content 为需适配的原格式读取工具，实施后按真实格式能力列表展示；没有适配前标明不可用，不以现有 read_file 冒充支持。search_content 当前仅搜索文本文件，不能暗示已覆盖 Office 正文。浏览下载原格式文件时校验相同库范围与凭据。

Resources 用 `wiki://{kb}/purpose.md`、`wiki://{kb}/schema.md`、`wiki://{kb}/index`、`wiki://{kb}/{relative_path}` 等逻辑 URI，和工具共用授权。Prompts 提供上述七类能力；question/topic 等必填字段校验错误明确返回。

读取采用第 11 章版本化分段协议，每次最多返回 64 KiB UTF-8 内容，带后续游标和完整标记；不是自动按截断内容完成任务。MCP 文本写入上限本版定为 4 MiB UTF-8，超限拒绝，不拆成可能损坏文档的多次覆盖；编辑器和预览能力据实际配置另行说明。路径参数设长度限制，默认 260 字符；如产品支持长路径应整体调整校验与说明，而非部分端点暗中放开。

HTTP 所有请求校验 Bearer 令牌，写权限独立令牌，随机令牌不少于 32 字节，受保护存储，不写普通日志。Origin 仅允许缺省的原生客户端请求或明确白名单来源。令牌轮换和范围切换使会话失效，不仅更换显示文本。

写入原子替换，提交前重查授权与版本；已有文件版本取读取返回的 version，新文件要求 expectedAbsent=true，二者互斥。人工修订保护命中返回 MANUAL_REVIEW_REQUIRED，不能绕过后直接覆盖。错误至少区分 KB_NOT_FOUND、PATH_NOT_ALLOWED、READ_ONLY_MODE、VERSION_REQUIRED、VERSION_CONFLICT、FILE_TOO_LARGE、FORMAT_NOT_SUPPORTED、SOURCE_READ_FAILED、SERVICE_UNAVAILABLE。错误不得泄露密钥、正文或其他库内容。

stdio stdout 只输出协议消息，日志走 stderr/文件。HTTP 和 stdio 复用业务校验，不各自拼路径。客户端配置按实际可执行文件、端点和目标客户端生成并实测，不提供未经核实的通用 JSON。

## 8. 配置与外部访问

应用配置保留 wikisDir 语义，主题与导航偏好独立管理，写配置保留未知字段。规则保存在库内 Markdown，不复制到另一套表单数据源。权限与令牌不当作普通布局偏好；本版 HTTP 写授权在应用重启后恢复只读。

浏览分享默认关闭，实际端口由系统分配或用户指定，运行时返回实际地址。4 位 PIN 是可信局域网轻量门槛；所有页面、API、下载均受控，无上传、编辑、删除、配置写入、工作流执行路由。退出桌面停止其宿主服务，独立 stdio 不能错误宣称已退出。

共享目录权限由 Windows 管理，不新增账号体系或云同步。根目录不可达时不自动切回本地，不建同名空库。删库永久删除，输入库名确认，目录不可访问或服务不能停止时拒绝。

## 9. 规范优先级

本版分章文档是唯一规范；完整版由分章生成，不单独手改。00 定义产品决策，01—06 定义交互，07 定义改造映射，08 为用户说明，09 为验收，本章定义数据与服务契约，11 定义跨重启状态与失败恢复，12 定义自包含任务、单次确认与回收恢复，13 定义本机执行和导出，14 定义控件与实现映射，15 汇总最终决策和文档检查结果。相互冲突时先修正文档，不要求实施者回查已删除的历史资料。概念图仅供布局参考，示例日期、文本、按钮状态不覆盖文字规范。
