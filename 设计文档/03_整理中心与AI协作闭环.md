# 03｜整理中心与 AI 协作闭环

## 1. 页面目标

这里统一回答“有什么要整理、交给 AI 什么任务、执行后怎样确认”。不再展示七张并列卡，不加入聊天窗口。任务选择只有三项：**更新知识 / 提问分析 / 检查维护**。

```text
整理                                           当前知识库：产品研究
[更新知识] [提问分析] [检查维护]
┌───────────────────────────────────────────────────────────────────┐
│ 处理范围  [待整理变更(3) ▾]                                        │
│ □ 全选   文件                 变化              时间               │
│ ☑        需求说明.docx         新增              今天 10:00         │
│ ☑        会议纪要.md           修改              今天 10:10         │
│ ☑        旧方案.txt            删除              昨天 16:00         │
│ 已选择 3 项：新增 1、修改 1、删除 1                                 │
│ 执行方式：[手动复制 ▾]                            [复制整理指令]     │
├───────────────────────────────────────────────────────────────────┤
│ 1 准备指令  →  2 在外部 AI 中执行  →  3 检查结果                    │
│ 指令预览（默认折叠，生成后可展开）                   [复制整理指令]   │
│ 状态：已复制，等待你在外部 AI 中执行                                 │
│ [查看本次变化] [刷新待整理清单]                     [确认完成这 {n} 项]   │
└───────────────────────────────────────────────────────────────────┘
```

## 2. 更新知识：三个范围、一套流程

| 范围 | 适用情况 | 默认选择 |
|---|---|---|
| 待整理变更 | 日常新增、修改、删除 | 默认范围；首次进入默认不勾选，提供全选 |
| 所选资料 | 从资料页带入，或手动选择 | 继承调用方明确选择 |
| 全部资料 | 第一次整理，或主动全面重新整理 | 先显示总数与可能耗时；用户确认范围后生成 |

“全部资料”不命名为“重建”，避免用户误解为先删除 Wiki。其语义是按批量模板重新审视全部输入，不能先清空知识目录。

待整理清单显示资料新增、修改、删除；目标与规则变化作为独立持久提醒。保留 `.changes.json` 格式与合并规则，提醒在 .llmwiki/reviews.json 中按版本维护，完成条件见第 11 章。

对于删除项，文案写“整理引用”，不写“重新读取资料”。生成器组合原增量处理说明与清理计划，必须保留“共享实体不整页删除、先列拟修改项”的约束。没有删除工具的 MCP 任务要明确：本次可修订引用，但真正删除文件需本机确认，不能承诺自动完成全部清理。

## 3. 任务准备、复制与主动执行

以下步骤描述无已配置本机工具时的复制分支；有适配工具时由第 13 章开始/取消/核对流程执行，复用相同快照与确认规则。

1. 选择任务和范围，页面检查当前库可访问、目标资料存在、删除项确实已删除。
2. 点击“复制整理指令”，一次完成校验、持久化库/范围/规则/文件快照、组合上下文与任务正文，再写剪贴板；可选“预览完整指令”，不强制先预览。
3. 展示任务摘要：处理范围、外部工具与访问方式。本机启动器由用户点击开始后启动外部进程；复制方式仍由用户去外部工具粘贴。应用不内置模型。
4. 写剪贴板成功才显示“已复制，等待外部执行”；复制失败保留已准备任务，重试同一快照，不重复创建任务。
5. 用户到外部 AI 工具粘贴执行；面板不根据剪贴板事件推断是否启动、成功或失败。
6. 返回后“查看本次变化”打开本次文件变化与逐项核对面板，再由条目进入知识页，“刷新待整理清单”读取当前真实状态。
7. 用户核对后点击“确认完成这 {n} 项”，仅确认本次仍一致的变更。

修改输入后生成新任务，不覆盖原快照；切库保留原库任务。范围内资料变化仅使相应项失效，无关新增项不阻断所选任务；全部资料范围增加、规则或模板变化时，重新复制必须准备新任务。完整失效规则见第 11 章。

指令正文继续复用已有 PromptEngine/模板，不在页面写第二套文案。UI 中文名称与协议标识分离，旧 CLI/MCP 标识保持兼容。

## 4. 确认处理的必要保护

“确认处理”表示用户确认本次变更已由外部 AI 处理，不是系统证明知识质量合格。按钮旁显示这一说明。

- 在结果面板持续显示将移出的项目和数量，勾选即表示用户已核对；点击“确认完成这 {n} 项”一次提交，不再另弹普通确认框。
- 已复制不是启用确认按钮的充分依据；用户可以未复制而在外部自行处理，因此允许“我已在外部完成”并明确确认。
- 只有选中的待整理记录能被清除，不清空整库变更。
- 新增/修改项比较记录快照及当前文件内容版本；删除项比较变更记录版本，并确认文件没有重新出现。
- 生成后再次变动的项继续保留，反馈“已确认 2 项；1 项有新变化，仍待整理”。
- 确认与新增变更并发时必须在业务服务中以同一写入临界区比较并修改，不能在 UI 先读后全量覆盖 JSON。
- 若旧记录无 hash，可计算当前指纹并结合记录字段形成会话快照；不能因缺 hash 就直接清除。无法稳定匹配的项要求刷新后重新选择。
- 所选资料/全部资料模式只有能映射到本次快照的待整理记录才可确认，不能按文件名消除后来发生的新记录。
- 所有新资料按原文件相对路径匹配；SHA256 针对原文件字节计算，不用派生文本替代。历史记录按第 07、10 章显式适配。

确认失败保留所有未成功项。现有清除 API 如不支持上述语义，应先增加服务级“比较后确认”能力，再启用新按钮；禁止仅用前端延迟掩盖竞态。

## 5. 任务状态与持久化

| 状态 | 用户能看到什么 | 可做什么 |
|---|---|---|
| 未准备 | 任务表单与范围 | 选择、生成 |
| 已生成 | 本次范围、指令、生成时间 | 预览、复制 |
| 已复制/已交给外部 | 等待外部执行，未确认完成 | 查看结果、刷新、确认 |
| 某项已变化（附加标记） | 标注受影响项，其他项可继续核对 | 为变化项准备新任务 |
| 部分确认 | 已确认数量、保留项目原因 | 继续处理剩余项 |
| 本次已确认 | 明确本次范围，不表示整库无其他变更 | 返回知识或开始下一次 |

生成后的任务以隐藏 JSON 记录跨重启保留，不建数据库、不混入 `.changes.json`。恢复任务范围、文件版本和逐项确认进度，不把复制恢复成执行成功。未完成任务不自动清理，完成/放弃记录保留最近 50 条且最多 30 天；字段与恢复细则见第 11 章。

## 6. 提问分析

类型切换：“回答问题 / 对比主题”。输入区仅显示对应字段，例子使用当前知识主题的通用占位，不插入虚构答案。

- 回答问题：标签“你想了解什么？”，必填；调用 Query 模板。
- 对比主题：标签“你想比较什么？”，必填；调用 Compare 模板。
- 下方共用执行入口；本机工具可用时“开始分析”，否则复制完整任务。
- 显示“回答会在外部 AI 工具中生成”，不显示空聊天气泡或“发送”按钮。
- 分析结果是否写入 queries/comparisons 以模板规则为准，界面不能声称每次提问都会存档。

## 7. 检查维护

两个任务：

1. **检查知识质量**：沿用 Lint，检查来源、矛盾、陈旧、孤立页、缺口；可由用户主动交给本机工具执行，或复制检查任务；程序结束仍需核对报告。
2. **处理已删除资料的引用**：沿用 Clean，可从删除变更中选择；显示“先生成清理计划，再在外部确认执行”。

维护面板不提供“一键清空知识”“自动修复全部”等新能力。无删除项时仍可阅读说明，但不生成空清理任务。

## 8. MCP 协作与手动复制的关系

执行入口与访问方式分开：已验证本机工具可用时默认“开始整理”，否则“复制整理指令”；高级入口可导出任务包。访问方式为文件访问或 MCP；选择外部 MCP 客户端时只复制任务说明，不假装已派发。详细启动、取消和重试按第 13 章。

本工具提供 MCP 服务，通常由外部客户端主动调用；**服务开启不等于任务已发送，连接成功不等于整理完成**。外部客户端需读取资料并写知识时必须有写权限；只读连接只能查询和生成计划，应提示切到文件直读方式或由用户开启写入。

MCP 写入不自动确认待整理项。旧 Prompt 若包含绝对路径，则“手动文件访问”保留该语义；MCP 版本通过同一生成器的传输上下文适配成逻辑资源和工具调用，不能把本机路径当远端可访问路径，也不能宣称两个版本逐字一致。

## 9. 七类能力去向对照

| 旧能力 | 中文新入口 | 协议/模板兼容标识 |
|---|---|---|
| Boundary | 自动随任务携带；高级查看/复制库说明 | boundary |
| Batch Ingest | 更新知识 / 所选资料或全部资料 | batch_ingest |
| Incremental Ingest | 更新知识 / 待整理变更 | incremental_ingest |
| Query | 提问分析 / 回答问题 | query |
| Compare | 提问分析 / 对比主题 | compare |
| Lint | 检查维护 / 检查知识质量 | lint |
| Clean | 检查维护 / 处理已删除资料的引用 | clean |

## 10. 原格式资料的读取能力

任务直接列出源文件名与真实路径，包括 docx/xlsx；不再要求存在同名 .md。执行前说明外部 AI 必须能读取相应原格式，不能因文件不是 Markdown 就忽略它。

文件直读模式由外部 Agent 的文件读取/解析工具处理；MCP 模式通过已实现的原格式内容读取能力提供临时文本或表格响应，不生成落盘 Markdown。工具不支持、读取失败、内容被截断或加密时明确告知，受影响项继续待整理，不当作已执行成功。可更换具备读取能力的工具，不强迫用户转换源格式。

## 11. 结果核对与部分完成

本次结果面板列出从任务准备以来 wiki/ 新增、修改、删除的文件及来源关联；变化可能来自其他程序，不等于 AI 成功。资料逐项选择确认，读取失败/未完整读取默认保留，已在其他工具完成可带理由人工确认；无变化但已核对无需修改也可说明后确认。

外部执行期间新增无关资料不影响本次已完成项。确认前重新扫描并比较源版本，记录冲突或有新变化的项继续保留。任务开始基线、跨重启恢复、确认凭据与规则提醒完成条件统一按 [闭环补全规范](11_闭环补全与状态恢复规范.md) 实施。

## 12. 日常操作减负

统一使用第 12 章的自包含任务；有可用适配工具时按第 13 章主动执行，无工具时单按钮复制；结果页勾选后一次确认。资料删除先移入回收站，恢复会使相关清理任务按版本失效，不自动恢复已清理的知识。
