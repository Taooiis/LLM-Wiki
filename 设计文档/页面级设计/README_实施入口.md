# LLM Wiki 桌面版｜页面级详细设计包

> 目标：将整体概念图拆解成可直接交给开发 Agent 按页面实现的设计说明。设计目标不是“做一个相似配色的后台”，而是尽可能还原概念图中的 Windows Fluent 深色桌面产品观感、布局比例、信息层级和交互细节。

## 设计基线

- 技术：`.NET 10 + WPF + WPF-UI 4.3.0 + MVVM`。
- 视觉：Windows 11 Fluent、深色优先、Windows 蓝色强调色；**禁止紫色、紫色渐变、紫色发光**。
- 不引入 HandyControl、MahApps.Metro、MaterialDesignThemes 等第二套 UI 框架。
- 主窗口最小尺寸建议 `1180 × 760`；在 1100×650 下保证核心操作可用，低于该尺寸允许滚动或折叠次要区域。
- 页面内完成主要任务；弹窗只处理删除、覆盖、未保存离开等短决策。
- 所有页面的业务行为以《设计文档》01-04（总体设计 / 架构与数据 / 多设备只读访问 / 兼容与迁移）为准；文件类型已定案：白名单 md / txt / docx / xlsx，docx / xlsx 上传时转 Markdown 副本、原件存 `raw/original/`（原《功能交互规格.md》已删除）。

## 推荐阅读和开发顺序

1. 先读 `00` 和 `07`，确定全局框架、主题、交互约束与组件边界。
2. 按 `01 → 02 → 03` 实现首页、源文档和目录浏览。文档编辑工作区是核心，应先稳定再复用。
3. 实现 `04` 工作流，再实现 `05` 分享。
4. 最后完成 `06` 配置、设置和指南，并执行 `07` 的全量验收。

## 还原概念图的关键

- 左侧固定导航栏约占窗口宽度 220–236px；右侧是统一页面工作区。
- 首页不是纯统计后台：顶部有简洁欢迎区，中部统计卡，底部以知识库、待处理变更、快捷入口和存储信息构成可操作总览。
- 源文档和目录浏览采用“左侧列表/树 + 右侧预览/编辑工作区”，禁止把主编辑器塞进小弹窗。
- 工作流采用整齐的卡片网格，卡片内容层级统一，输入与输出预览都在卡片内完成。
- 所有主要按钮、选中态、焦点态、进度条使用 Windows 蓝色；不做紫色渐变。
- 视觉细节要完整：边距、对齐、空状态、加载态、错误态、悬停态、禁用态、滚动条、状态栏都要实现，不能只搭静态骨架。

## Agent 执行总约束

- 每次只实现一个阶段或一个页面，不要一次性重写全项目。
- 开始前先检查现有项目结构、已有 ViewModel、服务接口和资源字典；复用已有业务逻辑，不要重复造轮子。
- 不得为了视觉实现而改动业务目录结构、文件落盘规则、Ingest 规则或数据格式。
- 不得伪造统计数据、分享地址、任务进度或服务状态。
- 完成后必须 `dotnet build`，运行检查页面布局，并说明改动文件、实现点、未完成项和验证结果。
