# LLM Wiki 桌面版｜页面级详细设计包

> 目标：将整体概念图拆解成可直接交给开发 Agent 按页面实现的设计说明。设计目标不是“做一个相似配色的后台”，而是尽可能还原概念图中的 Windows Fluent 深色桌面产品观感、布局比例、信息层级和交互细节。

## 设计基线

- 技术：`.NET 10 + WPF + WPF-UI 4.3.0 + MVVM`。
- 视觉：Windows 11 Fluent、深色优先、Windows 蓝色强调色；**禁止紫色、紫色渐变、紫色发光**。
- 不引入 HandyControl、MahApps.Metro、MaterialDesignThemes 等第二套 UI 框架。
- 主窗口最小尺寸建议 `1180 × 760`；在 1100×650 下保证核心操作可用，低于该尺寸允许滚动或折叠次要区域。
- 页面内完成主要任务；弹窗只处理删除、覆盖、未保存离开等短决策。
- 所有页面的业务行为以《设计文档》01-04（总体设计 / 架构与数据 / 多设备只读访问 / 兼容与迁移）为准；文件类型已定案：白名单 md / txt / docx / xlsx，docx / xlsx 上传时转 Markdown 副本、原件存 `raw/original/`（原《功能交互规格.md》已删除）。

## 推荐阅读和开发顺序

1. 先读 `00` 和 `07`，确定全局框架、主题、交互约束与组件边界。
2. 按 `01 → 02 → 03` 实现首页、源文档和目录浏览。文档编辑工作区是核心，应先稳定再复用。
3. 实现 `04` 工作流，再实现 `05` 分享。
4. 最后完成 `06` 配置、设置和指南，并执行 `07` 的全量验收。

## 还原概念图的关键

- 左侧固定导航栏约占窗口宽度 220–236px；右侧是统一页面工作区。
- 首页不是纯统计后台：顶部有简洁欢迎区，中部统计卡，底部以知识库、待处理变更、快捷入口和存储信息构成可操作总览。
- 源文档和目录浏览采用“左侧列表/树 + 右侧预览/编辑工作区”，禁止把主编辑器塞进小弹窗。
- 工作流采用整齐的卡片网格，卡片内容层级统一，输入与输出预览都在卡片内完成。
- 所有主要按钮、选中态、焦点态、进度条使用 Windows 蓝色；不做紫色渐变。
- 视觉细节要完整：边距、对齐、空状态、加载态、错误态、悬停态、禁用态、滚动条、状态栏都要实现，不能只搭静态骨架。

## Agent 执行总约束

- 每次只实现一个阶段或一个页面，不要一次性重写全项目。
- 开始前先检查现有项目结构、已有 ViewModel、服务接口和资源字典；复用已有业务逻辑，不要重复造轮子。
- 不得为了视觉实现而改动业务目录结构、文件落盘规则、Ingest 规则或数据格式。
- 不得伪造统计数据、分享地址、任务进度或服务状态。
- 完成后必须 `dotnet build`，运行检查页面布局，并说明改动文件、实现点、未完成项和验证结果。

# 00｜全局框架与视觉规范

## 1. 目标效果

整体接近概念图中的 Windows 11 桌面应用：左侧深色导航、顶部轻量标题/搜索区、右侧宽阔工作区、卡片有轻微层次而非强烈投影。界面应稳重、清晰、紧凑，不要做成紫色科技风，也不要做成网页后台的密集表格风。

## 2. 主窗口结构

建议采用三段式：

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ LLM Wiki   [搜索知识库、文档或功能 Ctrl+K]                [帮助] [窗口控制] │
├──────────────────────┬─────────────────────────────────────────────────────┤
│ 品牌/应用名           │ 页面标题                           页面主操作        │
│                      ├─────────────────────────────────────────────────────┤
│  ◉ 首页               │                                                     │
│  ▤ 源文档             │                                                     │
│  ▥ 目录浏览           │                    页面内容区                       │
│  ◫ 工作流       3     │                                                     │
│  ⇧ 分享               │                                                     │
│                      │                                                     │
│                      │                                                     │
│                      │                                                     │
│  ──────────────────  │                                                     │
│  ◇ 小白指南           │                                                     │
│  ⚙ 配置               │                                                     │
│  ⚙ 设置               │                                                     │
├──────────────────────┴─────────────────────────────────────────────────────┤
│ 当前知识库：产品知识库   存储：D:\\LLMWiki   服务：空闲   v1.0.0             │
└────────────────────────────────────────────────────────────────────────────┘
```

### 2.1 尺寸与自适应

- 默认启动尺寸建议 1440×900，最小尺寸建议 1180×760。
- 左导航宽度 224px；可折叠到 64px 图标栏。折叠状态持久化。
- 顶部标题/搜索区高度约 52px；页面标题区 72–88px；底部状态栏 28px。
- 内容区左右 Padding 24px，上下 20px；卡片间距 16px。
- 页面内容区允许独立滚动，导航栏和顶部区域不随内容滚动。
- 小窗口时优先压缩卡片列数：4列→2列→1列；不要让按钮、文字互相覆盖。

## 3. 导航规范

导航项固定为：首页、源文档、目录浏览、工作流、分享；底部为小白指南、配置、设置。

- 当前项：使用低饱和蓝色半透明底（例如 `#163A55`），左侧可有 2px 蓝色指示条；不使用渐变胶囊。
- 图标：使用 WPF-UI / SymbolIcon 对应 Fluent 图标，统一 16–18px。
- 工作流待处理数量仅在大于 0 时显示小徽标；颜色用警示橙/红，不要让整个导航项变红。
- 导航切换保留页面自己的搜索、筛选、滚动位置；切换知识库时刷新依赖当前库的数据。
- 编辑器有未保存内容时，导航切换必须先走统一未保存保护流程。

## 4. 顶部搜索

- 顶部搜索框宽度建议 360–460px，placeholder：`搜索知识库、源文档或 Wiki 内容…`。
- `Ctrl+K` 聚焦，Esc 收起建议列表，Enter 打开第一条结果。
- 结果按知识库 / 源文档 / Wiki 文档 / 功能入口分组。
- 搜索无结果时展示清晰空状态和清空入口。
- 如果当前搜索能力仅支持本地文件名，文案不得暗示支持全文搜索。

## 5. 视觉 Token

以下作为统一资源字典，不允许各页面随意写不同色值：

| Token | 值 | 用途 |
|---|---|---|

### 5.1 字体与间距

- 页面标题 26–28px / Semibold。
- 区块标题 17–18px / Semibold。
- 卡片标题 14–16px / Semibold。
- 正文 13–14px；辅助信息 11–12px。
- 默认圆角：卡片 10px；输入框 6px；按钮 6px；对话框 10px。
- 内容边距 20–24px；卡片间距 14–16px；列表行高 44–52px。

## 6. 控件与组件约束

- 主窗体：WPF-UI `FluentWindow`。
- 导航：`NavigationView` / 对应导航控件。
- 图标：`SymbolIcon`，统一图标尺寸。
- 通知：WPF-UI `Snackbar`。
- 聚焦确认：WPF-UI `ContentDialog` 或项目已封装的统一 Dialog。
- 开关：`ToggleSwitch`。
- 搜索：`AutoSuggestBox` 或现有搜索控件。
- 卡片：优先 `Border + Grid` 或 WPF-UI 卡片控件，不要额外引入完整 UI 框架。
- 左右分栏：`Grid` + `GridSplitter`。
- 文档编辑：现有 Markdown 编辑方案；若使用 AvalonEdit，需统一暗色配色。
- Markdown 预览：沿用现有渲染方案；若使用 WebView2，必须限制本地资源访问和脚本权限。

## 7. 状态与交互统一

每个页面都必须定义：初始/加载/空/正常/错误/禁用/执行中状态。

- Snackbar：只提示一次性结果，不承担持久状态。
- 页面内状态：显示保存状态、服务状态、任务进度等长期信息。
- 异步请求：避免 UI 线程阻塞；重复点击期间禁用同一操作。
- 错误信息：尽量说明原因和下一步，不只显示“操作失败”。
- 不允许使用系统 `MessageBox` 作为主要交互。

以上是建议，不要求为迁就目录结构而大规模搬迁现有代码。命令和状态应由 ViewModel 管理，View 不直接操作文件系统。

## 9. 全局验收

- [ ] 深色主题下所有页面均无紫色主色或紫色渐变。
- [ ] 导航栏宽度、页面边距、卡片间距统一。
- [ ] 1100×650 下核心操作不被裁切。
- [ ] 折叠导航后图标提示和当前页状态仍清楚。
- [ ] 页面切换不会静默丢失未保存内容。
- [ ] 加载、空、错误、禁用状态均有明确 UI。
- [ ] 所有图标语义准确，按钮有 Tooltip 或文字说明。

# 01｜首页：知识库总览

## 1. 页面目标

首页是进入应用后的工作台。用户打开后应立即知道：当前有哪些知识库、当前库的资料规模、是否有待处理变更、存储位置是否正常，以及下一步可以做什么。首页不能只是四个数字，也不能把所有功能入口堆成一排按钮。

## 2. 页面整体布局

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 首页                                                                  │
│ 管理你的知识库，查看最近变更并继续知识整理。               [新建知识库] │
├─────────────────────────────────────────────────────────────────────┤
│  欢迎使用 LLM Wiki                                                    │
│  将资料整理成可检索、可维护、可追溯的知识库。                           │
│  [打开源文档] [查看工作流]                                             │
├──────────────────┬──────────────────┬──────────────────┬──────────────┤
│ 知识库数量        │ 源文档数量        │ 待处理变更        │ 存储状态       │
│  08               │  126              │  03               │ 正常           │
│ 个知识库          │ 份源文档          │ 需要重新 Ingest   │ D:\\LLMWiki     │
├─────────────────────────────────────┬───────────────────────────────┤
│ 我的知识库                          │ 待处理变更                    │
│ [搜索知识库…]                       │ 3 项待处理                    │
│ ┌───────────────────────────────┐   │ 文件名 / 变更类型 / 时间       │
│ │ 产品知识库       24份文档      │   │ [查看全部] [去处理]             │
│ │ 最近访问：今天   [打开] […]    │   ├───────────────────────────────┤
│ └───────────────────────────────┘   │ 快捷入口                      │
│ ┌───────────────────────────────┐   │ [上传文档] [浏览目录]            │
│ │ 项目知识库       18份文档      │   │ [生成 Ingest] [运行 Lint]        │
│ └───────────────────────────────┘   ├───────────────────────────────┤
│                                     │ 当前存储位置                    │
│                                     │ D:\\LLMWiki [打开配置]           │
└─────────────────────────────────────┴───────────────────────────────┘
```

## 3. 页面分区与视觉细节

### 3.1 标题区

- 左侧标题“首页”，下方一行简短说明：`管理知识库、源文档和知识更新状态。`
- 右侧主按钮：`新建知识库`，蓝色实心按钮。
- 不再放置多个同级主按钮；上传、浏览等操作放入快捷入口。

### 3.2 欢迎 Banner

- 横向卡片，高度约 112–132px；底色使用 `#252B30` 或同色系微弱层次，不使用渐变色。
- 左侧标题：`欢迎使用 LLM Wiki`；说明：`把分散的资料整理为可持续维护的知识库。`
- 右侧可以放轻量线性知识图谱/文档图标组合，不要使用大面积装饰插画遮挡文字。
- 两个轻量按钮：`打开源文档`、`查看工作流`。
- 如果不需要 Banner 的视觉高度，可在窄窗口下压缩为普通说明行。

### 3.3 四张统计卡

四卡等宽，桌面宽屏一行显示；小窗口两列。

| 卡片 | 主值 | 辅助文案 | 点击行为 |
|---|---|---|---|
| 知识库 | 当前知识库总数 | 个知识库 | 跳转知识库列表/定位我的知识库 |
| 源文档 | 当前选中库的源文档数，需明确口径 | 份源文档 | 跳转源文档页 |
| 待处理变更 | 当前选中库待处理数 | 需要重新 Ingest | 跳转工作流或源文档变更区 |
| 存储状态 | 正常/异常/未配置 | 当前路径摘要 | 跳转配置页 |

- 数字 28–32px，标签 13px，辅助文字 11–12px。
- 图标使用低对比度蓝色/灰色底，不做彩色大圆形渐变。
- 待处理数大于 0 时可显示小型警示标识；为 0 显示“全部已同步”或“暂无待处理”。
- 存储状态不能仅根据路径字符串存在判断，应使用真实校验结果；无法验证时显示“未验证”。

## 4. 我的知识库区域

- 区块标题：`我的知识库`，右侧显示总数和排序方式（最近访问/名称）。
- 搜索框在标题下方，输入即时过滤，不弹窗。
- 卡片列表每项显示：知识库名称、源文档数、最近访问时间、路径摘要（可选）、当前选中标记。
- 当前知识库用蓝色细边框或左侧蓝色指示条标记，不能只靠文字颜色。
- 单击卡片：切换当前库并刷新依赖数据；若当前有未保存编辑，先执行未保存保护。
- 双击卡片或点击“打开”：进入源文档页并选中该库。
- 更多菜单：删除知识库。删除必须确认，明确展示库名和不可恢复风险。
- 空状态：显示“还没有知识库”，主操作“新建知识库”，辅助说明默认存储目录。

## 5. 待处理变更区域

- 仅展示最近若干条（建议 3–5 条），不在首页呈现完整复杂表格。
- 每行显示文件名、变更类型（新增/修改/删除）、时间；类型用小徽标。
- 点击行跳转源文档页并定位对应文件/变更。
- `查看全部`进入完整变更列表；`去处理`跳转工作流增量 Ingest。
- 无待处理变更时显示轻量空状态：“当前知识库已同步”。
- 不能只显示红色告警而不给下一步操作。

## 6. 快捷入口与存储信息

快捷入口建议 2×2 小按钮或图标入口：上传文档、浏览目录、生成 Ingest、运行 Lint。入口点击后应直接进入对应页面并聚焦目标区域，不要再弹一个“请选择操作”窗口。

存储位置卡片显示：
- 当前根目录完整路径（超长时省略中间段，悬停显示完整路径）。

# 02｜源文档：管理与编辑工作区

## 1. 页面目标

源文档是资料进入知识库的入口。核心任务包括查看文件、上传、新建 Markdown、编辑文本文件、删除文件、查看待处理变更。页面必须保持“左侧文件列表 + 右侧文档工作区”，预览和编辑在右侧同一位置切换，不再使用传统编辑弹窗。

## 2. 整体布局

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ 源文档                                                [新建文档] [上传文件] │

│ └──────────────────────────┘ │                                           │
│ ┌──────────────────────────┐ │ 文档正文预览区域                           │
│ │ PDF 需求附件.pdf   只读   │ │                                           │
│ │    1.8 MB · 昨天         │ │                                           │

│ │ TXT 会议记录.txt         │ │                                           │
│ └──────────────────────────┘ │                                           │
```

## 3. 左侧文件列表

### 3.1 列表头

- 当前知识库名称必须持续可见。
- 搜索框只过滤当前已加载列表，按现有规格不额外触发磁盘读取。
- 类型筛选可选：全部、Markdown、文本、PDF、Office、其他支持类型。筛选项只能覆盖已实现白名单。
- 列表标题显示文件数量。

### 3.2 文件行

每行包含：
- 类型图标：MD/TXT/PDF/XLSX/DOCX/HTML/JSON 等。
- 文件名，最多两行或单行省略。
- 辅助信息：文件大小、修改时间。
- 只读类型显示“只读”徽标。
- 当前选中项用低饱和蓝色背景 + 左侧 2px 蓝线。

交互：
- 单击：加载右侧预览。
- 双击：可编辑文本文件进入编辑；只读文件按策略打开或仍留在预览。
- 右键菜单：编辑（可编辑时）、打开（只读时）、复制相对路径、删除。
- 删除前确认，删除后清空右侧工作区并刷新待处理变更。

### 3.3 待处理变更

列表底部或独立折叠区显示待处理变更数量。点击后展开变更列表，显示动作、新增/修改/删除、文件名、时间和勾选框。

- 勾选状态不能因列表虚拟化/滚动而丢失。
- “生成选中 Ingest”只有选中项大于 0 时可用。
- 点击后跳转工作流页，自动填入文件名并生成对应提示词。
- “标记已处理”仅对明确选中的变更生效；不得无提示清空未勾选项。

## 4. 右侧文档工作区

### 4.1 Empty 状态

没有选中文档时显示居中图标、标题“选择一个源文档”、说明“从左侧列表选择文件，或上传/新建一份资料”，以及两个快捷操作“上传文件”“新建文档”。

### 4.2 Preview 状态

顶部工具栏：
- 文件名（主标题）。
- 完整相对路径（辅助文本，等宽字体）。
- 右侧操作：可编辑文件显示“编辑”；只读文件显示“打开”；更多菜单含复制路径、删除。

正文区域：
- Markdown 使用排版预览；TXT/代码/JSON 使用等宽文本预览；PDF/Office 等按当前已确认策略展示预览或只读信息。
- 预览内容区可滚动，不影响左侧列表。
- 顶部或底部显示文件类型、大小、修改时间、保存状态。

### 4.3 Editing 状态

编辑状态必须在原右侧区域内完成，不弹出独立小窗。

```text
┌────────────────────────────────────────────────────────────────┐
│ 编辑：产品需求说明.md                 ● 有未保存更改 [保存] [取消] │
│ raw/sources/产品需求说明.md                                     │
├────────────────────────────────────────────────────────────────┤
│ [Markdown] [预览] [分屏]                         字数 1280       │
│                                                                │
│ # 产品需求说明                                                  │
│                                                                │
│ 在这里编辑文档正文……                                            │
│                                                                │
├────────────────────────────────────────────────────────────────┤
│ Ctrl+S 保存    Markdown 文件    行 18，列 1                      │
└────────────────────────────────────────────────────────────────┘
```

- 编辑器填满右侧工作区；不能在卡片里再嵌套一个小型编辑框。
- 顶部显示文件名、路径、保存状态、保存/取消操作。
- 支持编辑/预览/分屏模式（如果现有编辑器能力允许）；最小实现可先实现编辑与预览切换。
- Ctrl+S 保存；Esc 不直接丢弃内容，触发退出编辑保护。
- 保存成功：状态变为“已保存”，更新修改时间，自动登记待处理变更并追加 `wiki/log.md`（沿用现有业务逻辑）。
- 保存失败：编辑内容保留，状态变为“保存失败”，错误详情显示在工作区内，提供“重试保存”。不能关闭编辑器。

## 5. 新建文档

- 点击页头“新建文档”后，右侧直接进入 Editing / New 状态。
- 文件名输入位于工具栏下方或工具栏左侧，默认建议 `.md`，但不要在用户未确认时自动覆盖已有同名文件。
- 文件名为空、非法字符、路径穿越、同名冲突时，在输入区附近显示错误。
- 内容编辑区立即可用。
- 点击“创建”或 Ctrl+S：校验文件名→写入 `raw/sources/`→刷新列表→选中新文件→显示成功反馈。
- 创建成功后提示用户后续可去工作流页重新 Ingest。
- 创建失败不得清空编辑内容。

## 6. 上传文件

- 点击“上传文件”调用系统文件选择器，支持多选。
- 选择完成后进入上传处理状态，展示文件名、进度、成功/失败结果；若无法获取精确进度，显示阶段状态，不要编造百分比。
- 同名冲突必须明确选择覆盖/跳过/取消（具体策略需与现有实现对齐）。
- 上传完成刷新列表；新文件按业务规则生成待处理变更。
- **重要：** 原规格中 `.docx/.xlsx` 转 Markdown、原件存 `raw/original` 与“原样存储”的方案存在待确认冲突。此页面只实现已确认策略，不得自行改写文件转换行为。

## 7. 删除与未保存保护

删除源文件：确认对话框明确文件名、相对路径和“删除后会记录一条待处理变更”。删除后刷新列表、清空预览、更新首页计数。

未保存保护统一提供：
- `保存后离开`：保存成功后执行原导航/切换动作。
- `放弃更改`：丢弃本次编辑并执行原动作。
- `继续编辑`：关闭确认并保留当前内容。

不允许“点关闭就直接丢失”。

## 8. ViewModel 建议

`SourceDocumentsViewModel`：当前库、文件集合、搜索词、类型筛选、选中文件、变更集合、选中变更集合、加载状态、上传状态。

`DocumentWorkspaceViewModel`：模式（Empty/Preview/Editing/ReadOnly）、当前文档、编辑内容、原始内容、保存状态（None/Saved/Dirty/Saving/Failed）、文件名、相对路径、错误信息、字数/行列信息。

命令：`LoadDocuments`、`SelectDocument`、`CreateDocument`、`UploadDocuments`、`EnterEditMode`、`SaveDocument`、`CancelEdit`、`DeleteDocument`、`GenerateSelectedIngest`、`MarkChangesProcessed`。

## 9. 验收清单

- [ ] 选中文档后右侧能正确加载真实内容，不出现空白假预览。
- [ ] 预览→编辑在同一工作区切换，不打开模态编辑窗。
- [ ] 新建文档也复用同一编辑工作区。
- [ ] Ctrl+S 可保存；保存成功后自动登记变更并写日志。
- [ ] 保存失败保留内容，显示原因并支持重试。
- [ ] 切换文件、切换库、切换页面、关闭窗口均触发未保存保护。
- [ ] 上传多文件时能显示处理结果；失败文件不会被误报成功。
- [ ] 删除后列表、预览、变更计数正确刷新。
- [ ] 文件类型处理严格遵循最终确认的白名单和转换规则。

## 3. 左侧目录树

- 顶部显示当前知识库名称。
- 搜索框支持按文件名/目录名过滤；过滤后保留父级路径，匹配项高亮。
- 提供“展开全部”“折叠全部”，避免按钮过多。
- 文件夹和文件使用不同 Fluent 图标；Markdown、TXT、JSON 等按类型区分。
- 文件夹展开状态在页面会话内保留；刷新目录后尽量恢复展开路径。
- 当前选中节点蓝色背景 + 左侧指示线。
- 目录排序规则必须稳定：文件夹优先还是按名称排序，需与现有产品行为保持一致；不要依赖文件系统不稳定枚举顺序。

## 4. 右侧工作区

复用源文档页的 `DocumentWorkspace` 组件，保持工具栏、预览、编辑、保存状态、未保存保护完全一致。

### 4.1 预览

- 顶部显示文件名、完整相对路径、类型和操作。
- Markdown 正文按标题、列表、代码块、表格、引用等正常渲染。
- TXT/JSON 等文本文件使用适合阅读的等宽预览。
- 图片等资源类型可显示预览（若当前项目已有能力）；其他类型显示文件信息和“打开”操作。

### 4.2 编辑

- `.md/.txt` 等允许编辑的文件在右侧原位进入编辑模式。
- 只读文件不显示“编辑”按钮，显示只读原因或“由外部程序打开”。
- 保存必须写回当前节点的**原相对路径**，例如 `wiki/concepts/产品架构.md`，不能错误写到知识库根目录。
- 保存失败保留内容，支持重试。
- 编辑内容变更登记逻辑遵循现有系统；不要将 Wiki 文件修改错误登记为源文档变更，除非原业务规则明确要求。

## 5. 特殊文件和目录

- `purpose.md`、`schema.md`：允许在目录浏览中查看；配置页也提供专门编辑入口。两个入口必须共用同一文件服务和保存规则，避免覆盖冲突。
- `wiki/log.md`：建议只读展示或按现有权限编辑，不得随意改动日志结构。
- `.changes.json` 等内部状态文件：默认隐藏或放入“系统文件”折叠分组，普通用户不应误删。
- `raw/original` 等原始文件目录是否展示，按现有目录浏览范围决定。

## 6. 刷新与异常

- 刷新目录时显示轻量加载状态，保留当前选择；若当前文件已不存在，清空工作区并提示。
- 目录不可访问时显示错误说明和重试按钮，不显示空树冒充空知识库。
- 目录搜索无结果显示“没有匹配的目录或文件”。
- 对大量目录使用异步加载或虚拟化，避免阻塞 UI。

## 7. ViewModel 建议

- `TreeNodes`、`FilteredTreeNodes`、`SearchKeyword`、`SelectedNode`、`ExpandedNodeIds`、`IsLoading`、`LoadError`。
- `DocumentWorkspaceViewModel` 作为共享组件状态，保存 `RelativePath` 而不是只保存文件名。
- 命令：`LoadTree`、`RefreshTree`、`ExpandAll`、`CollapseAll`、`SelectNode`、`OpenInExternalApp`。

## 8. 验收清单

- [ ] 左侧树和右侧预览工作区布局与源文档页统一。
- [ ] 能展示 wiki 下多级目录结构，搜索保留父级路径。
- [ ] 点击任意支持文件，右侧加载正确内容。
- [ ] Markdown/TXT 编辑保存回原相对路径，不发生根目录错写。
- [ ] 只读文件没有误导性的编辑入口。
- [ ] 刷新目录不会无故丢失当前选择和展开状态。
- [ ] 系统文件有合理保护，错误状态可重试。

1. 左上编号/图标。
2. 卡片标题。
3. 一句话说明用途。
4. 输入说明或输入控件。
5. 主操作“生成提示词”。
6. 次操作“复制提示词”。
7. 可折叠的提示词预览区域。

视觉：
- 卡片背景 `CardBackground`，描边 `Stroke`，圆角 10px。
- 卡片内边距 16–18px；网格间距 16px。
- 编号徽标使用深蓝背景，不使用紫色圆形渐变。
- 主操作按钮蓝色；复制为次级按钮/图标按钮。
- 生成后卡片底部显示“已生成”状态和预览折叠区，不要把整段长提示词直接撑满卡片。

## 4. 七类工作流定义

### 4.1 边界说明（Boundary）

- 输入：当前知识库名、真实绝对路径、purpose/schema 摘要、目录清单。
- 输出：Agent 接入说明，包含可读写范围、目录约定、文件边界和操作约束。
- 页面不需要用户输入。
- 生成时必须使用当前选中知识库的真实路径，不允许硬编码。
- 预览内容支持滚动和复制。

### 4.2 批量 Ingest

- 输入框：文件名，逗号分隔；留空代表全部源文档。
- 可提供“从源文档选择”轻量选择器，但不要为简单输入强制弹窗。
- 生成前归一化路径：若输入已包含 `raw/sources/` 前缀，避免重复拼接。
- 输出提示词明确列出目标文件、处理边界和输出目录。
- 输入为空时，界面显示“将处理当前库全部源文档”，让用户知道范围。

### 4.3 增量 Ingest

- 输入：当前 `.changes.json` 待处理变更。
- 生成内容只针对新增/修改/删除变更。
- 待处理数量为 0 时，卡片显示“暂无待处理变更”，生成按钮禁用或允许生成空任务（按现有实现确定）。
- 与源文档页联动：从“生成选中 Ingest”跳转时自动带入所选文件，不丢失上下文。
- 执行后用户回到源文档页标记已处理；不能在复制提示词时就自动清除变更。

### 4.4 Query

- 输入：用户问题。
- 输出：要求基于当前知识库回答、提供来源引用、标记不确定性，不得虚构来源。
- 空问题时提示输入问题；复制时按当前输入实时重新生成提示词。
- 问题过长时显示字数提示，不静默截断。

### 4.5 Lint

- 输入：当前知识库上下文。
- 检查项：知识矛盾、陈旧内容、孤立页面、缺失引用、知识缺口。
- 输出：分组检查任务和建议报告格式。
- 不能声称已完成检查；本卡只是生成指令，除非系统真的执行 Agent 任务。

### 4.6 Compare

- 输入：对比主题。
- 输出：对比维度、来源引用、相同点、差异、结论和待确认问题。
- 空主题时禁用生成按钮并提示。
- 复制时基于当前输入实时生成。

### 4.7 Clean

- 输入：待清理的删除变更及知识库上下文。
- 输出：清理 Wiki 中对已删除源文档的引用、关联页和失效索引的指令。
- 明确要求先列出拟删除/修改项并确认，再执行不可逆清理；不能将 Clean 设计成直接删除按钮。

## 5. 提示词预览交互

- 点击“预览提示词”展开卡片内区域，支持代码样式等宽字体、复制、收起。
- 点击“复制提示词”将当前最新生成结果写入剪贴板并 Snackbar 提示卡片名称。
- 复制失败必须提示原因，不能虚假显示成功。
- Query/Compare/批量 Ingest 的输入改变后，将生成状态标记为“输入已变化，需要重新生成”。
- 不要每次输入字符都自动复制或自动执行。

## 6. 长任务和执行状态

如果现有项目支持真正执行工作流：
- 显示任务阶段、当前处理文件、已完成/总数（仅在真实数据可得时）。
- 提供取消操作；取消后保留已完成结果并说明状态。
- 任务失败显示失败阶段和可重试入口。

如果当前仅生成提示词：
- 页面文案统一叫“生成提示词 / 复制提示词”，不要叫“运行成功”。
- 不显示虚构的进度百分比。

## 7. ViewModel 建议

- 当前库信息、待处理变更数量。
- 每张卡片独立的输入、生成结果、是否展开、是否过期、复制状态。
- 命令：`GenerateBoundaryPrompt`、`GenerateBatchIngestPrompt`、`GenerateIncrementalIngestPrompt`、`GenerateQueryPrompt`、`GenerateLintPrompt`、`GenerateComparePrompt`、`GenerateCleanPrompt`、`CopyPrompt`、`ImportPendingChanges`。

可用统一 `WorkflowCardViewModel` 表示卡片，但每类输入和生成器仍需保持强类型或明确配置，不建议用大量字符串魔法判断业务类型。

## 8. 验收清单

- [ ] 七张卡片齐全，顺序和用途明确。
- [ ] 宽屏采用双列网格，Clean 可横跨两列；窄屏自动单列。

- [ ] 路径前缀不会重复。
- [ ] 增量 Ingest 读取真实待处理变更；复制不会自动标记已处理。
- [ ] 提示词预览可展开、收起、复制。
- [ ] 不把提示词生成冒充 Agent 执行。

### Light 主题适配

## 3. 服务状态卡

状态至少包含：未启动、启动中、运行中、停止中、启动失败。

- ToggleSwitch 与真实服务状态绑定；无库时 `CanStart=false` 开关禁用，点了也不弹错
- 启动中禁用重复点击，展示阶段状态
- 启动成功后显示地址、PIN 和分享范围
- 启动失败显示错误原因和重试按钮；开关回到关闭状态
- 停止时先执行真实停止动作；停止成功后清除可用地址显示或标记为不可访问
- 服务状态需在页面、状态栏保持一致

## 4. 地址与 PIN

- 地址使用可复制文本块，长地址自动换行或横向滚动；复制按钮始终可见
- 多网卡环境如果有多个可访问地址，应逐条展示并注明局域网网卡/地址，不要拼成一个不清晰字符串
- PIN 使用较大等宽字体，避免与地址混淆
- PIN 重新生成前说明旧 PIN 失效规则；如果重新生成会断开现有访问，需要提示
- PIN 不应写入普通日志或错误详情
- "在浏览器中打开" 仅在本机地址可用时启用

### LanAddresses 修正（实现）

- `LanAddresses()` 仅返回局域网 IPv4 地址；本机回环地址由 `LocalAddress` 单独提供
- 未检测到局域网地址时，页面显示「未检测到局域网地址：请确认已连接网络」

## 5. 分享范围与安全提示

固定显示只读能力清单：

- 允许：目录浏览、文档预览、按权限下载（仅在服务确实支持时）
- 禁止：编辑、上传、删除、配置修改、工作流执行
- 服务端必须真正限制写接口；不能只在前端隐藏按钮
- 仅暴露当前选中知识库或产品已定义的范围；切换存储目录后分享服务应按原规格跟随新目录
- 不允许把任意本机路径通过 URL 参数暴露给外部请求

### 当前库/范围展示（实现）

- 当前知识库：`SelectedKb` 为空时显示「未选择」；选中后即时更新
- 分享范围：`StoragePathText` = 未选库时「未选择知识库，不会暴露任何目录」；选中后显示知识库子目录

## 6. 空状态和异常

- 未启动：展示说明、主开关和"启动分享服务"；若未选库显示黄色提示「请先在首页选择或创建知识库」
- 启动失败：错误摘要、详细信息折叠区、重试
- 没有可分享知识库：说明先创建或选择知识库，启动按钮禁用

## 7. ViewModel 建议

- `IsRunning`、`IsBusy`、`Port`、`Pin`、`LocalAddress`、`FriendlyAddress`、`LanAddresses`、`StatusText`、`ToggleText`、`ShowConnectionInfo`、`EmptyKbHint`、`CanStart`、`CanToggle`、`SelectedKbText`、`StoragePath`、`StoragePathText`、`LastError`、`HasError`、`SelectedKb`
- 命令：`ToggleShare`、`StartShare`、`StopShare`、`CopyUrl`、`CopyPin`、`RegeneratePin`、`OpenLocalUrl`

- `Refresh()` 从服务读取真实状态，`OnNavigatedToAsync()` 进入页面时调用

# 07｜公共交互组件与验收清单

## 1. 统一文档工作区 DocumentWorkspace

源文档页、目录浏览页、purpose/schema 编辑入口尽量复用统一工作区。通过输入参数控制数据来源和允许的操作，不复制三套编辑器。

### 1.1 状态枚举

```csharp
public enum DocumentWorkspaceMode
{
    Empty,
    Preview,
    Editing,
    ReadOnly
}

public enum DocumentSaveState
{
    None,
    Saved,
    Dirty,
    Saving,
    Failed
}
```

### 1.2 必须具备的属性

- `Mode`：Empty/Preview/Editing/ReadOnly。
- `DocumentName`、`RelativePath`、`DocumentType`、`FileSize`、`LastModified`。
- `Content`、`OriginalContent`。
- `SaveState`、`SaveErrorMessage`、`IsBusy`。
- `CanEdit`、`CanSave`、`CanDelete`。
- `LineNumber`、`ColumnNumber`、`WordCount`（编辑器能力允许时）。

### 1.3 状态流转

```text
Empty --选择文件--> Preview
Preview --编辑--> Editing
Preview --只读文件--> ReadOnly
Editing --内容改变--> Dirty
Dirty --保存--> Saving --成功--> Saved
Dirty --保存--> Saving --失败--> Failed（内容保留）
Editing/Dirty --取消--> 统一未保存保护
```

### 1.4 保存要求

- 保存命令执行期间禁用重复保存。
- 保存成功才更新 `OriginalContent` 和 `SaveState=Saved`。
- 保存失败不能更新原始内容，不能清空编辑器。
- 保存成功后刷新文件元信息和相关计数。
- 保存接口应接收明确的目标路径/文档标识，避免只用文件名定位导致错写。

## 2. 未保存保护对话框

触发场景：切换文档、切换知识库、离开页面、关闭窗口、切换存储根目录。

对话框文案示例：

- 标题：`还有未保存的更改`
- 正文：`"产品需求说明.md"有尚未保存的修改。离开前要如何处理？`
- 按钮：
  - 主按钮：`保存后离开`
  - 次按钮：`放弃更改`
  - 轻按钮：`继续编辑`

规则：

- 保存失败时留在当前编辑状态。
- 用户点击继续编辑时不改变任何内容。
- 放弃更改必须明确恢复到原始内容或退出当前文档。
- 不允许在未保存保护对话框上再叠加另一个确认弹窗。

## 3. 确认对话框规范

仅用于删除、覆盖、清空等不可逆操作。结构：标题、对象/范围、后果说明、确认按钮、取消按钮。

示例删除文档：

- 标题：`删除源文档`
- 正文：`确定删除"产品需求说明.md"吗？删除后会记录一条待处理变更，后续可通过增量 Ingest 更新 Wiki。`
- 确认按钮：`删除文件`（危险样式）
- 取消按钮：`取消`

禁止：按钮只写"确定"；对话框里再打开另一个对话框；使用 MessageBox 作为全站通用方案。

## 4. Snackbar / Toast

- 位置：主窗口底部或右下角，不遮挡关键操作。
- 成功提示约 2.5–3 秒自动消失；错误提示可稍长或要求用户手动关闭。
- 成功示例：`已保存`、`已复制：增量 Ingest`、`已创建知识库：产品知识库`。
- 错误示例：`保存失败：没有权限写入目标文件。编辑内容已保留。`
- 不用 Snackbar 展示需要用户持续关注的任务进度或服务运行状态。

## 5. 加载、空状态、错误状态

每个数据区都必须覆盖：

| 状态 | 表现 | 用户操作 |
|---|---|---|
| Loading | 骨架/局部进度，避免全屏闪烁 | 可等待；长任务可取消 |
| Empty | 图标 + 一句话 + 主操作 | 创建/上传/清空搜索 |
| Error | 错误摘要 + 重试 | 重试/查看详情 |
| Normal | 正常内容 | 常规操作 |
| Busy | 当前操作按钮显示处理中 | 防重复提交 |
| ReadOnly | 明确只读原因 | 打开外部程序/返回 |

禁止用空列表代表加载失败；禁止用"暂无数据"掩盖接口异常。

## 6. 键盘操作

| 快捷键 | 行为 |
|---|---|
| Ctrl+K | 聚焦全局搜索 |
| Ctrl+S | 保存当前文档（编辑状态） |
| Esc | 关闭轻量 Flyout；编辑状态下触发退出保护，不直接丢稿 |
| Ctrl+F | 聚焦当前页面搜索（如存在） |
| F5 | 刷新当前页面数据（不覆盖未保存编辑） |
| Ctrl+N | 源文档页新建 Markdown（仅当焦点不在文本输入控件时） |

快捷键必须有上下文判断，不能在用户正在输入文本时误触发页面命令。

## 7. 可访问性与细节

- 图标按钮必须提供 Tooltip 和 AutomationProperties.Name。
- 键盘 Tab 顺序与视觉顺序一致；焦点边框清晰可见。
- 颜色不能作为唯一状态区分方式，徽标需带文字。
- 文本对比度足够；次级文字不能淡到不可读。
- 长路径、长文件名、长错误信息有合理换行/省略和 Tooltip。
- 滚动条与深色主题一致，但不要隐藏到用户无法发现。

### 阶段 0：现状盘点（只检查，不改代码）

完成主窗口、导航、主题 Token、统一 Snackbar、Dialog 基础、状态栏。此阶段不改业务行为。

- `App.xaml`：Theme.Dark.xaml / Theme.Light.xaml 两套动态资源字典
- `MainWindow.xaml.cs`：启动时 `AppThemeService.Apply(configService.Theme)`
- 状态栏 `DispatcherTimer` 2s 轮询 `CurrentKb`/`ConfigService.WikisDir`/`ShareService.Running`
- 导航中文化：首页/源文档/目录浏览/工作流/分享/配置/设置/指南

### 阶段 2：文档工作区

先实现 `DocumentWorkspace` 和未保存保护；再改造源文档页。完成预览、编辑、新建、保存、失败保留内容。

### 阶段 3：目录浏览复用

目录树复用工作区；重点回归相对路径写回、只读文件、刷新恢复选择。

### 阶段 4：首页

完成欢迎区、统计卡、知识库列表、待处理摘要、快捷入口和存储信息。

### 阶段 5：工作流

七张卡片、输入联动、提示词生成、复制、待处理变更跳转。

### 阶段 6：分享与配置

先核实服务端只读安全，再做 UI；路径变更与运行服务状态联动。

- ShareService.RegeneratePin(out string error)：运行时重新生成 PIN
- LanAddresses()：仅返回局域网 IPv4，本机回环单独提供
- ConfigViewModel：路径状态「✓/⚠」+ 文案、CreateDefaultPurpose/Schema、保存失败保留内容

### 阶段 7：设置、指南与回归

完成主题切换、版本信息、指南；执行全量验收。

- ThemeService.Apply(theme) 替换资源字典，Light/Dark 即时切换
- SettingsViewModel：ChangeTheme + ConfigService.SetTheme 持久化，CheckUpdate 调用 UpdateService.CheckResultAsync()
- GuidePage.xaml：5 分组折叠面板
