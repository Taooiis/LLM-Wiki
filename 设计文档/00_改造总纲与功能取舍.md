# 00｜LLM Wiki V2 改造总纲与功能取舍

> 编制日期：2026-10-30。性质：针对已实现产品的最终设计规格（V2.0）；不是功能已验收报告。本设计包为唯一设计基准，已包含必要数据与服务契约，不依赖历史文档。本次未取得应用源码、运行截图和可执行程序，具体实现差异由改造阶段 0 核实。

## 1. 改造结论

产品定位保留为：**本地知识库维护工具，用外部 AI 把原始资料整理为可追溯的知识。**

主流程统一为：选择知识库 → 添加资料 → 整理知识 → 检查结果 → 确认本次变更已处理。日常阅读直接进入知识页。

界面围绕三件事组织：

1. **资料**：我放进来了什么，还缺什么？
2. **知识**：整理后得到了什么，内容能否追溯？
3. **整理**：哪些资料变了，下一步怎样交给 AI？

保留外部 AI、真实文件、源格式保存、局域网只读分享和 MCP 能力；减少平行入口、重复配置、技术名词和虚假的完成感。不新增聊天、模型 API 配置、云同步、知识图谱、数据库或无人值守自动执行；允许用户主动启动已适配的外部 Agent，见第 13 章。

## 2. 目前交互为何容易混淆

| 需要解决的交互问题 | 对用户的影响 | V2 处理 |
|---|---|---|
| 首页、源文档、工作流都能展示和处理变更 | 不知道哪里才是最终操作入口 | 待整理清单只在“整理”页完整维护；其他页只显示数量并跳转 |
| 源文档和目录浏览都有编辑工作区 | 资料与 AI 产物边界不清，编辑规则冲突 | “资料”编辑输入；“知识”阅读产物。共享文档控件但按区域授权 |
| 七张提示词卡长期并排 | 用户要理解 Ingest、Lint、Clean 才能开始 | 改为“更新知识、提问分析、检查维护”三类任务，按需显示表单 |
| 边界说明是一张日常任务卡 | 接入设置与日常工作混在一起 | 每次任务自动携带必要上下文；独立说明收为高级入口 |
| 批量、增量、清理各为独立卡 | 同一批新增、修改、删除被拆成多次操作 | 合并到“更新知识”，用范围和删除项处理规则区分 |
| 配置同时放路径、purpose/schema；设置另起一页 | 当前库与整个应用的作用范围不直观 | 库内设置管目的和结构；应用设置管根目录与外观 |
| 分享页面混合浏览者与 Agent | PIN、令牌、只读、写入概念互相干扰 | 同一入口下分“浏览分享”“AI 工具”两个独立页签 |
| 复制提示词后缺少清晰闭环 | 容易把“已复制”理解成“已整理” | 明确显示“等待外部执行”；用户核对结果后才确认处理 |
| 首页统计、欢迎图、最近访问和路径占大量面积 | 看得到数据，找不到下一步 | 默认打开当前库的知识；用状态摘要和下一步提示替代仪表盘 |
| 全局搜索与局部搜索能力界限模糊 | 用户误以为能语义检索或全文提问 | 顶部只做当前库文件名查找；内容搜索仅在真实支持时单独标注 |

上述属于设计判断，需用真实操作走查验证，不宣称已通过用户研究。

## 3. 明确的功能取舍

| 能力 | 决策 | 新位置或行为 |
|---|---|---|
| 首页仪表盘、装饰 Banner、四张统计卡 | 取消独立首页 | 当前库顶部显示资料数、待整理数；无库时显示创建引导 |
| 建库、切库、删库、场景模板 | 保留并集中 | 左上知识库切换器；库设置危险区删库 |
| 上传/新建/编辑/删除资料 | 保留 | “资料”页；首页重复按钮取消 |
| Wiki 目录与 Markdown 阅读 | 保留 | “知识”页；系统文件不进入普通内容树 |
| Wiki 手工编辑 | 默认关闭普通入口 | 高级“手动修订知识”正式纳入，保留服务并执行版本保护 |
| 待处理变更列表 | 合并 | “整理 → 更新知识”，是唯一确认处理入口 |
| 批量与增量 Ingest | 合并 UI，不改核心模板 | “更新知识”范围：待整理、所选资料、全部资料 |
| Clean | 保留为删除项分支和高级维护 | 先生成清理计划，协议不支持删除时提示到本机确认 |
| Query、Compare | 合并任务入口，保留不同生成器 | “提问分析”下选择“回答问题 / 对比主题” |
| Lint | 保留，中文命名 | “检查维护 → 检查知识质量” |
| 边界说明 | 生成器自动随任务组合 | 首次与日常都复制完整任务；高级入口可单独查看库说明 |
| 浏览分享 | 保留 | “连接与分享 → 浏览分享”；仅浏览、下载 |
| 本机启动器 | 新增用户主动执行 | 已验证适配器可开始/取消任务；复制方式始终保留 |
| 任务包导出 | 高级入口 | 默认只导出说明与清单，资料需显式选择 |
| MCP | 保留，能力与实现对齐 | “连接与分享 → AI 工具”；默认关闭、默认只读 |
| purpose/schema | 保留原文件 | “知识库设置 → 目标与结构”，显示中文标题与文件名 |
| 配置与设置 | 合并应用级入口 | 根目录、主题、版本、应用帮助 |
| 小白指南 | 改为“使用帮助” | 固定帮助入口 + 各页就地帮助链接 |
| Obsidian、资源管理器打开目录 | 保留低频入口 | 库菜单“打开文件夹”；不新增 Obsidian 配置向导 |

## 4. 本版统一决策

| 范围 | 唯一基准 |
|---|---|
| 桌面知识编辑 | 默认阅读，手动修订从高级入口显式进入 |
| AI 工具 | 本机启动器/复制/导出是执行入口；文件访问/MCP 是访问方式，不内置模型 |
| stdio | 首轮只读，独立进程生命周期与授权库明确 |
| Office | 当前 md/txt/docx/xlsx 白名单；上传文件保持原格式和字节，不生成 Markdown 副本；增加格式须独立定义能力 |
| 桌面渲染 | 全 WPF，不引入 WebView2 |
| 分享范围 | 服务会话绑定用户确认的单库，切库不静默换范围 |
| 配置 | 保留 wikisDir 与已有字段，UI 偏好独立命名，令牌受保护存储 |
| 验收 | 所有清单从未勾选开始，以实际构建与操作结果为准 |
| 数据和服务规则 | 本包 10_数据与服务契约.md，无需查阅其他版本 |

## 5. 改造边界与优先级

- **第一优先级**：已验证本机工具主动执行与复制兜底、单按钮复制完整任务、单次结果确认、资料回收站、导航、中文文案、待整理唯一入口、统一文档工作区、处理确认不误清、新版帮助。先改善最常用闭环。
- **第二优先级**：连接状态、分享范围固定、配置分层、外部改动冲突保护。
- **第三优先级**：高级手动修订、较复杂搜索、复杂执行历史等增强。没有可靠数据时不做占位界面。

新上传资料统一按原格式保存在 raw/sources/，停止创建 Office Markdown 副本；已有原件和历史副本不自动搬移或删除，按第 07、10 章兼容处理，不因为合并页面而删除已实现服务。新增权限限制属于业务行为调整，应独立提交、提供迁移说明和回归结果。

## 6. 产品成功标准

第一次使用的人不阅读技术协议，也能找到添加资料和整理入口；熟练用户能在当前资料选择后直接进入整理，不必重复选文件。复制、外部执行、确认处理三个阶段清晰分开。用户始终知道当前知识库、编辑是否保存、哪一个库正在对外开放。

验收方法见 09：按完整任务走查，不以按钮数量减少作为唯一成效标准。

## 7. 闭环实施要求

第 11 章的轻量文件扫描与任务恢复、逐项确认和失败补记是本版必须完成的基础能力，不归入可推迟的复杂执行历史。上传范围为 md/txt/docx/xlsx，单文件 20 MiB；原格式保存不等于自动支持任意格式。
