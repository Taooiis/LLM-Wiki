# LLM Wiki｜分步骤实施与实现后验证清单

> 配套页面整合版，2026-10-30。以下是待执行清单，不是通过记录。保持.NET 10 + WPF + WPF-UI 4.3.0 + MVVM，全WPF，不换技术架构。

## 1. 交给开发AI的执行方式

1. 先读 [总体架构](00_总体架构与实现约定.md)，盘点现有代码、组件与服务；不从零重写、不引入第二套UI框架。
2. 每次只实现一个阶段或一页；读该页完整MD与对应PNG，先列状态/命令/服务映射，再改代码。
3. 图用来对齐外观，MD决定尺寸、状态和行为。禁止只看图猜业务，也不能只用默认控件说布局完成。
4. 每页同时完成正常、空、加载、错误、忙、只读、主题/选中/失焦/焦点状态；按钮接真实命令，不放占位成功。
5. 每阶段运行实际工程构建和相关测试，交同尺寸截图与偏差记录；发现规范冲突先改统一规则，不另添一份“补丁设计”。

## 3. 视觉复刻的实际检查方法

- 基准1440×900 DIP、100%系统缩放；另外125%/150%、1180×760与1100×650。生成图按同纵横比归一化，不能单轴拉伸。
- 主边界目标误差≤4DIP，标准行高/间距/按钮≤2DIP；再人工检查文字、图标、层次、圆角和状态，不只看整图相似度。
- 每页用相同演示资料与状态重现图示：知识选中失焦、资料未保存、整理两项确认一项变更、AI工具能力验证、双规则独立状态、设置深色已选、帮助快速上手。
- 图中路径/日期/版本是示例，不硬编码产品数据；运行日志、进度、连接与已确认状态必须来自真实服务。
- 必交深浅主题的普通/选中/选中失焦/键盘焦点/禁用/错误截图；逐层检查树箭头/图标、DataGridCell、ComboBox弹出项、Tab/Menu、Markdown内部元素。
- 构建通过与视觉通过分别记录。不能用静态XAML或只拍悬停项证明全部可用，也不能因PNG中文字误差发明新功能。

反馈验证另含公共弹框与通知板：D01—D16、N01—N06的布局/键盘/时序/失败/上下文及页内持久状态，不能只验静态框。

## 4. 七页关键路径验证

| 页面 | 必须走通 |
|---|---|
| 知识 | 模板空状态→打开真实知识→来源定位；手改→冲突/保护；焦点移正文目录仍选中 |
| 资料 | 混合格式上传→字节一致→文本保存→外部Office刷新→整理所选→回收恢复冲突 |
| 整理 | 复制→主动核对→无变化理由确认→重启不回流；部分失败→结束保留剩余 |
| 连接与分享 | PATH/版本/身份/真实执行分别检测；清空剪贴板后本机开始无需粘贴；服务切库范围不变 |
| 知识库设置 | 两草稿一成一败、规则变化未全量处理、停服/任务未结束拒绝删库 |
| 应用设置 | 旧异步校验晚返回、路径应用失败恢复旧值、运行禁止换根、全主题生效 |
| 使用帮助 | 本机/复制教程与按钮一致，错误就地链接与返回任务，离线与无搜索结果 |
