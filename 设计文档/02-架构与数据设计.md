# 02 · 架构与数据设计

## 1. 技术形态总览

```
┌─────────────────────────────────────────────┐
│ LLM Wiki 桌面客户端（.NET 11 进程）           │
│                                             │
│  ┌───────────────┐      ┌───────────────┐   │
│  │ WPF 宿主窗口   │ 嵌套 │ WebView2 控件  │   │
│  │ (窗口/托盘/    │─────▶│ HTML/JS 面板UI │   │
│  │  只读服务开关) │      └───────┬───────┘   │
│  └───────┬───────┘              │ 命令消息   │
│          │                      ▼           │
│  ┌────────┴─────────────────────────────┐   │
│  │ 文件桥服务层（C# 内置，替代 server.js） │   │
│  │  库管理 · 目录树 · 读写 · 上传/删除    │   │
│  │  变更记录 · 配置 · Office→MD 转换     │   │
│  └──────────────────┬───────────────────┘   │
│                     │ 直接文件 IO            │
│                     ▼                       │
│  C:\…\wikis\<库名>\…（可配置，支持 UNC）      │
│                                             │
│  [可选] 只读分享服务（Kestrel，见 03 文档）    │
└─────────────────────────────────────────────┘
             ▲
             │ 复制提示词（人工）
    外部 Agent（opencode / codex）──直接读写 wikis 文件
```

要点：

- **单进程**：宿主、前端、文件桥同进程；不再有"黑窗口控制台 + 浏览器"两个角色。
- **前端 UI 从 Demo 移植**：`wiki-manager.html` 的页面结构、交互逻辑、提示词模板填充逻辑原样迁移，只把 HTTP `fetch` 换成对宿主的命令调用。
- **提示词内容不变**：生成出来的提示词文本与 Demo 逐字兼容（见 04 文档），保证 Agent 侧零改动。

## 2. 模块划分

| 模块 | 职责 | 对应 Demo 里的东西 |
| --- | --- | --- |
| 宿主壳 | 主窗口生命周期、托盘/退出、只读开关、设置入口 | `start.bat` / `stop.bat` 的角色 |
| 面板前端 | 知识库列表、源文档、路径浏览、配置、工作流、分享设置各页 | `wiki-manager.html` |
| 文件桥服务层 | 知识库 CRUD、目录树、文件读写、上传/删除、变更记录、存储路径配置 | `server.js` 全部业务 |
| 格式转换器 | docx/xlsx → Markdown 副本转换（上传时触发） | 无（本次新增） |
| 提示词引擎 | 模板 + 库信息填充 → 可复制提示词（含 Clean 级联清理卡，§8） | 面板工作流页逻辑 + `prompts/` 模板 |
| 只读分享服务 | 局域网只读网页（可选开关） | Demo 的 0.0.0.0 监听（弱化为只读，见 03） |

## 3. 界面结构（沿用 Demo 六页心智模型）

1. **知识库（顶部常驻）**：下拉切换 + 新建输入框；显示当前库绝对路径。
2. **源文档页**：四格式上传、新建/编辑（仅 txt/md 可在面板编辑；office 文件只上传与预览）、删除、待处理变更区（勾选 → 生成增量 Ingest 提示词 → 标记已处理）。
3. **路径浏览页**：目录树 + 点文件弹窗预览/编辑（规则同上：md/txt 可编辑，docx/xlsx 只读预览转换结果，附"预览的是入库副本"提示）。
4. **配置页**：`purpose.md` / `schema.md` 编辑；存储路径更改（浏览/手输/恢复默认，含实时校验：拒绝单个反斜杠开头路径等 Demo 已有的防护）。
5. **工作流页**：边界说明 / Ingest（批量、增量）/ Query / Lint / Compare / Clean（级联清理）六类提示词卡，生成 + 一键复制，提示词里写知识库绝对路径。
6. **分享页**：只读访问开关、端口、访问地址与二维码（03 文档）。

## 4. 文件桥接口（语义清单）

传输形态留给实现者（`AddHostObjectToScript`、消息通道或进程内 Kestrel 自桥均可），但**语义必须对齐 Demo 的 API**，前端迁移成本才最低：

| 命令 | 说明 | Demo 对应 |
| --- | --- | --- |
| 库列表 / 新建库 | 新建时按骨架生成目录与默认文件 | `GET/POST /api/kbs` |
| 删除库 | 含 `raw/original/` 整库永久删除；输入库名确认；存储路径不可达时拒绝（02 文档 §5 同） | 本次新增（Demo 无删库） |
| 目录树 | 递归列目录，跳过 `.` 开头与 node_modules | `/api/tree` |
| 读/写文件 | md/txt（库内路径安全校验 `..`、绝对路径拒绝） | `GET/POST /api/file` |
| 上传 | 四格式入 `raw/sources/`，office 触发转换；重名覆盖语义与 Demo 一致 | `/api/upload` |
| 删除 | 限定 md/txt 可删；office 原件+副本成对删除（见 §6） | `/api/delete` |
| 源列表 | 列 `raw/sources/` 全部四格式 | `/api/sources` |
| 变更查询/清除 | `.changes.json` 读写 | `/api/changes*` |
| 存储路径设置 | 解析校验逻辑照搬 Demo（盘符/UNC/相对，非法形态拒绝） | `/api/settings` |
| 磁盘/目录浏览/常用位置 | 分享路径选择器与存储路径浏览用 | `/api/drives` `/api/browse` `/api/places` |
| 局域网电脑/共享选择 | 列局域网 PC 与其磁盘共享（复刻 Demo 的 `net view` 调用与解析），供"存储路径"点选 UNC 路径用 | `/api/netpc` `/api/netshares` |

与 Demo 的接口差—只有两条，来自新格式：

- 上传接口多两类扩展名与转换钩子；
- 删除接口对 office 文件改为"原件 + 入库副本"成对删除（否则会留下孤儿副本，`log.md` 里也应记为一次删除动作）。

## 5. 数据目录与骨架

沿用 Demo 结构，**唯一新增**是 `raw/original/`：

```
wikis/<库名>/
├── purpose.md              # 目标、关键问题、研究范围（面板-配置页可改）
├── schema.md               # 结构规则（默认即可）
├── .changes.json           # 待处理变更（点号开头，目录树跳过）
├── raw/
│   ├── sources/            # Agent 读的入库副本：.md/.txt（office 转换产物也在这里）
│   ├── original/           # 本次新增：docx/xlsx 原件（Agent 不引用此目录）
│   └── assets/             # 图片
├── wiki/
│   ├── index.md / log.md / overview.md
│   ├── entities/  concepts/  sources/
│   ├── queries/   synthesis/ comparisons/
```

- 建库骨架、`purpose.md`/`schema.md`/`index.md`/`log.md`/`overview.md` 的默认内容照搬 Demo 文案。
- **场景模板（借鉴参考实现）**：新建库时可从 4 个模板选一（通用 / 研究 / 读书 / 业务），唯一作用是给 `purpose.md`、`schema.md` 预填不同文案；目录骨架不动，不选模板即"通用"。
- **旧库零迁移**：没有 `raw/original/` 的库视为"纯文本库"，一切照旧；首次上传 office 文件时自动建目录。

## 6. 格式转换流水线（本次设计核心新增）

### 6.1 规则

1. **转换发生在上传时刻**，不是 Ingest 时刻——保证 Agent 任何时刻读 `raw/sources/` 都是成立的纯文本。
2. **入库副本是事实上的唯一.source**：文件名 = 原文件名 + `.md` 后缀（如 `调研报告.docx → raw/sources/调研报告.docx.md`），避免与已有 md 重名，也让"它来自哪个原件"自解释。
3. **原件落 `raw/original/`**，仅作存档与人工下载回查；Agent 的引用格式仍是 `[来源: 调研报告.docx]`（提示词模板中的说明见 04 文档）。
4. **log 与变更**：一条上传动作记两行事实（原件入库 + 副本生成），待处理变更以副本文件名为准（Agent 只能读到副本）。
5. **txt 编码**：读入时探测（UTF-8 / UTF-8-BOM / GB 系），统一以 UTF-8 写副本（txt 原 content 只有内容入库，不改原件字节）。

### 6.2 转换保真度策略（留给实现者的裁量）

- **docx**：标题层级 → `#`，段落 → 段落，列表 → `-`，表格 → md 表格；图片/艺术字不做（如需可记在 log 说明损失）。推荐 OpenXML SDK 方向实现，具体库由实现者定。
- **xlsx**：每个工作表一个 `## 表名` 二级标题，表格落 md 表格；大于阈值行数（建议 >200 行）截断并附"已截断，原件见 raw/original/说明"；公式取缓存值，不保留公式本身。
- 转换失败时：**不静默半入库**——报错给用户、原件与副本都不落盘或都回滚，log 不留伪记录。

### 6.3 参考实现佐证（nashsu/llm_wiki）

参考实现（Tauri v2 + Rust）对同类问题采用：DOCX 用 docx-rs 抽标题/加粗/列表/表格为结构化 Markdown；XLSX 用 calamine 保证单元格类型正确、多工作表、Markdown 表格。策略与本节完全一致，具体库我们用 C# 对应物（Office 转换推荐 OpenXML SDK 方向；xlsx 亦可行 OpenXML，或 ClosedXML/MiniExcel，实现者定）。其"每工作表一个二级标题"、"公式取缓存值"的做法即本节 6.2 的来源。

## 7. 变更记录与 log（沿用 Demo，增加 SHA256 指纹）

- 写源文档 / 上传 / 删除时自动向 `wiki/log.md` 追加一行（格式 `%Y-%m-%d %H:%M 动作：路径`），source 范围动作同时写 `.changes.json`。
- **SHA256 变更指纹（借鉴参考实现）**：`.changes.json` 每条记录带当时内容的 SHA256；面板生成"增量 Ingest 提示词"时附一句"hash 与上次 Ingest 一致的文件可跳过"。作用：Agent 执行时能自主跳过假变更（被打开重存但内容没变的文件），省 token。
- office 文件的两行事实记录见 §6.1 第 4 条。
- Demo 中"配置更新"（purpose/schema 保存）的记入格式原样保留。

## 8. 删除级联（借鉴参考实现的"级联清理"）

参考实现在删除源文件时自动清理 wiki 侧（摘要页、index、失效 [[wikilink]]）。**本设计不做自动清理**（反目标：面板不写 `wiki/` 层），但把清理变成一张**提示词卡**：

- 工作流页新增第 6 类提示词：**Clean（级联清理）**——选中某个已删除/即将删除的源文档生成提示词，Agent 按提示删除该源的摘要页、从 index.md 清条目、清理失效 `[[wikilinks]]`、共享实体页只摘除该源条目不删页。
- 与"待处理变更"联动：删除动作进变更清单，标识类型为 `删除`，勾选后可生成 Clean 提示词；同一变更也已支持生成增量 Ingest 时的"跳过已删文件"说明。
- `[[wikilinks]]`、frontmatter `sources: []` 进 schema 默认文案（见 04 文档借鉴映射），使 Agent 生成的页面天然支持上面这套清理语义。
