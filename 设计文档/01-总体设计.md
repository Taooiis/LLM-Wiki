# 01 · 总体设计

## 1. 意图与背景

**LLM Wiki Demo**（`C:\Users\Ari\Documents\LLM Wiki Demo`）是一套"文件桥 + 浏览器面板 + 复制提示词"的知识库方案。：Node.js 起 `server.js` 管文件，`wiki-manager.html` 面板管交互，AI 工作一律由用户把面板生成的提示词复制给外部 Agent（opencode / codex）执行，Agent 直接读写 `wikis/<库名>/` 下的纯文本文件。

本次立项是它的**新一代版本**，动机有两条：

1. **源文件格式扩到 Office**：现实中要进知识库的资料大量是 Word、Excel；在重要维护场景里要求用户先另存为 md 是明显摩擦。新版直接收 txt / md / docx / xlsx。
2. **桌面客户端化**：用 **WPF UI Library（WPF-UI 4.3.0）原生控件**做成 Windows 桌面应用（全 WPF 化、放弃 WebView2），替代"装 Node、跑 bat、开浏览器"的使用方式，交付形态是可直接安装/双击运行的程序。

## 2. 定位一句话

**一个 Windows 桌面知识库维护工具**：管理知识库的源材料与结构，产出可直接交给外部 AI 工具执行的提示词；它自己是文件管理器，不是问答机器。

## 3. 目标（必须做到）

- 建 / 切换 / 删除多个知识库，目录结构沿用 Demo 约定（见 02 文档数据节）。
- 源文档：上传 / 新建 / 编辑 / 删除，支持 **txt、md、docx、xlsx** 四种格式。
- docx / xlsx 在**上传时**自动转换出 Markdown 副本供 Agent 使用，原件保留在库内。
- 源文档与配置的每次变更自动记入该库 `wiki/log.md`，未重新 Ingest 的变更进入"待处理变更"清单（复用 Demo 的 `.changes.json` 机制）。
- 目录浏览 / 源文档页：目录树浏览、Markdown 预览与编辑、待处理变更管理；配置页：存储路径配置。
- 提示词生成：边界说明、Ingest（批量 / 增量）、Query、Lint、Compare、Clean 七类卡，一键复制。
- 多设备**只读**访问：应用内开关，暴露一个局域网只读网页，供手机 / 其他电脑浏览查看（详见 03 文档）。
- 脱离 AI 完整可用：装上工具、不接任何 AI 也能管理源文件和日志。

## 4. 非目标（明确不做）

- **不做问答 / 聊天界面**：客户端不内置任何 LLM 调用，没有 API key 配置。
- **不做自动 Ingest**：用户不点提示词、不去外部 Agent 执行，`wiki/` 产物永不自动变化。
- **不做多端编辑**：只读网页非万不得已不做写操作；两个端同时编辑同一文件不在范围内。
- **不做云同步 / 账号系统**：数据全在本地与（可选的）局域网共享路径里。
- **不做通用文件管理器**：工具只对齐知识库目录约定，不打算管理任意文件夹。

## 5. 反目标（出现即为失败）

- **Agent 读不到源**：只要存在一种"入库成功但外部 Agent 拿不到内容"的格式路径（如数据库形式的中间层），就算失败。入库副本必须是 Agent 可直接读的文件。
- **破坏 Demo 数据**：同一个 `wikis` 目录，换到新客户端后必须原样可用；任何要求用户重做知识库的改动都算失败。
- **隐藏的写行为**：面板对"知识内容"（`wiki/` 产物）保持只读；用户手工编辑的只有 `raw/` 与 `purpose.md`、`schema.md`（与 Demo 约定一致）。
- **只读服务越权**：多设备页面一旦出现上传 / 删除 / 编辑入口即失败（03 文档边界）。

## 8. 留给实现者（Builder）的部分

- WPF 与 WinForms 的最终取舍（D1 已给倾向，需说明理由即可）。
- docx / xlsx 转 Markdown 的具体库选型与转换保真度策略（结构 vs 表格宽表如何落成 md 表格）。
- 文件桥接口的传输形态（WPF UI `NavigationView` / Frame 承载的 WPF UI Page 经 DI 注入 C# 服务直调 / 控件直调 `BridgeDispatcher`；`bridge.js` 随 Web 前端移除），只要求语义对齐 Demo API 清单（02 文档）。
- 安装形态（自包含单文件 / 依赖框架）；全 WPF 化后不再需要 WebView2 运行时检测。
- txt 编码探测（UTF-8 与 GB 系）细节。
- UI 视觉细节：2026-10-29 起以《页面级设计》（00-07）为准做 Fluent 深色视觉还原；Demo 面板布局仅作结构参考（原 `WPF-UI-PLAN.md` 的保守视觉策略已被页面级设计取代，该文件已删除）。
