# 11｜闭环补全与状态恢复规范

> 本章补全外部文件变化、跨重启任务、结果检查、逐项确认、规则更新和失败恢复。本章与 01—10 的相应入口配套实施，不增加主导航、数据库或内置 AI。2026-10-30。

## 1. 本版已定范围

资料保存、预览、AI 读取与编辑分别声明能力。当前资料类型 md/txt/docx/xlsx，上传保持原格式和字节；PDF 等尚不支持，不要求用户改成 Markdown。单文件最大 **20 MiB（20,971,520 字节）**，多选按文件逐项提交，不把整批大小当作单文件限制；协议封装开销另计。底层若只有旧请求体限制，按文件拆分/调整传输适配后再上线这一口径。

列表可显示“可预览 / 外部程序打开 / 读取工具待配置”等说明，上传成功不能推导为可在任意 AI 中完整读取。

## 2. 本地状态文件与生命周期

在每库隐藏目录 `.llmwiki/` 下保存可读 JSON，不引入数据库，不修改 `.changes.json` 的已有格式。路径校验统一禁止普通文档 API、浏览分享、MCP 直接访问这些内部文件。

| 文件 | 用途 |
|---|---|
| manifest.json | 最近一次完整扫描的源文件路径、大小、时间、SHA256；扫描代次与规则版本 |
| tasks/{任务ID}.json | 本次任务范围、源文件/变更快照、规则版本、知识文件基线、逐项确认状态 |
| operations/{操作ID}.json | 待提交/已提交的文件动作与变更、日志补记进度；作为可恢复操作凭据 |
| trash/{条目ID}/ | 源资料回收文件、覆盖前版本和恢复元信息；不自动永久清理 |
| reviews.json | 规则更新提醒的确认/暂时忽略版本，手动修订知识的路径与版本 |

各文件含 schemaVersion，先临时写入再原子替换。未知字段保留；不认识的未来版本只读报错，不以空对象覆盖。损坏状态隔离为损坏文件并提示重建可推导部分；任务已确认与未确认状态不能凭猜测恢复。

任务只保存路径、哈希、时间、范围、任务参数和状态，不复制源文件或知识正文，不保存令牌、PIN、外部 AI 对话。指令用冻结输入与模板版本生成；模板版本不可用时显示“无法恢复原指令”，允许查看摘要并生成新任务，不伪造旧指令。

已确认/已放弃任务保留最近 50 条且最多 30 天，超出后清理；未结束任务不自动清理。放弃任务仅关闭记录，不清除待整理项。删除库时隐藏状态一并删除，备份完整库时一并包含；应用退出不删除。任务详情放在整理页“未完成任务 / 最近任务”折叠区，不新增任务中心导航。

## 3. 文件变化发现

启动、进入资料页、手动刷新、确认任务前执行扫描；文件监测只触发去抖扫描，不能作为唯一依据。生成任务前也检查相关源文件与规则，避免复制已过期范围。

扫描 raw/sources/ 及可靠识别的历史源位置。排除 `~$` Office 锁文件、应用临时文件、隐藏状态目录和不支持类型；过滤规则固定并可查。遍历失败、共享断开、读取被锁、权限失败时标记“扫描不完整”，不能把未读到的文件判为删除，不能替换上次完整清单。

变化最终以原字节哈希判断：时间或大小改变是快速筛选线索；启动、用户刷新和确认前须校验相关文件内容，不能漏掉同大小/同时间的更改。读取前后比较元信息，变化中重试；仍不稳定显示“文件正在保存”，暂不提交该项快照。

对完整可读范围比较：新路径是新增、已有路径哈希变化是修改、完整扫描确定消失才是删除。路径改名默认作为“旧路径删除 + 新路径新增”，不猜测重命名；大小写和 Windows 名称规范由文件服务统一处理。

检测结果通过同一变更服务写入，保留原去重规则；扫描完成不等于已整理。先可靠登记变化，再推进 manifest 基线。首次接入没有 manifest 的存量库时保留已有变更，建立扫描基线，并显示“历史处理状态未核对”，提供“核对现有资料”；不自动宣称全部已整理，也不一口气覆盖原待整理记录。

操作日志不因多次扫描重复追加。由应用完成的操作通过操作ID去重；外部发现的变化以路径、前后哈希、动作和扫描代次去重。已确认版本不因相同扫描重复回到待整理。

## 4. 跨重启任务与失效规则

复制指令或开始本机执行前持久化任务快照；写入失败不提供假成功的生成状态。任务冻结库绑定、范围、所选变更身份、源哈希、purpose/schema 哈希、模板版本及知识文件路径/哈希基线。快照不是文件内容副本，外部执行时仍要核对当前版本。

状态为“已准备 / 已复制待外部执行 / 待核对 / 部分确认 / 已确认 / 已放弃”。资料发生变化是逐项附加标记，不把整任务直接覆盖成未知状态。重启进入整理页显示“有未完成任务，继续核对”，恢复选择与已确认进度；绝不恢复成外部执行成功。本机进程的准备/运行/取消/结束状态另由第 13 章 attempt 管理，不能混为任务已确认。

| 变化 | 原任务处理 |
|---|---|
| 新增不在本次范围的资料 | 原所选任务仍有效，页头提醒另有变更；全部资料任务提示范围增加，重新复制需生成新任务 |
| 本次某资料内容变化或删除 | 该项失效，不再按原版本确认；其他未变化项仍可核对 |
| 已删除资料重新出现 | 删除项失效，不能继续按旧清理计划确认 |
| purpose/schema 或模板规则变化 | 原指令不再允许当作当前指令复制；已完成的旧任务可核对，但新规则提醒仍保留 |
| 切换库 | 只切换视图，保留任务绑定；返回原库继续，不对新库复用旧指令 |
| 根目录变化 | 不按同名库自动匹配任务；新位置通过已有状态和用户核对确认身份 |

不允许旧任务反复生成后覆盖原快照。重新生成创建新任务，保留被替代任务的摘要与确认进度。任务指令要求读取前检查源版本，变化时停止该项并报告；本机文件直读无法强制限制外部程序，UI 如实说明。

## 5. 本次变化与结果核对

“查看本次变化”先打开整理页内的“本次结果核对”面板，另有“打开知识页”。对比任务开始时的 wiki/ 文件清单与当前清单，显示新增、修改、删除及无变化；wiki/log.md 单独列为操作日志，不算知识产出。

每项展示相对路径、变化类型、当前文件打开入口和来源关联。已删除文件因未备份正文，仅能显示删除事实，不能提供虚假的旧内容预览；本版提供文件级变化，不承诺逐行 Diff 或历史回滚。

面板固定说明“以下为任务准备以来检测到的变化，可能包含其他程序的修改，不代表均由本次 AI 产生”。多任务时间重叠提示“变化范围可能重叠”。无法解析来源时不猜测哪项资料已完成。

资料级核对表列：源文件、原动作、执行报告（未提供/已读取/读取失败/读取不完整）、知识变化关联、用户确认状态。外部 AI 的报告是辅助信息，不是应用自动验证；无报告也可由用户人工核对，不能伪造“AI 已处理”。

## 6. 逐项确认与规则更新

确认表默认不勾选。未生成任务但在外部已完成的情况，先建立标注“用户补充确认”的当前版本快照，并要求用户核对这些正是已处理版本；不伪装成恢复了历史执行快照。用户选中确已完成的资料或删除项，点击“确认完成这 {n} 项”后仅清除快照仍匹配的记录；普通确认不再追加确认弹窗。未读取、失败、未完成分段读取的项目默认不能确认；用户若在另一工具已完整处理，可选择“我已在其他方式完成”，在行内填写说明，再使用同一面板的提交按钮一次确认，系统重新比较当前源版本，不额外弹窗。

每项结果独立为“已确认 / 有新变化保留 / 未完成保留 / 记录冲突待刷新”。无变更文件也可能无需改知识，允许“已核对，无需修改”并记录用户理由；不能强制每项都产生 Wiki 修改。单项确认不能清除新增的无关项。

确认保存使用可恢复操作凭据：先保存确认意图，再比较版本并更新变更文件，最后标记任务该项已确认。中断恢复时核实变更与凭据状态，幂等完成或保守保留，不仅凭任务里的勾选删记录。

purpose/schema 变化独立显示“规则已更新，已有知识尚未按新规则核对”。“稍后处理”只折叠当前版本提醒，保存 ignoredVersion，不等于完成。全部资料任务按当前规则逐项确认完毕后，用户仍需显式“确认已按新规则核对现有知识”；才推进已确认规则版本。也可人工完成全库核对后独立确认。部分任务不自动消除此提醒。

## 7. 文本编辑与手动知识修订

| 状态 | 保存按钮与行为 |
|---|---|
| 预览 | 显示“编辑”，没有可提交草稿 |
| 编辑但内容未变化 | 保存禁用，显示“未修改”；Ctrl+S 不写盘、不制造变更 |
| 已修改 | 保存启用；取消、切换、关闭执行统一保护 |
| 保存中 | 禁止重复保存、目标切换和覆盖动作；等待保存结果后再执行离开意图 |
| 成功 | 更新原始缓冲与版本，继续留在编辑模式，显示“已保存”；可点“完成编辑”返回预览 |
| 失败 | 留在编辑，保留草稿和原始版本，重试或另存；不提示再次上传同一文件 |
| 外部版本冲突 | 不覆盖，提供磁盘版本、另存、返回编辑；另存生成独立资料且需合法命名 |

本版正常退出靠离开保护；意外崩溃的未保存编辑草稿不保证恢复，帮助必须说明。持久任务记录只恢复任务，不等同恢复文档草稿。Word/Excel 的外部编辑保存由对应程序负责，桌面无法替它确认未保存内容。

手动修订知识成功后在 reviews.json 记录路径和新哈希。后续整理任务标出“含手动修订内容”，默认要求 AI 保留人工内容；确需覆盖时先列出拟修改项让用户在外部确认。MCP 写入命中受保护手工版本时返回 MANUAL_REVIEW_REQUIRED，不直接覆盖；用户可在桌面明确解除该文件当前版本的保护。外部文件直读只能通过任务约定提醒，不承诺技术上拦截 Agent。

## 8. 知识空状态

新建 index/overview 的模板不视为已生成知识。创建时记录模板内容哈希，或与可验证模板版本比较；仍全部为初始骨架且没有其他知识页时显示“还没有整理出的知识”。用户编辑过首页或新增知识页则展示实际内容，但不据此声称 AI 已执行成功。

存量库无法识别模板时保守展示内容，不因猜测清空文件。来源解析失败不影响阅读。index/overview 缺失仍按 02 的降级入口处理。

## 9. 文件成功、记录失败与崩溃恢复

源文件、变更 JSON 与日志无法当作一个跨文件原子事务。应用操作先写 operations 凭据（目标、动作、前后哈希、临时文件标识），再提交源文件，随后补变更与日志，最后标记操作完成。日志内部或关联元数据用操作ID去重，不破坏可读日志格式。

源文件已提交但记录失败时显示“文件已保存，变更记录未完成”，提供“重试登记 / 查看文件”，不显示整体失败并要求用户重传。登记失败项进入持久修复队列；继续生成该项整理任务前先修复或明确阻止，不允许安静漏项。

启动按凭据与磁盘哈希恢复：未提交的临时文件可清理；已提交动作补记；目标后来又变化则保留最新变化并提示冲突，不能用旧凭据回滚新文件。删除凭据保存目标曾存在与动作版本，不因“文件现在不存在”就重复制造删除记录。

共享目录断开时凭据可能暂时无法写入，应在源提交前拒绝新动作；提交后断线的未知结果先显示“结果待核实”，重连检查后恢复。文件扫描可以补源变化，但不能凭当前文件恢复完整历史日志，缺失时明确说明。多程序写同库仍应遵守单维护者约定，不能宣称拥有跨设备完整事务。

## 10. MCP 分段读取与版本闭合

read_file 返回 content、version（原字节 SHA256）、totalBytes、nextCursor 与 complete。read_source_content 返回原文件 sourceVersion、内容片段、页/段/工作表定位、覆盖范围、nextCursor、complete、warnings；首请求固定版本，后续请求带 version/cursor，源文件变化返回 VERSION_CONFLICT，不能混读两个版本。

工具支持按 cursor 继续读取；Excel 可提供工作表列表与按表/行区间读取。读取上限为每响应最多 64 KiB UTF-8 内容，单次受限不等于处理完成；结构定位元数据和必要封装另计，遇到单字段超限也必须分段或明确报错。读取超时、权限、加密和格式错误分别返回，不能以空内容表示成功。

write_wiki_file 的 expected_version 取读取返回的 version；新建文件传显式 expectedAbsent=true，与 expected_version 互斥。完整更新不得只凭截断预览生成内容。MCP 的成功读取/写入不自动确认任务；可在带任务上下文时记录观察到的覆盖信息，缺少上下文或客户端走文件直读时由用户核对。

## 11. 实施依赖顺序

先完成状态存储与恢复、扫描登记、任务快照和逐项确认，再开放结果核对与版本化 MCP 分段读取；最后更新帮助与视觉。状态文件损坏、重启、断网、部分完成、规则变化、人工修订覆盖和记录失败均须有验收用例。
