# 07｜实现映射与兼容迁移

## 1. 实施原则

这是已实现产品的渐进改造。先盘点真实源码，再按功能迁移视图和交互；不按文档建议目录批量搬代码，不从零重写文件桥、提示词引擎或分享服务；上传链路取消 Markdown 转换，既有转换器仅在需要时改为无落盘的读取适配。

本文件中的类名是现有程序盘点时的映射线索，不代表已验证存在。实施者必须将实际类、接口、资源字典和调用链填入盘点报告。

## 2. 页面映射

| 原页面/组件 | 新归属 | 实施动作 |
|---|---|---|
| DashboardPage | 库切换器、无库引导、页面摘要 | 拆出库操作；取消仪表盘导航，旧路由重定向到当前库 |
| SourcePage | 资料 | 复用上传与编辑，直接删除改为回收站服务；移走完整变更确认列表 |
| TreeBrowserPage | 知识 | 限制内容树范围；默认只读，复用预览 |
| WorkflowPage | 整理 | 七卡生成器保留，替换为任务表单与统一结果面板 |
| SharePage | 连接与分享 | 浏览分享和 AI 工具分页签，拆状态与生命周期 |
| ConfigPage | 知识库设置 + 应用设置 | purpose/schema 留库内；根目录移应用级 |
| SettingsPage | 应用设置 | 合并主题与版本，删除重复路径入口 |
| GuidePage | 使用帮助 | 改写为完整任务教程与配置解释 |
| DocumentWorkspace | 资料/知识/规则编辑共用 | 按文档角色注入权限，不以扩展名独自决定可编辑 |
| ChangeService/对应服务 | 整理中心 | 增加快照比较确认，原文件格式兼容 |
| 新增执行适配层 | AI 工具配置、本机任务运行 | 复用任务上下文；按工具能力启动、取消、接收事件，不拼 shell 命令 |
| PromptEngine/对应服务 | 整理、AI 工具、MCP Prompts | 单一模板来源，按传输上下文适配 |

旧快捷入口携带 kb 与相对路径重定向到新入口，不能静默丢上下文。原 Ctrl+K/Ctrl+S 等快捷键保持语义兼容，旧页面名不再出现在用户帮助。

## 3. 状态与服务边界

| 状态 | 所有者 | 约束 |
|---|---|---|
| 当前知识库、根目录 | 统一上下文服务 | 切换时发布版本化通知 |
| 文件读写、元数据、版本 | 文件服务 | UI 不直接拼路径写盘 |
| 原格式文件身份与读取能力 | 资料/文件服务和格式读取适配 | 以源文件路径与原字节指纹为准；预览/提取不改变存储格式 |
| 待整理记录 | 变更服务 | UI 只选择，服务原子比较后确认 |
| 文档草稿、搜索、选中项 | 各页/工作区 VM | 不塞进全局大 state，避免跨页污染 |
| 分享绑定库、权限、运行状态 | 各服务会话 | 与当前页面选库独立 |
| 指令预览与输入 | 整理任务 VM + 隐藏任务 JSON | 按范围内资料/规则版本逐项判断；跨重启恢复，切库不覆盖 |

异步加载应支持取消或丢弃旧上下文结果；写操作必须持有明确目标标识。复用统一未保存协调器，先处理草稿，再执行调用方原动作。

## 4. 必须保留的数据契约

保留 wikis/<库名>/、purpose.md、schema.md、raw/sources/、raw/assets/、wiki/ 和 .changes.json。所有新上传文件直接存 raw/sources/原文件名，保持原扩展名与字节，不生成 .docx.md/.xlsx.md，不为新上传建立 raw/original。来源引用始终写实际源文件名。中文导航别名不写成磁盘目录。

已有 raw/original 与衍生 Markdown 文件不自动移动、删除或重新生成。阶段 0 盘点其映射、人工修改及待整理记录；历史源文件继续从真实位置读取。只有能可靠识别原件和派生物时才分组展示，不凭文件后缀猜测并删文件。

如果历史待整理项指向派生 Markdown，保持该记录身份和相应版本快照，明确显示为历史记录；切换到原文件任务需显式记录映射和用户确认，不能直接把路径改写后清除。新上传 Office 为原文件身份，即使同名历史资料存在也先提示冲突与处理范围，不隐式建立第二份主源或覆盖用户编辑过的历史 Markdown。

不新建数据库，不改 .changes.json 结构与去重规则，不把任务记录塞入变更清单；隐藏 .llmwiki/ JSON 状态记录扫描、任务、修复操作和人工核对，见第 11 章。此轮禁止自动批量迁移资料；若后续需要统一历史路径，应单独提供可预览、可回滚的迁移方案。

配置读取保留 wikisDir 与未知字段。新 UI 偏好可加命名空间或配置版本，但必须兼容旧启动；配置修改失败不切换运行时路径。

## 5. 有意改变的行为与迁移要求

| 改变 | 风险 | 迁移要求 |
|---|---|---|
| 分享绑定单库 | 旧链接可能失去其他库访问 | 首次升级停止服务并提示重新开启，不沿用旧范围凭据 |
| 写授权重启恢复只读 | 旧客户端写入失败 | 提示重新授权，返回明确只读错误，不自动提升权限 |
| stdio 仅只读 | 原写配置可能依赖旧启动参数 | 盘点现有配置，展示受影响项与替代 HTTP 写入方式 |
| Wiki 默认阅读 | 用户习惯直接编辑 | 若保留高级修订，在更多菜单和帮助中明确路径 |
| 上传保持源格式、不转 Markdown | 现有上传链路和任务可能依赖衍生文件 | 停止新转换；历史原件、派生物与变更保留并显式映射；任务直接读取原格式 |
| 写入要求版本前置条件 | 旧 MCP 客户端未传字段 | 发布错误码与参数说明；先验证现有客户端再启用强制策略 |
| 变更仅比较后确认 | 旧“全部清空”操作收窄 | 移除含糊按钮，保留逐项/全选明确确认 |

以上应分业务提交实施，不能和纯视觉改动混为一次“页面美化”。用户已实现的能力以保留服务为原则；任何无法确认安全兼容的行为先保留旧服务、暂不开放新入口，记录为未完成，不伪装验收通过。

## 6. 模板适配与 MCP 约束

七类协议名称与原参数兼容；中文任务名只是展示。文件直读模板保留绝对路径，MCP 模板使用授权库标识和工具名；共用核心任务定义和引用规则。

HTTP 与 stdio 共用路径校验和读权限策略。写入仅 HTTP 显式授权；检查相对路径、根目录包含关系、链接/junction、大小上限与系统文件禁区。不能靠文件扩展名白名单绕过 .changes.json 隐藏策略。

参数和日志限制沿用现有服务可验证值；不在改造文档中指定未经核实的 SDK 最新版本或客户端配置字段。开发时根据锁定依赖和目标客户端官方文档核对，记录实际版本与生成配置样例。

## 7. 回滚与交付

开始前备份用户目录与应用配置，记录旧版本构建和关键流程。纯 UI 改造不迁移业务数据，因此回滚旧程序时文本资料仍保持目录兼容；原格式 Office 新上传路径可能超出旧程序读取能力，须先核实支持矩阵，不能宣称无条件可回滚；新增配置字段不应破坏旧版本读取。

服务范围、授权模式和参数要求的变化需要单独迁移说明；回滚时不自动恢复高权限或重启分享。每阶段提供改动文件、行为变化、构建结果、关键页面截图、已知问题和回滚办法。

状态 JSON 引入与原格式上传同属有意行为变化：普通旧客户端需忽略隐藏目录，旧程序不会理解任务恢复、人工保护或未完成修复记录。回滚前完成修复、停止写入并核查原格式读取能力。

回收站是有意新增的可恢复删除机制：本地与 UNC 同用库内隐藏文件存储，回滚到不认识该目录的程序不会自动恢复资料；回滚前核实并导出需要保留的条目。MCP 和浏览分享不新增删除/回收访问权限。
