# 04｜连接与分享及权限

## 1. 入口与概念

页面分为“浏览分享”“AI 工具”两个页签，各自拥有真实状态、开关、权限和帮助。共用宿主是实现细节，界面开关独立；关闭浏览分享不能意外断开用户以为独立运行的 MCP。若现有服务耦合，先拆生命周期再开放独立开关。

| 场景 | 方式 | 凭据 | 写入 |
|---|---|---|---|
| 手机或其他设备看资料和知识 | 浏览分享 | 4 位 PIN | 始终禁止 |
| 本机 Agent 直接访问文件 | 复制含库上下文的完整任务 | 文件系统权限 | 由外部 Agent 和用户本机权限约束 |
| 外部 AI 客户端通过协议访问 | MCP | HTTP 令牌；stdio 遵循本机权限 | 默认只读，HTTP 可显式授权写入 |
| 多台电脑访问同一文件夹 | Windows 共享路径 | Windows 共享权限 | 不由网页或 MCP 开关约束 |

页面不得暗示关闭 MCP 写入就能限制拥有文件系统权限的本机 Agent，也不得暗示 UNC 目录天然只读。

## 2. 分享范围：固定单库会话

开启前显示“分享知识库：产品研究”。服务会话绑定该库，而非动态读取 SelectedKb。用户切换到其他库时，服务继续原范围，并在全局显示分享中的库名。

更换分享库需要“停止并更换范围”，关闭旧连接、失效旧凭据、生成新凭据后重启；不在旧令牌下静默暴露新库。删除正在分享的库时先停止相关服务，停止失败则拒绝删除。根目录切换也先停止所有绑定服务，保留配置但不自动重启。

MCP 的 list_knowledge_bases 仅返回当前授权范围；携带其他 kb 参数应拒绝。浏览分享不提供全根目录库列表。此为有意收窄的 V2 权限变化，需验证旧客户端兼容行为。

## 3. 浏览分享线框

```text
连接与分享                  [浏览分享] [AI 工具]
浏览分享：已关闭                                  [启动浏览分享]
让可信局域网中的其他设备查看“产品研究”。
分享范围：产品研究 / 资料、知识和可下载原件

启动后：
访问地址  http://<真实局域网地址>:<实际端口>   [复制] [二维码]
访问码    <本次生成的 PIN>                    [复制] [更换访问码]
允许：浏览、预览、下载     不允许：上传、编辑、删除、改配置
[停止浏览分享]
```

启动时显示“正在启动”，失败回到关闭并展示原因；运行中显示实际端口与可用地址。无 LAN 地址提供本机测试地址并说明“当前未检测到局域网地址”；多个网卡逐条展示，避免混为单个文本。

二维码默认编码不含 PIN 的地址，扫码后输入 PIN；如旧实现包含 PIN，需明显标注“二维码包含访问码”，不把带凭据 URL 写日志。更换 PIN 应使旧凭据与已认证会话失效；如果现有 cookie 机制不能失效，应修正服务端而非只替换显示文字。

只读网页沿用“只读浏览 · 编辑请回到桌面应用”横幅，移动端树与正文可切换，允许下载已授权库的原件。下载也校验 PIN 和路径，不因静态文件中间件绕过认证。

## 4. AI 工具：先选方式，再显示配置

### 4.1 手动复制

默认说明“到整理页复制完整任务，在能访问该目录的外部 AI 中执行”。不再要求首次先复制接入说明，也不显示无可靠依据的接入完成状态；高级折叠入口保留“查看库说明 / 复制库说明”。

每次任务自动携带库身份、路径、目标规则入口、版本、任务范围和边界；不依赖历史对话记忆。MCP 的首次客户端配置仍在此页完成，服务端每次调用独立校验权限，不要求 AI 先调用 boundary。完整交互见第 12 章。

### 4.2 MCP 本机 HTTP

展开后展示：服务状态、绑定库、本机端点、权限“只读”、令牌掩码、复制令牌、重新生成、客户端配置。

默认关闭、回环监听、只读。写入用独立写令牌；开启前明确“允许此连接修改本库 wiki/ 下的知识文件，不能修改原始资料、库规则或删除文件”。本版每次启动应用后恢复为只读，写权限不自动恢复；已有持久写权限要在升级说明中提示此变化。

停止或降权时，在最终落盘前再次检查会话权限；已经成功提交的写入不能撤销，UI 不承诺回滚。不能仅靠前端隐藏写入工具。

“允许局域网访问”为高级配置，默认关闭，显式确认后才改变监听；明文 HTTP 仅限可信网络。不在首轮承诺 HTTPS 证书管理。客户端配置按真实支持的客户端适配生成，不在文档虚构通用 JSON 或安装路径。

### 4.3 stdio 本机进程

放在高级连接方式中，V2 默认只读。显示实际可执行文件路径、配置预览与说明“由外部客户端启动，退出桌面应用不一定停止该进程”。不显示由桌面服务推测的运行状态。

若无法通过统一授权机制约束 stdio 范围，首轮不要宣称其跟随桌面当前库；需将授权库作为启动配置，配置改变后重启客户端进程。原实现若支持 --allow-write，必须核实现存配置并给出只读迁移提示，不能只隐藏开关。

## 5. 写入、清理与并发

HTTP 写入仅允许 wiki/ 下既有白名单文本；禁止 raw/、purpose.md、schema.md、.changes.json、wiki/log.md，禁止所有删除工具。原子写入、路径边界、拒绝链接绕过和令牌验证必须在服务层执行。

对已存在文件的写入强制 expected_version，缺失时返回 VERSION_REQUIRED；新建用显式“不存在”前置条件，避免抢占同名文件。该调整与旧可选参数存在兼容差异，要升级协议说明并回归客户端。

桌面保存同样比较磁盘版本；有可靠跨进程编辑登记时可附加“正在编辑”保护，没有时只承诺版本冲突检测，不声称能感知其他进程所有未保存草稿。stdio 只读降低首轮并发复杂度。

## 6. 连接诊断与权限反馈

只展示可验证状态：服务正在监听、令牌已配置、最近调用时间/工具/结果。没有可靠客户端心跳时不显示“已连接 3 台”。令牌、PIN、正文、绝对路径不进入普通调用日志。

常见错误对应中文：未授权→检查令牌；权限不足→连接只读；范围不符→连接绑定其他库；版本冲突→重新读取后重试；服务停止→返回应用开启。技术错误码可在详情中查看。

## 7. 验收

- [ ] 两类服务独立启停，状态来自服务，退出行为符合说明。
- [ ] 切库不静默换范围；更换范围使旧凭据失效。
- [ ] 旧 PIN/cookie、旧令牌、无凭据下载均被正确拒绝。
- [ ] 写权限升级、降级、重启恢复只读实际生效。
- [ ] 跨库、路径穿越、符号链接、删除、写入禁区均被服务拒绝。
- [ ] 写入版本冲突不覆盖已有内容，不自动清除待整理项。
- [ ] stdio 生命周期和授权范围与 UI 文案一致。

## 8. 原格式资料访问

浏览分享允许下载授权范围内的原格式文件，支持预览时直接预览，不支持时显示文件信息和下载入口，不提供强制转 Markdown 的操作。

MCP read_file 是文本读取工具，不表示能读取 Word/Excel。原格式读取使用第 10 章 read_source_content 格式适配，响应可包含临时文本或表格，不产生知识库 Markdown 副本。客户端或工具缺少适配时明确返回格式/读取错误；连接可用与文件可读取分别显示，不把这些失败项标记处理完成。

## 9. 本机执行配置

AI 工具页签内统一管理本机工具适配、MCP 连接及手动说明。适配器配置、身份检测、主动启动和取消按第 13 章；不把 MCP 当作与启动器互斥的执行方式，也不在应用设置重复配置。
