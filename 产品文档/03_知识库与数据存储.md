# 03 知识库与数据存储

## 3.1 存储位置

- **知识库根目录**：默认 `我的文档\LLM Wiki\wikis`。若旧位置 `%APPDATA%\LLM_Wiki\wikis` 已有数据则沿用（不自动搬移）。可在 应用设置 → 存储 更换，只换读取位置，不搬迁数据。
- **应用配置** `config.json`：在程序 exe 所在目录。字段：`wikisDir`（根目录）、`theme`（Light/Dark，默认 Dark）、`lastKb`（上次打开的库）、`lastPages`（每库上次停留页面）。
- **本机 AI 工具档案**：`%APPDATA%\LLM_Wiki\agent-profile.opencode-cli.json`（只存路径、模型选择与验证结果，**不存任何账号、API Key 或令牌**）。
- **MCP 令牌**：`%APPDATA%\LLM_Wiki\mcp.token`、`mcp.write.token`（DPAPI 加密，仅当前 Windows 用户可解）。

## 3.2 库名规则

只允许中英文、数字、下划线、中划线（正则 `^[a-zA-Z0-9_\-一-鿿]+$`）；列表忽略 `.` 开头目录。

## 3.3 库目录结构

新建知识库后：

```text
{根目录}\{库名}\
├── purpose.md               # 规则：目标与边界（按场景模板预填）
├── schema.md                # 规则：组织规则（固定模板）
├── .changes.json            # 待整理变更记录
├── raw\
│   ├── sources\             # 原始资料（原格式字节保存）
│   └── assets\              # 图片
├── wiki\
│   ├── index.md             # 知识首页（内容目录）
│   ├── overview.md          # 全局摘要
│   ├── log.md               # 操作历史（自动追加，AI 禁改）
│   ├── entities\            # 人、组织、产品
│   ├── concepts\            # 理论、方法、技术
│   ├── sources\             # 资料摘要
│   ├── queries\             # 问题分析
│   ├── synthesis\           # 综合分析
│   └── comparisons\         # 对比分析
└── .llmwiki\                # 应用内部状态（AI 不可见、不可写）
    ├── kb.json              # 库元数据（创建时间、模板哈希）
    ├── manifest.json        # 资料扫描基线（每个文件的哈希）
    ├── reviews.json         # 规则版本确认 + 人工修订保护登记
    ├── tasks\{taskId}.json  # 整理任务快照
    ├── attempts\{id}.json   # 本机 AI 执行回执（OpenCode 另有临时 .task.txt）
    ├── operations\{id}.json # 可恢复操作凭据（崩溃后补记用）
    └── trash\{id}\          # 库内回收站（payload 原字节 + meta.json）
```

## 3.4 内部文件说明

| 文件 | 作用 | 谁能写 |
|---|---|---|
| `.changes.json` | 待整理变更（`{file, action, time, hash}`，action ∈ 新增/修改/删除） | 仅应用 |
| `manifest.json` | 扫描基线：顶层资料文件的大小/修改时间/SHA256 | 仅应用 |
| `reviews.json` | 已确认的规则版本、忽略的规则版本、人工修订保护列表（旧版手动修订产生，新版不再新增） | 仅应用 |
| `tasks\*.json` | 任务快照：范围、每项资料哈希、wiki 基线、生成的指令、状态 | 仅应用 |
| `wiki\log.md` | 操作历史：添加/替换/保存/回收/恢复/MCP 写入/规则更新，格式 `- yyyy-MM-dd HH:mm 动作：路径` | 仅应用（AI 禁改） |
| `purpose.md` / `schema.md` | 规则文件，知识库设置页编辑 | 仅应用（乐观锁） |

## 3.5 编码与一致性

- 文本文件按 BOM → 严格 UTF-8 → GB18030 顺序识别编码，**保存时保留原编码、BOM 与换行风格**。
- 所有状态文件走"临时文件 + 原子替换"写入，未知字段原样保留（升级不丢数据）。
- 哈希口径：文件字节 SHA256（小写 hex），用于变更指纹、MCP 版本号、乐观锁。

## 3.6 多机与备份

- 支持把根目录指向 UNC 共享，但**共享目录的读写由 Windows 管理**；请避免多台设备同时维护同一库，修改者负责重新整理。
- **回收站不是备份**：整库删除或磁盘损坏会连带失去回收站内容，应用不会自动清理。
- 备份 = 复制整个库文件夹（含 `.llmwiki\`，否则任务与变更状态丢失）。
- 删除知识库是**永久删除**（资料、知识、任务状态、回收站一并删除），需在 知识库设置 → 基本信息 → 危险操作 中输入完整库名确认。

## 3.7 扫描机制

- 只扫 `raw/sources/` **顶层**（不递归）；`raw/assets/` 不在基线内。
- 首次扫描只建基线，不把存量资料记成"新增"。
- 扫描中出现无法读取的文件时**不判断删除**（防误报），并提示"扫描未完成"。
- 文件读取前后大小/时间不一致视为不稳定，不记变更。
