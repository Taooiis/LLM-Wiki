# 07｜公共交互组件与验收清单

## 1. 统一文档工作区 DocumentWorkspace

源文档页、目录浏览页、purpose/schema 编辑入口尽量复用统一工作区。通过输入参数控制数据来源和允许的操作，不复制三套编辑器。

### 1.1 状态枚举

```csharp
public enum DocumentWorkspaceMode
{
    Empty,
    Preview,
    Editing,
    ReadOnly
}

public enum DocumentSaveState
{
    None,
    Saved,
    Dirty,
    Saving,
    Failed
}
```

### 1.2 必须具备的属性

- `Mode`：Empty/Preview/Editing/ReadOnly。
- `DocumentName`、`RelativePath`、`DocumentType`、`FileSize`、`LastModified`。
- `Content`、`OriginalContent`。
- `SaveState`、`SaveErrorMessage`、`IsBusy`。
- `CanEdit`、`CanSave`、`CanDelete`。
- `LineNumber`、`ColumnNumber`、`WordCount`（编辑器能力允许时）。

### 1.3 状态流转

```text
Empty --选择文件--> Preview
Preview --编辑--> Editing
Preview --只读文件--> ReadOnly
Editing --内容改变--> Dirty
Dirty --保存--> Saving --成功--> Saved
Dirty --保存--> Saving --失败--> Failed（内容保留）
Editing/Dirty --取消--> 统一未保存保护
```

### 1.4 保存要求

- 保存命令执行期间禁用重复保存。
- 保存成功才更新 `OriginalContent` 和 `SaveState=Saved`。
- 保存失败不能更新原始内容，不能清空编辑器。
- 保存成功后刷新文件元信息和相关计数。
- 保存接口应接收明确的目标路径/文档标识，避免只用文件名定位导致错写。

## 2. 未保存保护对话框

触发场景：切换文档、切换知识库、离开页面、关闭窗口、切换存储根目录。

对话框文案示例：

标题：`还有未保存的更改`
正文：`“产品需求说明.md”有尚未保存的修改。离开前要如何处理？`
按钮：
- 主按钮：`保存后离开`
- 次按钮：`放弃更改`
- 轻按钮：`继续编辑`

规则：
- 保存失败时留在当前编辑状态。
- 用户点击继续编辑时不改变任何内容。
- 放弃更改必须明确恢复到原始内容或退出当前文档。
- 不允许在未保存保护对话框上再叠加另一个确认弹窗。

## 3. 确认对话框规范

仅用于删除、覆盖、清空等不可逆操作。结构：标题、对象/范围、后果说明、确认按钮、取消按钮。

示例删除文档：
- 标题：`删除源文档`
- 正文：`确定删除“产品需求说明.md”吗？删除后会记录一条待处理变更，后续可通过增量 Ingest 更新 Wiki。`
- 确认按钮：`删除文件`（危险样式）
- 取消按钮：`取消`

禁止：按钮只写“确定”；对话框里再打开另一个对话框；使用 MessageBox 作为全站通用方案。

## 4. Snackbar / Toast

- 位置：主窗口底部或右下角，不遮挡关键操作。
- 成功提示约 2.5–3 秒自动消失；错误提示可稍长或要求用户手动关闭。
- 成功示例：`已保存`、`已复制：增量 Ingest`、`已创建知识库：产品知识库`。
- 错误示例：`保存失败：没有权限写入目标文件。编辑内容已保留。`
- 不用 Snackbar 展示需要用户持续关注的任务进度或服务运行状态。

## 5. 加载、空状态、错误状态

每个数据区都必须覆盖：

| 状态 | 表现 | 用户操作 |
|---|---|---|
| Loading | 骨架/局部进度，避免全屏闪烁 | 可等待；长任务可取消 |
| Empty | 图标 + 一句话 + 主操作 | 创建/上传/清空搜索 |
| Error | 错误摘要 + 重试 | 重试/查看详情 |
| Normal | 正常内容 | 常规操作 |
| Busy | 当前操作按钮显示处理中 | 防重复提交 |
| ReadOnly | 明确只读原因 | 打开外部程序/返回 |

禁止用空列表代表加载失败；禁止用“暂无数据”掩盖接口异常。

## 6. 键盘操作

| 快捷键 | 行为 |
|---|---|
| Ctrl+K | 聚焦全局搜索 |
| Ctrl+S | 保存当前文档（编辑状态） |
| Esc | 关闭轻量 Flyout；编辑状态下触发退出保护，不直接丢稿 |
| Ctrl+F | 聚焦当前页面搜索（如存在） |
| F5 | 刷新当前页面数据（不覆盖未保存编辑） |
| Ctrl+N | 源文档页新建 Markdown（仅当焦点不在文本输入控件时） |

快捷键必须有上下文判断，不能在用户正在输入文本时误触发页面命令。

## 7. 可访问性与细节

- 图标按钮必须提供 Tooltip 和 AutomationProperties.Name。
- 键盘 Tab 顺序与视觉顺序一致；焦点边框清楚可见。
- 颜色不能作为唯一状态区分方式，徽标需带文字。
- 文本对比度足够；次级文字不能淡到不可读。
- 长路径、长文件名、长错误信息有合理换行/省略和 Tooltip。
- 滚动条与深色主题一致，但不要隐藏到用户无法发现。

## 8. 分阶段实施计划

### 阶段 0：现状盘点（只检查，不改代码）

输出：现有 View/VM/服务映射、页面截图、可复用控件、当前问题清单、编译基线。

Agent 指令：

> 请先检查当前 WPF 分支，不要修改任何代码。确认 .NET 10、WPF-UI 4.3.0、MVVM 的实际使用方式；列出主窗口、导航、首页、源文档、目录浏览、工作流、分享、配置、设置和指南的 View/ViewModel/服务对应关系；确认现有文档编辑器、Markdown 预览、文件上传、知识库切换、变更记录、分享服务的实现位置。执行一次构建并记录错误。最后给出按本设计文档实施的文件级改造计划。

### 阶段 1：全局框架和主题

完成主窗口、导航、主题 Token、统一 Snackbar、Dialog 基础、状态栏。此阶段不改业务行为。

### 阶段 2：文档工作区

先实现 `DocumentWorkspace` 和未保存保护；再改造源文档页。完成预览、编辑、新建、保存、失败保留内容。

### 阶段 3：目录浏览复用

目录树复用工作区；重点回归相对路径写回、只读文件、刷新恢复选择。

### 阶段 4：首页

完成欢迎区、统计卡、知识库列表、待处理摘要、快捷入口和存储信息。

### 阶段 5：工作流

七张卡片、输入联动、提示词生成、复制、待处理变更跳转。

### 阶段 6：分享与配置

先核实服务端只读安全，再做 UI；路径变更与运行服务状态联动。

### 阶段 7：设置、指南与回归

完成主题切换、版本信息、指南；执行全量验收。
